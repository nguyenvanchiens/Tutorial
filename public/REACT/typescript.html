TypeScript với React

Năm 2026, TypeScript là mặc định cho dự án React nghiêm túc. Nó bắt lỗi ngay khi gõ, biến IDE thành tài liệu sống, và giúp refactor an toàn. Trang này dạy bạn type chính xác props, state, hooks, context và reducer — đúng React 19 + TS 5.x.

1. Vì sao dùng TypeScript?

TS là JS + hệ thống kiểu (type). Code TS được biên dịch (type-check) rồi xoá type để ra JS thường. Type chỉ tồn tại lúc dev — runtime hoàn toàn là JS.

✅ TypeScript cho bạn

  • Bắt lỗi trước khi chạy (typo prop, sai kiểu)
  • Autocomplete & "go to definition" chính xác
  • Refactor an toàn — đổi tên field, IDE báo mọi chỗ hỏng
  • Type như tài liệu: nhìn signature biết cách dùng
  • Tự tin hơn khi làm team / codebase lớn

JS vs TS — lỗi bắt được sớm

// JS — chạy mới crash
function greet(user) {
  return `Hi ${user.naem}`; // typo, im lặng
}

// TS — báo đỏ ngay lúc gõ
function greet(user: User) {
  return `Hi ${user.naem}`;
  // ❌ Property 'naem' does not exist on type 'User'
}
Setup nhanh: npm create vite@latest my-app -- --template react-ts. File component đổi đuôi .tsx, file logic dùng .ts.

2. Các kiểu cơ bản

// Primitive
let name: string = 'Chiến';
let age: number = 25;
let active: boolean = true;

// Array
let ids: number[] = [1, 2, 3];
let names: Array<string> = ['a', 'b'];

// Object & optional (?)
let user: { id: number; nick?: string } = { id: 1 };

// Union — một trong nhiều kiểu
let status: 'idle' | 'loading' | 'error' = 'idle';

// Function
const add = (a: number, b: number): number => a + b;

// any (tránh!) vs unknown (an toàn) vs never
let x: unknown; // phải narrow trước khi dùng
Tránh any: nó tắt mọi kiểm tra — mất hết lợi ích TS. Khi không rõ kiểu, dùng unknown rồi thu hẹp (narrow) bằng typeof/in. Bật "noImplicitAny": true để TS không lén dùng any.

3. interface vs type

Cả hai mô tả "hình dạng" object. Khác biệt nhỏ — chọn nhất quán trong dự án.

interface — hay dùng cho object/props

interface User {
  id: number;
  name: string;
  role?: string; // optional
}

// Kế thừa
interface Admin extends User {
  perms: string[];
}

// Declaration merging (gộp tự động)
interface User { age: number; }

type — linh hoạt hơn (union, tuple)

type ID = number | string;       // union
type Point = [number, number];     // tuple

type User = {
  id: ID;
  name: string;
};

// Giao kiểu (intersection)
type Admin = User & { perms: string[] };
Tiêu chíinterfacetype
Object shape✅ tốt✅ tốt
Union / tuple / primitive alias❌ không✅ được
Kế thừa / mở rộngextends& (intersection)
Declaration merging✅ có❌ không
Khuyến nghị thực tế: dùng interface cho props & shape object công khai, dùng type cho union/utility/phép biến đổi kiểu. Quan trọng nhất là nhất quán trong team.

4. Type Props

Định nghĩa một interface cho props rồi annotate tham số. Năm 2026 không còn dùng React.FC (vì ép kiểu children ngầm gây phiền).

interface ButtonProps {
  label: string;
  variant?: 'primary' | 'danger';        // optional union
  disabled?: boolean;
  onClick: () => void;                       // hàm không trả gì
  children: React.ReactNode;               // bất kỳ thứ render được
}

function Button({ label, variant = 'primary', onClick, children }: ButtonProps) {
  return (
    <button className={variant} onClick={onClick}>
      {label} {children}
    </button>
  );
}

// Mở rộng prop của thẻ HTML gốc (giữ onClick, type, ...)
interface InputProps extends React.ComponentProps<'input'> {
  label: string;
}
React 19 lưu ý: React.ReactNode cho children bất kỳ; React.ReactElement nếu chỉ nhận đúng 1 element. React.ComponentProps<'button'> kế thừa toàn bộ attribute hợp lệ của thẻ HTML — khỏi khai báo tay.

5. Type State — useState<T>

Thường TS tự suy ra kiểu từ giá trị khởi tạo. Chỉ cần annotate khi giá trị ban đầu là null/[] hoặc union.

Suy luận tự động

// TS tự biết: number / string / boolean
const [count, setCount] = useState(0);
const [name, setName] = useState('');
const [open, setOpen] = useState(false);

setCount('x'); // ❌ TS báo lỗi ngay

Cần annotate generic

// null ban đầu → phải nói rõ kiểu
const [user, setUser] = useState<User | null>(null);

// array rỗng ban đầu
const [items, setItems] = useState<Todo[]>([]);

// union literal
const [tab, setTab] = useState<'home' | 'profile'>('home');
Quy tắc: để TS suy luận khi giá trị khởi tạo đã đủ rõ; chỉ ghi useState<T> khi khởi tạo là null, [], {} hoặc bạn muốn union rộng hơn giá trị ban đầu.

6. Type Event handlers

Đừng để event là any. Dùng đúng kiểu để có autocomplete e.target.value, e.key...

// onClick button
const onClick = (e: React.MouseEvent<HTMLButtonElement>) => {
  console.log(e.currentTarget);
};

// onChange input
const onChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  setName(e.target.value); // value được biết là string
};

// onSubmit form
const onSubmit = (e: React.FormEvent<HTMLFormElement>) => {
  e.preventDefault();
};

// onKeyDown
const onKeyDown = (e: React.KeyboardEvent) => {
  if (e.key === 'Enter') submit();
};

// MẸO: gắn handler inline → TS tự suy ra kiểu e, khỏi annotate
<input onChange={(e) => setName(e.target.value)} />
Mẹo tiết kiệm: nếu viết handler inline ngay trên JSX, TS tự suy ra kiểu event từ thuộc tính (contextual typing) — không cần annotate tay. Chỉ annotate khi tách handler ra biến/hàm riêng.

7. Generics trong Component

Generic giúp viết component tái sử dụng giữ nguyên kiểu dữ liệu. Ví dụ kinh điển: một <List> nhận bất kỳ kiểu item nào.

// Component generic — <T,> (dấu phẩy để TS không nhầm là JSX)
interface ListProps<T> {
  items: T[];
  renderItem: (item: T) => React.ReactNode;
  keyOf: (item: T) => string | number;
}

function List<T,>({ items, renderItem, keyOf }: ListProps<T>) {
  return (
    <ul>
      {items.map((it) => (
        <li key={keyOf(it)}>{renderItem(it)}</li>
      ))}
    </ul>
  );
}

// Dùng — TS tự suy T = User, item trong renderItem được biết là User
<List
  items={users}
  keyOf={(u) => u.id}
  renderItem={(u) => u.name}
/>
Vì sao mạnh: không cần tạo UserList, PostList riêng. Một List<T> hoạt động cho mọi kiểu mà vẫn full type-safe bên trong renderItem. Đây là nền của nhiều thư viện table/select.

8. Type Hooks & Custom Hooks

Annotate giá trị trả về của custom hook giúp nơi dùng có autocomplete chuẩn. Dùng as const để giữ kiểu tuple.

useRef & useReducer

// ref tới DOM (khởi tạo null)
const inputRef = useRef<HTMLInputElement>(null);
inputRef.current?.focus();

// ref lưu giá trị mutable
const id = useRef<number>(0);

Custom hook có kiểu

function useToggle(init = false) {
  const [on, setOn] = useState(init);
  const toggle = () => setOn((o) => !o);
  // as const → trả về tuple [boolean, () => void]
  return [on, toggle] as const;
}

const [open, toggle] = useToggle();
// Custom hook fetch generic — trả về union state đầy đủ
interface FetchState<T> {
  data: T | null;
  loading: boolean;
  error: Error | null;
}

function useFetch<T>(url: string): FetchState<T> {
  const [state, setState] = useState<FetchState<T>>({
    data: null, loading: true, error: null,
  });
  // ... useEffect gọi fetch, set state ...
  return state;
}

// Nơi dùng chỉ định T → data biết đúng kiểu
const { data, loading } = useFetch<User[]>('/api/users');

9. Discriminated Union cho Reducer

Pattern quan trọng nhất khi dùng useReducer với TS. Mỗi action có một type literal làm "discriminant" — TS tự thu hẹp payload theo từng case.

interface State { count: number; step: number; }

// Mỗi action có "type" riêng + payload tương ứng
type Action =
  | { type: 'increment' }
  | { type: 'decrement' }
  | { type: 'setStep'; step: number }
  | { type: 'reset'; payload: State };

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case 'increment':
      return { ...state, count: state.count + state.step };
    case 'setStep':
      return { ...state, step: action.step }; // TS biết có .step
    case 'reset':
      return action.payload;                  // TS biết có .payload
    default:
      const _exhaustive: never = action;       // ✅ ép xử lý hết case
      return state;
  }
}

const [state, dispatch] = useReducer(reducer, { count: 0, step: 1 });
dispatch({ type: 'setStep', step: 5 }); // ✅ thiếu step → TS báo lỗi
Mẹo exhaustiveness: gán action vào biến kiểu never ở default. Nếu sau này thêm action mới mà quên xử lý, TS sẽ báo lỗi compile — không bao giờ sót case.

10. Type Context

Type context an toàn + một custom hook kiểm tra undefined giúp tránh lỗi "dùng context ngoài Provider".

interface AuthContextValue {
  user: User | null;
  login: (email: string) => Promise<void>;
  logout: () => void;
}

// Khởi tạo null + union, KHÔNG fake giá trị mặc định
const AuthContext = createContext<AuthContextValue | null>(null);

// React 19: dùng <AuthContext> trực tiếp làm Provider (bỏ .Provider)
export function AuthProvider({ children }: { children: React.ReactNode }) {
  const [user, setUser] = useState<User | null>(null);
  const value: AuthContextValue = {
    user,
    login: async (email) => { /* ... */ },
    logout: () => setUser(null),
  };
  return <AuthContext value={value}>{children}</AuthContext>;
}

// Custom hook: ép kiểm tra Provider, trả về kiểu KHÔNG null
export function useAuth(): AuthContextValue {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth phải dùng trong <AuthProvider>');
  return ctx;
}
React 19: bạn có thể render <AuthContext value={...}> trực tiếp thay cho <AuthContext.Provider>. Mẫu createContext<T | null>(null) + custom hook ném lỗi là cách type context an toàn nhất, tránh phải kiểm tra undefined ở mọi nơi dùng.

11. Utility Types

TS có sẵn các kiểu biến đổi giúp tái dùng type mà không lặp lại. Cực hữu ích cho form, API, props.

UtilityLàm gìVí dụ
Partial<T>Mọi field thành optionalPartial<User> — patch update
Required<T>Mọi field thành bắt buộcRequired<Config>
Pick<T, K>Chọn vài fieldPick<User, 'id' | 'name'>
Omit<T, K>Bỏ vài fieldOmit<User, 'password'>
Record<K, V>Object map key→valueRecord<string, number>
Readonly<T>Mọi field chỉ đọcReadonly<Props>
ReturnType<F>Kiểu trả về của hàmReturnType<typeof useAuth>
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
}

// Tạo user: bỏ id (server cấp), bỏ ngày tạo
type NewUser = Omit<User, 'id'>;

// Hồ sơ công khai: chỉ lấy id + name
type PublicUser = Pick<User, 'id' | 'name'>;

// Form update từng phần
function updateUser(id: number, patch: Partial<User>) { /* ... */ }
updateUser(1, { name: 'Lan' }); // ✅ chỉ cần field muốn đổi
Vì sao đắt giá: một interface User nguồn → derive ra NewUser, PublicUser, UserForm. Khi User đổi, tất cả tự cập nhật. Đừng copy-paste type — hãy biến đổi.

12. tsconfig — những cờ quan trọng

Với Vite, phần biên dịch do esbuild lo; tsconfig.json chủ yếu để type-check. Vài cờ nên bật:

{
  "compilerOptions": {
    "strict": true,              // BẬT — gom mọi check nghiêm ngặt
    "noUncheckedIndexedAccess": true, // arr[i] có thể undefined → an toàn hơn
    "noImplicitAny": true,       // cấm any ngầm (đã nằm trong strict)
    "jsx": "react-jsx",        // React 17+ JSX transform, khỏi import React
    "moduleResolution": "bundler", // chuẩn cho Vite
    "target": "ES2022",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "skipLibCheck": true,        // bỏ check .d.ts của lib → build nhanh
    "verbatimModuleSyntax": true  // rõ ràng import type vs import value
  }
}
Cờ quan trọng nhất: "strict": true — nó bật cả gói strictNullChecks, noImplicitAny... Nếu chỉ nhớ một cờ, nhớ cái này. Dự án mới của Vite đã bật sẵn.

13. Lỗi thường gặp & cách sửa

"Object is possibly 'null'"

const ref = useRef<HTMLInputElement>(null);
ref.current.focus(); // ❌ current có thể null
ref.current?.focus(); // ✅ optional chaining

"Type 'string' is not assignable to..."

// state là union literal hẹp
const [tab, setTab] = useState<'a' | 'b'>('a');
setTab(someString); // ❌ string quá rộng
setTab(x as 'a' | 'b'); // hoặc validate trước

Sự kiện là implicit any

// ❌ Parameter 'e' implicitly has 'any'
const onChange = (e) => setX(e.target.value);
// ✅ annotate kiểu
const onChange = (e: React.ChangeEvent<HTMLInputElement>) => {};

"Property does not exist on type '{}'"

// quên annotate useState({}) → kiểu {}
const [u, setU] = useState({}); // ❌ u.name lỗi
const [u, setU] = useState<User | null>(null); // ✅
Mẹo đọc lỗi TS: đọc từ dòng cuối lên — dòng cuối thường là nguyên nhân gốc. Lỗi dài với Type X is not assignable to Y nghĩa là bạn đưa kiểu rộng vào chỗ cần kiểu hẹp. Dùng as const, narrowing (typeof/in), hoặc sửa type gốc — hạn chế tối đa as any.

💡 Bài tập thực hành

  1. Type lại component JS
    Lấy Button, UserCard ở bài React Cơ bản, viết interface props, bỏ hết any, mở rộng prop từ React.ComponentProps<'button'>.
  2. Generic List + Select
    Viết <List<T>> và <Select<T>> nhận options: T[] + getLabel, giữ type-safe trong callback.
  3. useReducer + discriminated union
    Cài đặt reducer cho giỏ hàng (add/remove/updateQty/clear). Thêm check never ở default để đảm bảo exhaustive.
  4. Typed Context + custom hook
    Tạo ThemeContext ('light' | 'dark') + useTheme() ném lỗi khi dùng ngoài Provider. Dùng cú pháp Provider của React 19.
  5. useFetch<T> generic
    Hoàn thiện useFetch<T> trả về { data, loading, error } có type. Gọi với User[] và render an toàn với optional chaining.
Tự check: nếu bạn type được props, state, event, reducer, context mà không dùng any → bạn đã đạt chuẩn TypeScript Junior React 2026. Tiếp theo: React Nâng cao.
