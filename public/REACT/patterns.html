Design Patterns

Cách tổ chức component có thể tái sử dụng, dễ test, dễ mở rộng. Khác biệt giữa Junior và Senior nằm ở đây.

1. Composition — Pattern số 1 của React

React không có inheritance. Mọi thứ là composition: ghép các component nhỏ thành component lớn thông qua children và props.

Containment — slot

function Dialog({ title, children, footer }) {
  return (
    <div className="dialog">
      <header>{title}</header>
      <main>{children}</main>
      <footer>{footer}</footer>
    </div>
  );
}

<Dialog
  title="Xác nhận"
  footer={<Button>OK</Button>}>
  <p>Bạn chắc chứ?</p>
</Dialog>

Specialization — "extends" kiểu React

function WelcomeDialog() {
  return (
    <Dialog title="Chào mừng">
      <p>Cảm ơn bạn đã đăng ký</p>
    </Dialog>
  );
}

// Thay vì class Welcome extends Dialog
// → compose: Welcome RENDER Dialog với props cụ thể
Nguyên tắc: nếu bạn đang nghĩ "kế thừa component" → dừng lại, dùng composition. React không đi theo OOP.

2. Container vs Presentational

Tách logic (data fetching, state) khỏi UI (render). Giúp test UI độc lập, đổi style dễ dàng.

// Presentational — chỉ nhận props, render UI
function UserList({ users, onDelete }) {
  return (
    <ul>
      {users.map(u => (
        <li key={u.id}>{u.name}
          <button onClick={() => onDelete(u.id)}>x</button>
        </li>
      ))}
    </ul>
  );
}

// Container — quản state, gọi API, truyền xuống
function UserListContainer() {
  const { data, mutate } = useQuery('/users');
  const del = (id) => mutate(del => del.filter(x => x.id !== id));

  return <UserList users={data} onDelete={del} />;
}
2026 update: với custom hooks, nhiều team gộp lại: 1 component gọi useUsers() hook (logic) rồi render UI. Tách rõ rệt chỉ khi component phức tạp hoặc cần Storybook.

3. Compound Components

Nhiều component cùng hoạt động như một — chia sẻ state qua Context. User ghép linh hoạt như Lego.

const TabsContext = createContext();

function Tabs({ children, defaultTab }) {
  const [active, setActive] = useState(defaultTab);
  const value = useMemo(() => ({ active, setActive }), [active]);
  return <TabsContext.Provider value={value}>{children}</TabsContext.Provider>;
}

Tabs.List = function List({ children }) {
  return <div className="tab-list">{children}</div>;
};

Tabs.Tab = function Tab({ id, children }) {
  const { active, setActive } = useContext(TabsContext);
  return (
    <button
      className={active === id ? 'active' : ''}
      onClick={() => setActive(id)}>
      {children}
    </button>
  );
};

Tabs.Panel = function Panel({ id, children }) {
  const { active } = useContext(TabsContext);
  return active === id ? <div>{children}</div> : null;
};

// Dùng — cực kỳ đẹp
<Tabs defaultTab="home">
  <Tabs.List>
    <Tabs.Tab id="home">Home</Tabs.Tab>
    <Tabs.Tab id="about">About</Tabs.Tab>
  </Tabs.List>
  <Tabs.Panel id="home">Nội dung Home</Tabs.Panel>
  <Tabs.Panel id="about">Nội dung About</Tabs.Panel>
</Tabs>
Ví dụ thực tế: Radix UI, Headless UI, shadcn/ui dùng pattern này. Ghép flexible, accessibility sẵn, styling tuỳ ý.

4. Render Props

Component nhận 1 prop là function → gọi function đó với state/helper để render UI. "Tôi cho bạn dữ liệu, bạn tự render".

function Mouse({ render }) {
  const [pos, setPos] = useState({ x: 0, y: 0 });

  useEffect(() => {
    const h = (e) => setPos({ x: e.clientX, y: e.clientY });
    window.addEventListener('mousemove', h);
    return () => window.removeEventListener('mousemove', h);
  }, []);

  return render(pos);
}

// Dùng
<Mouse render={({ x, y }) => (
  <h1>Chuột tại ({x}, {y})</h1>
)} />

// Hoặc qua children prop
<Mouse>
  {({ x, y }) => <h1>({x}, {y})</h1>}
</Mouse>
2026: Custom hooks phổ biến hơn render props vì đơn giản hơn. Nhưng render props vẫn hữu ích khi cần cấu trúc JSX động (vd: <Popover> truyền vị trí cho trigger).

5. Higher-Order Component (HOC)

Function nhận component, trả về component mới (bọc thêm logic). Legacy pattern — custom hooks làm việc này tốt hơn trong function component.

// HOC: bọc component để thêm auth check
function withAuth(Component) {
  return function WithAuth(props) {
    const user = useUser();
    if (!user) return <Login />;
    return <Component {...props} user={user} />;
  };
}

// Dùng
const ProtectedDashboard = withAuth(Dashboard);
Khi nào vẫn dùng HOC? Khi cần bọc prop injection cho component class (code cũ), hoặc cần 1 pass đồng bộ bên ngoài React tree (vd integration với lib thứ 3 kiểu connect() của Redux cũ). Mặc định 2026: dùng hook.

6. Controlled vs Uncontrolled

Controlled — React nắm state

<input
  value={text}
  onChange={e => setText(e.target.value)}
/>

Dễ validate, transform, reset. Mặc định cho form thật.

Uncontrolled — DOM nắm state

<input defaultValue="abc" ref={inputRef} />

// Đọc qua ref khi cần
const value = inputRef.current.value;

Ít code hơn, tốt cho form đơn giản. React Hook Form dùng uncontrolled để perf cao.

7. Provider Pattern

Bọc app bằng 1 Provider để cung cấp API/state xuống toàn cây. Thường gặp: Theme, Auth, i18n, Query Client.

// Gom nhiều provider
function AppProviders({ children }) {
  return (
    <QueryClientProvider client={queryClient}>
      <ThemeProvider>
        <AuthProvider>
          <RouterProvider router={router}>
            {children}
          </RouterProvider>
        </AuthProvider>
      </ThemeProvider>
    </QueryClientProvider>
  );
}

// Hook bao ngoài cho tiện
function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth phải trong AuthProvider');
  return ctx;
}

8. State Reducer Pattern

Cho phép user tùy biến logic state của component. Hữu ích khi làm thư viện UI.

function Toggle({ stateReducer = (s, a) => a.changes }) {
  const [state, dispatch] = useReducer(
    (state, action) => {
      const changes = baseReducer(state, action);
      return stateReducer(state, { ...action, changes });
    },
    { on: false }
  );

  return <button onClick={() => dispatch({ type: 'toggle' })}>
    {state.on ? 'ON' : 'OFF'}
  </button>;
}

// User tuỳ biến: cấm tắt sau khi đã mở
<Toggle stateReducer={(state, { type, changes }) => {
  if (type === 'toggle' && state.on) return state;
  return changes;
}} />

10. Anti-Patterns cần tránh

❌ God Component

1 file 2000 dòng, 20 useState, gọi 5 API. Tách theo responsibility: data hook, presentational component, container.

❌ Prop drilling 5 tầng

Prop đi xuyên qua 5 component chỉ để dùng ở cuối. Dùng Context hoặc kéo state lên state store.

❌ Dùng Redux cho mọi state

Form state, modal open, collapsed sidebar → state cục bộ. Redux cho state liên app và complex (cart toàn site, auth).

❌ Effect chồng effect

1 effect set state A, effect khác phản ứng A set B, B set C… Gộp thành reducer hoặc tính derived state.

❌ Ref hack thay state

Dùng ref để bypass re-render khi bạn thật sự cần render lại. Ref là giá trị không-trigger-render; nếu UI cần update → state.

❌ Tạo component trong render

function Parent() {
  // SAI — component mới mỗi render → mất state
  function Child() { return <div/>; }
  return <Child/>;
}
