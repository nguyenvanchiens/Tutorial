1. Render Cycle & Reconciliation

Hiểu chính xác khi nào React render, render cái gì, và cách nó cập nhật DOM tối thiểu.

Khi nào component render?

  • State của nó thay đổi (setState)
  • Prop thay đổi (cha re-render truyền xuống)
  • Context mà nó consume thay đổi
  • Cha nó re-render (mặc định con cũng render, dù props y hệt)
Lưu ý: "cha render → con render" là mặc định. Tránh bằng React.memo hoặc cấu trúc lại cây.

Reconciliation — 2 pha

  1. Render phase: chạy function component, tạo VDOM mới
  2. Commit phase: diff VDOM cũ/mới, patch DOM thật, chạy useLayoutEffect → paint → useEffect

Render phase phải pure — không side effect. Side effect đặt trong effect hooks hoặc event handlers.

Key thay đổi = component bị huỷ & tạo lại

// Đổi userId → Form unmount và mount mới → state bên trong reset
<Form key={userId} user={user} />

// Hữu ích khi muốn force reset state mà không cần useEffect

2. Tối ưu Performance

Nguyên tắc thứ tự

  1. Đo trước, tối ưu sau — dùng React DevTools Profiler. Đừng đoán.
  2. Fix rendering thừa — state đặt đúng nơi, tách component nhỏ, pass children thay vì prop.
  3. Memo hoá — React.memo, useMemo, useCallback (khi cần).
  4. Virtualize — list >500 item dùng react-window / @tanstack/react-virtual.
  5. Code split — lazy + Suspense cho route/modal hiếm dùng.

React.memo — bỏ qua render nếu props không đổi

const Avatar = React.memo(function Avatar({ src, alt }) {
  // chỉ render lại khi src hoặc alt đổi
  return <img src={src} alt={alt} />;
});

// Custom compare (hiếm dùng)
React.memo(Component, (prev, next) => {
  return prev.id === next.id;  // true = skip render
});
memo chỉ hiệu quả khi:
  1. Props là primitive hoặc reference ổn định (wrap bằng useMemo/useCallback ở cha)
  2. Component đó render tốn CPU
  3. Cha re-render thường xuyên
Thiếu 1 trong 3 → memo thành gánh nặng, không lợi ích.

Pattern "pass children" để tránh render thừa

❌ Con render mỗi khi cha render

function Parent() {
  const [count, setCount] = useState(0);
  return (
    <div>
      <button onClick={() => setCount(c+1)}>+</button>
      <ExpensiveChild />  // render thừa mỗi +
    </div>
  );
}

✅ Đẩy state xuống / nâng lên

function Parent({ children }) {
  // Parent nhận children → không re-render chúng
  const [count, setCount] = useState(0);
  return (
    <div>
      <button onClick={() => setCount(c+1)}>{count}</button>
      {children}
    </div>
  );
}

<Parent>
  <ExpensiveChild />
</Parent>

3. Code Splitting với lazy + Suspense

Chia bundle thành nhiều chunk nhỏ, load theo nhu cầu. Giảm initial load time đáng kể.

import { lazy, Suspense } from 'react';

// Không import trực tiếp
const Dashboard = lazy(() => import('./Dashboard'));
const Settings  = lazy(() => import('./Settings'));

function App() {
  return (
    <Suspense fallback={<Spinner />}>
      <Routes>
        <Route path="/" element={<Dashboard />} />
        <Route path="/settings" element={<Settings />} />
      </Routes>
    </Suspense>
  );
}
Chỗ nên split: Route, Modal lớn, trình editor (Monaco), chart lib, admin-only panel. Prefetch bằng onMouseEnter để load khi user sắp click.

4. Error Boundary

Bắt lỗi trong cây con, hiển thị UI fallback thay vì sập cả app. Phải là class component (hooks chưa thay thế được).

class ErrorBoundary extends React.Component {
  state = { hasError: false, error: null };

  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }

  componentDidCatch(error, info) {
    logToServer(error, info);  // Sentry, Datadog, …
  }

  render() {
    if (this.state.hasError) {
      return <div>Có lỗi xảy ra. <button onClick={() => this.setState({hasError: false})}>Thử lại</button></div>;
    }
    return this.props.children;
  }
}

// Dùng
<ErrorBoundary>
  <App />
</ErrorBoundary>
Error Boundary KHÔNG bắt:
  • Lỗi trong event handler (dùng try/catch)
  • Lỗi async (Promise reject) — dùng .catch() hoặc react-error-boundary
  • Lỗi trong SSR
  • Lỗi trong chính boundary
Lib khuyên dùng: react-error-boundary — cung cấp hook useErrorBoundary() + fallback component API gọn hơn.

5. Portals — Render ra ngoài cây DOM

Render component vào DOM node khác (thường document.body) mà vẫn giữ React tree — event bubble theo React tree, không theo DOM.

import { createPortal } from 'react-dom';

function Modal({ open, onClose, children }) {
  if (!open) return null;

  return createPortal(
    <div className="modal-overlay" onClick={onClose}>
      <div className="modal" onClick={e => e.stopPropagation()}>
        {children}
      </div>
    </div>,
    document.body
  );
}
Dùng cho: Modal, Tooltip, Toast, Dropdown — thứ cần thoát khỏi overflow: hidden hay z-index stacking của cha.

6. Refs Forwarding & useImperativeHandle

forwardRef

Cho phép cha truyền ref vào component con (mặc định ref không được coi như prop).

const Input = forwardRef((props, ref) => (
  <input ref={ref} {...props} />
));

// Ở cha
const ref = useRef();
<Input ref={ref} />;
ref.current.focus();
React 19: ref giờ là prop thường, không cần forwardRef nữa.

useImperativeHandle

Tùy biến API mà cha thấy qua ref — chỉ expose function cần thiết, ẩn DOM node thật.

const FancyInput = forwardRef((props, ref) => {
  const inputRef = useRef();

  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current.focus(),
    clear: () => inputRef.current.value = '',
  }));

  return <input ref={inputRef} />;
});

7. Concurrent Features (React 18+)

useTransition

Chia update thành 2 loại: urgent (input, click) và transition (update UI nặng). React ưu tiên urgent, có thể huỷ/gián đoạn transition.

const [isPending, startTransition] = useTransition();

function onType(e) {
  setQuery(e.target.value);  // urgent → input mượt
  startTransition(() => {
    setResults(filter(bigList, e.target.value));  // có thể gián đoạn
  });
}

{isPending && <Spinner />}

useDeferredValue

Biến giá trị thành "deferred version" — dùng cho Results chậm cập nhật, input nhanh.

const query = useState('');
const deferredQuery = useDeferredValue(query);

<Input value={query} onChange={setQuery} />
<Results query={deferredQuery} />  // chậm hơn 1 nhịp, nhưng input mượt
React 19 mới: useOptimistic, useActionState, useFormStatus — cho Form Actions và Server Actions (xem Ecosystem / Next.js).

8. Virtualization cho list lớn

Render 10,000 item = DOM ngạt thở. Chỉ render những item đang thấy trong viewport.

// Dùng @tanstack/react-virtual
import { useVirtualizer } from '@tanstack/react-virtual';

function BigList({ items }) {
  const parentRef = useRef();

  const rowVirtualizer = useVirtualizer({
    count: items.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 40,
    overscan: 5,
  });

  return (
    <div ref={parentRef} style={{ height: 400, overflow: 'auto' }}>
      <div style={{ height: rowVirtualizer.getTotalSize(), position: 'relative' }}>
        {rowVirtualizer.getVirtualItems().map(v => (
          <div key={v.key} style={{ position: 'absolute', top: v.start, height: v.size }}>
            {items[v.index].name}
          </div>
        ))}
      </div>
    </div>
  );
}
