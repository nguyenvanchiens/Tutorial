Triết lý học React

🎯 20% Cốt lõi = 80% Giá trị

Hiểu rendering model, state & props, hooks, và unidirectional data flow. Nắm vững bản chất, mọi thứ còn lại chỉ là API.

  • JSX là syntactic sugar của React.createElement
  • Component là function nhận props, trả về UI
  • State thay đổi → React re-render → reconcile VDOM
  • Hooks là cách inject behavior vào function component

Mental Model của React

Hiểu 4 nguyên lý này, bạn dùng React đúng bản chất chứ không "chỉ cho chạy được".

1. UI là hàm của State

Xem UI như UI = f(state). Mỗi lần state đổi, React tính lại f(state) và so sánh với lần trước để cập nhật DOM tối thiểu.

// Bạn không "cập nhật DOM" — bạn mô tả UI theo state
function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>
    {count} clicks
  </button>;
}

2. Dữ liệu đi xuống, event đi lên

Cha truyền props xuống con. Con gọi callback do cha cung cấp để báo sự kiện ngược lên. Đây là unidirectional data flow — dễ debug, khó rối.

<Parent>
  <Child value={state} onChange={setState} />
</Parent>

3. Re-render ≠ Re-paint DOM

"React re-render" = gọi lại function component. Nó không có nghĩa là DOM bị thay. Reconciler so sánh VDOM cũ/mới rồi chỉ patch phần khác.

Hệ quả: đừng tối ưu React.memo sớm. Re-render rẻ hơn bạn tưởng, trừ khi component làm tính toán nặng.

4. State cục bộ hóa tới mức thấp nhất

Chỉ lift state up khi nhiều component cùng cần state đó. State đặt ở cha quá cao → nhiều component con re-render thừa.

Dấu hiệu sai: App.jsx có 20 useState → bạn đang dùng React như global store.

Sai lầm kinh điển khi học React

❌ Mutate state trực tiếp

// SAI
state.items.push(newItem);
setItems(state.items);

// ĐÚNG
setItems([...state.items, newItem]);

❌ Dùng index làm key trong list động

Khi list thay đổi thứ tự/insert/remove, index-key làm React nhận nhầm item → state dính sai element. Dùng id ổn định.

❌ setState trong render

// SAI — infinite loop
function Comp() {
  const [x, setX] = useState(0);
  setX(x + 1); // BOOM
}

❌ Quên cleanup trong useEffect

Subscribe/interval/listener phải return cleanup, không thì memory leak khi unmount.

❌ Nhét tất cả vào một component

Component > 300 dòng, có nhiều vai trò → tách theo trách nhiệm, không tách theo "loại" (component/util/helper).

❌ Optimize sớm với useMemo/useCallback

Chúng có chi phí. Chỉ memo khi (1) tính toán thật sự nặng, hoặc (2) dependency của component con đã React.memo.
