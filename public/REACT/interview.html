Phỏng vấn React

Câu hỏi thường gặp, đáp án ngắn gọn nhưng đầy đủ. Đọc xong tự trả lời — đừng học thuộc.

🟢 Junior (L1-L2)

JR1. Virtual DOM là gì? Khác gì Real DOM?

Virtual DOM là cây object JS mô tả UI. Mỗi lần state đổi, React tạo VDOM mới, diff với VDOM cũ để tìm thay đổi tối thiểu, rồi patch lên DOM thật.

Lợi ích: (1) DX tốt — mình viết khai báo, không tự thao tác DOM; (2) batch nhiều update → giảm reflow; (3) abstraction cho SSR, React Native.

JR2. Phân biệt State vs Props
  • Props: truyền từ cha xuống con, immutable trong con. Giống tham số function.
  • State: dữ liệu nội bộ component, thay đổi qua setState, trigger re-render.
JR3. Tại sao key quan trọng trong list?

React dùng key để nhận diện item giữa các lần render. Key ổn định → tái sử dụng DOM node, giữ state. Key trùng/đổi → bug state dính sai item, hoặc remount tốn tài nguyên.

Tránh dùng index khi list có thể reorder/insert/remove.

JR4. Controlled vs Uncontrolled Component?
  • Controlled: value + onChange — React giữ state. Dễ validate, nhiều render.
  • Uncontrolled: defaultValue + ref — DOM giữ. Ít render, đọc qua ref.
JR5. JSX là gì?

Cú pháp extension của JS cho phép viết UI giống HTML. Trình biên dịch (Babel/SWC) compile thành React.createElement(type, props, children). Cuối cùng nó vẫn là object JS.

JR6. Khi nào dùng Fragment <>...</>?

Component phải return 1 root element. Nếu không muốn thêm div thừa vào DOM (ảnh hưởng layout, CSS selector) → dùng Fragment.

JR7. useEffect với deps array hoạt động ra sao?
  • Không truyền: chạy mọi render.
  • []: chạy 1 lần sau mount.
  • [a, b]: chạy khi a hoặc b đổi (so sánh Object.is).

Cleanup chạy trước lần effect kế tiếp và khi unmount.

JR8. Lift state up là gì?

Khi 2 component anh em cần chia sẻ state → di chuyển state lên component cha chung gần nhất, truyền xuống qua props + callback. Là pattern cơ bản của unidirectional data flow.

JR9. Sự khác nhau giữa class component và function component?

Function component + hooks là chuẩn hiện tại. Class vẫn hợp lệ nhưng verbose, không dùng được hooks. Error Boundary hiện vẫn cần class.

JR10. setState có phải async không?

Không hoàn toàn. Nó lên lịch update, React batch nhiều setState cùng tick rồi render 1 lần. Trong cùng handler, đọc state ngay sau setState vẫn là giá trị cũ. Dùng setCount(c => c + 1) khi cần giá trị mới dựa trên cũ.

🟠 Middle (L3)

MID11. Reconciliation là gì?

Quá trình React so sánh VDOM cũ/mới để tính diff tối thiểu. Heuristic:

  • Khác loại element (vd div → span) → huỷ sub-tree, tạo mới.
  • Cùng loại: giữ DOM, update prop.
  • List: so sánh qua key để reorder thay vì tạo mới.
MID12. Khi nào dùng useMemo/useCallback?

Chỉ 3 trường hợp:

  • Tính toán thực sự nặng (sort/filter list lớn, parse data)
  • Giữ reference ổn định cho prop của component đã React.memo
  • Làm dep cho useEffect để tránh chạy lại không cần thiết

Ngoài ra: đừng memo. Memo có chi phí compare + lưu bộ nhớ.

MID13. React.memo hoạt động ra sao?

Bọc component, so sánh props bằng shallow equality. Nếu prop không đổi → skip render. Mặc định so sánh Object.is từng key; có thể truyền custom areEqual.

Điều kiện hiệu quả: prop phải stable reference — nếu cha truyền object/function inline → memo vô dụng.

MID14. Stale closure là gì? Cho ví dụ.
function Counter() {
  const [c, setC] = useState(0);
  useEffect(() => {
    const id = setInterval(() => {
      setC(c + 1);  // c đóng gói từ render đầu = 0
    }, 1000);
    return () => clearInterval(id);
  }, []);  // [] → không bao giờ tạo lại closure
}

Fix: setC(prev => prev + 1) hoặc thêm c vào deps.

MID15. Context hiệu suất kém khi nào?

Mọi consumer re-render khi value đổi. Nếu:

  • Value là object mới mỗi render (không memo)
  • Nhiều component consume chỉ 1 phần nhỏ của value

→ toàn cây re-render. Giải pháp: memo value, split context theo domain (ThemeContext, AuthContext), hoặc dùng Zustand/Jotai cho state phức tạp.

MID16. useLayoutEffect khác useEffect thế nào?
  • useEffect: chạy bất đồng bộ sau khi DOM đã paint.
  • useLayoutEffect: chạy đồng bộ sau DOM mutation, trước paint.

Dùng layout effect khi cần đo DOM (getBoundingClientRect) rồi điều chỉnh để tránh flash.

MID17. Cách tránh fetch data gây race condition?

Trong useEffect dùng AbortController huỷ request cũ khi deps đổi hoặc unmount. Hoặc đơn giản hơn: dùng React Query/SWR — tự xử lý.

MID18. Suspense là gì, dùng khi nào?

Component đặc biệt render fallback trong khi child "đang load". Dùng với:

  • lazy để code split
  • Data fetching tương thích (RSC, Relay, React Query + useSuspenseQuery)
MID19. Phân biệt useTransition vs useDeferredValue
  • useTransition: đánh dấu update là non-urgent. Có isPending.
  • useDeferredValue: đánh dấu value deferred. Không có pending flag, nhưng không cần đụng setter.

Dùng cho filter/search UI mượt khi list lớn.

MID20. Khi nào chọn Context thay Redux?
  • Context: state tương đối static (theme, locale, user info), ít consumer.
  • Redux/Zustand: state có nhiều action, cần devtools, selector fine-grained để tránh re-render.
MID21. Portal là gì?

createPortal(children, domNode) render child vào 1 DOM node khác (thường body) nhưng giữ nguyên vị trí trong React tree — event vẫn bubble theo React tree. Dùng cho Modal, Tooltip.

MID22. StrictMode làm gì?

Trong dev, cố ý gọi effect và component function 2 lần để phát hiện side effect bẩn, cảnh báo API deprecate. Production không ảnh hưởng.

MID23. Làm sao cancel request khi unmount?
useEffect(() => {
  const ctrl = new AbortController();
  fetch(url, { signal: ctrl.signal });
  return () => ctrl.abort();
}, [url]);
MID24. Error Boundary bắt được những lỗi nào?

Bắt: lỗi trong render, lifecycle, constructor của component con.

Không bắt: event handler (try/catch), async code (Promise reject), SSR, lỗi trong chính Error Boundary.

MID25. Code splitting trong React?

Chia bundle thành nhiều chunk, load theo nhu cầu bằng dynamic import. React cung cấp React.lazy + Suspense. Áp dụng cho route, modal lớn, editor, chart lib.

🔴 Senior (L4-L5)

SR26. Giải thích cơ chế Fiber

Fiber là kiến trúc reconciler từ React 16. Mỗi element thành 1 "fiber node" — đơn vị công việc có thể interrupt, resume, prioritize. Nhờ đó có Concurrent Mode, time-slicing, Suspense.

Render phase bây giờ không phải stack đệ quy mà là linked list các fiber, cho phép React nhường CPU cho event browser.

SR27. Server Components khác Client Components?
  • Server Component: render ở server, không có state/effect, không gửi JS xuống client. Truy cập trực tiếp DB/file.
  • Client Component: có 'use client', có hook/state/event, JS gửi xuống browser.

Chiến lược: Server làm default, đẩy Client ra lá cây để giảm bundle client.

SR28. Làm sao thiết kế component reusable?
  • Composition over props: ưu tiên children/slot hơn là 20 cờ showX.
  • Sensible defaults: 90% dùng không cần config.
  • Escape hatch: className, style, ref forward cho custom.
  • Controlled + uncontrolled: support cả hai.
  • Accessibility mặc định: role, aria, keyboard.
SR29. Strategy tối ưu perf một trang nặng?
  1. Measure: Profiler + Performance tab, xác định bottleneck (render, JS, network, layout).
  2. Nếu render thừa: restructure (push state xuống, pass children, memo có mục đích).
  3. Nếu list lớn: virtualize.
  4. Nếu bundle lớn: code split, tree-shake, import theo nhu cầu.
  5. Nếu network: React Query cache, prefetch, HTTP cache, CDN.
  6. Image: lazy load, AVIF/WebP, responsive srcSet.
SR30. Cách test custom hook?

Dùng renderHook của RTL:

import { renderHook, act } from '@testing-library/react';

test('useCounter tăng', () => {
  const { result } = renderHook(() => useCounter(0));
  act(() => result.current.increment());
  expect(result.current.count).toBe(1);
});
SR31. Khi nào Redux Toolkit thắng Zustand?
  • Team > 10 dev, cần convention chặt (slice, thunk).
  • Cần Redux DevTools + time-travel debug.
  • Tích hợp với middleware phức tạp (saga, offline sync).
  • Migrate từ code Redux cũ.

Còn lại Zustand gần như luôn đủ và đơn giản hơn.

SR32. Giải thích useSyncExternalStore

Hook chuẩn để subscribe vào external store (Redux, Zustand internal, browser API). Đảm bảo tính nhất quán với concurrent rendering — tránh tearing (component đọc snapshot khác nhau trong cùng render).

SR33. React 19 có gì mới đáng chú ý?
  • Actions & useActionState, useFormStatus — form workflow với Server Actions.
  • useOptimistic — optimistic UI dễ dàng.
  • use() — đọc Promise/Context ngay trong render.
  • Ref giờ là prop thường, không cần forwardRef.
  • Document metadata (title, meta) render trực tiếp trong component.
  • Compiler (experimental) — tự memo, bỏ useMemo/useCallback thủ công.
SR34. React Compiler làm gì?

Compiler tại build time phân tích component, tự động memo giá trị và function đủ điều kiện → bỏ useMemo/useCallback/React.memo thủ công. Tương tự Svelte/Solid nhưng vẫn giữ mental model React.

SR35. Design system với React — architecture thế nào?
  • Tokens: color, spacing, typography bằng CSS variable — dễ theme.
  • Primitives: Radix/Headless UI cho logic & a11y.
  • Styled layer: Tailwind/CVA/CSS Module.
  • Component API chuẩn hoá: variant, size, asChild pattern.
  • Storybook + visual regression.
  • Publish qua npm workspace hoặc monorepo (Turborepo).
SR36. Hydration mismatch là gì?

Xảy ra khi HTML render ở server khác với lần render đầu ở client (ví dụ: dùng Date.now(), window, localStorage trong render). Warning trong dev, có thể gây UI nhảy.

Fix: dùng useEffect để set giá trị client-only, hoặc suppressHydrationWarning cho node dự kiến sẽ khác.

SR37. SSR, SSG, ISR khác nhau thế nào?
  • SSR: render HTML mỗi request. Luôn mới. Tốn CPU server.
  • SSG: render tại build time, trả file tĩnh. Nhanh nhất, cache CDN.
  • ISR: SSG + revalidate định kỳ/on-demand. Cân bằng speed và freshness.
SR38. Bạn xử lý auth trong React app lớn ra sao?
  • Token (JWT/session) lưu httpOnly cookie (chống XSS) hoặc memory + refresh token rotation.
  • Context/Store cung cấp user, login, logout.
  • Route guard (RequireAuth) check user, redirect /login và giữ from location.
  • API client interceptor: đính token, retry khi 401 với refresh.
  • Framework: NextAuth/Clerk/Auth0 nếu cần OAuth, MFA, SSO.
SR39. Làm sao kiểm soát bundle size?
  • Bundle analyzer (rollup-plugin-visualizer) — tìm chunk to.
  • Tree-shake: import theo tên, tránh import *.
  • Chọn lib nhẹ: date-fns > moment, lodash-es/ > lodash full.
  • Code splitting theo route/feature.
  • Avoid duplicate: dùng peerDependencies đúng, check lockfile.
  • SSR render static content để giảm JS gửi xuống client.
SR40. Monorepo React: Turborepo vs Nx?
  • Turborepo: nhẹ, tập trung task cache & pipeline. Dễ adopt.
  • Nx: feature-rich — plugin cho mọi framework, code generator, module boundary rule. Phù hợp enterprise.

🧠 Coding Challenges

Bài code thực tế trong phỏng vấn React. Tự làm trước, đáp án chỉ để tham khảo.

CC-1: useFetch với cancel

Viết hook useFetch(url) trả về {data, loading, error}, huỷ request cũ khi url đổi hoặc unmount.

CC-2: useDebounce

Hook debounce giá trị. Dùng để search instant mà không spam API.

CC-3: Todo app + localStorage

Add, toggle, delete, filter all/active/done. Persist qua reload.

CC-4: Star Rating component

5 sao click chọn, hover preview, keyboard accessibility, controlled.

CC-5: Compound Tabs

API <Tabs><Tabs.List><Tabs.Tab/>...</Tabs>, share state qua Context.

CC-6: Infinite scroll

IntersectionObserver để load trang kế khi sentinel element xuất hiện.

CC-7: Autocomplete

Input + dropdown gợi ý. Debounce input, keyboard nav (↑↓ Enter Esc), click outside đóng.

CC-8: Modal với Portal

Open/close, close ESC & click overlay, focus trap, scroll lock body.

CC-9: Virtualized List 10k item

Tự viết (không lib) render chỉ item trong viewport, handle scroll position.

CC-10: Form với nested fields

Form "Invoice" có array items {name, qty, price}. Add/remove row, tính total real-time.

🎯 Tips đi phỏng vấn

Khi được hỏi lý thuyết

  • Trả lời định nghĩa → ví dụ code ngắn → use case thực tế
  • Nhắc đến trade-off, không nói "luôn đúng"
  • Nhận biết câu hỏi gài (vd "bạn có dùng useMemo không?" → nói khi nào, đừng gật đại)

Khi code live

  • Đọc đề to, xác nhận yêu cầu trước khi code
  • Bắt đầu skeleton chạy được, sau đó mới tối ưu
  • Nói thành tiếng suy nghĩ — interviewer đánh giá cả process
  • Hỏi về test/edge case khi xong — chứng tỏ tư duy chất lượng

Câu nên hỏi lại

  • Quy mô app, traffic, team size?
  • Stack hiện tại + plan tương lai?
  • Code review, testing culture, CI/CD?
  • Lộ trình phát triển của vị trí này?

Cảnh báo đỏ

  • Công ty không có version control/PR review
  • "Deploy thẳng production không có test"
  • Từ chối cho thấy code mẫu/kiến trúc
  • Tech debt khổng lồ + không có roadmap cải thiện
