JavaScript & ES6+ Nền Tảng

React là JavaScript. Mọi "phép màu" của React (state immutability, props, hooks, render) đều dựa trên cú pháp JS hiện đại. Nắm chắc 14 khái niệm dưới đây trước khi chạm tay vào React — bạn sẽ học nhanh gấp đôi và đỡ bug.

1. let / const & Scope

Quên var đi. Năm 2026 chỉ dùng const mặc định, đổi sang let khi cần gán lại. Cả hai có block scope (giới hạn trong { }), khác var là function scope.

Block scope vs function scope

for (let i = 0; i < 3; i++) { /* ... */ }
console.log(i); // ❌ ReferenceError (i chết ngoài for)

for (var j = 0; j < 3; j++) {}
console.log(j); // 3 (var rò rỉ ra ngoài — nguồn bug)

const không phải "bất biến"

const n = 5;
n = 6;             // ❌ không gán lại biến được

const user = { name: 'Chiến' };
user.name = 'Lan';  // ✅ vẫn sửa được nội dung object
// const khoá BIẾN, không khoá GIÁ TRỊ bên trong
Vì sao quan trọng cho React: bạn sẽ viết const [count, setCount] = useState(0) hàng nghìn lần. Hiểu vì sao count là const mà vẫn "đổi" được (thực ra mỗi render là một biến const mới) là chìa khoá hiểu mental model của React.

2. Closures & bẫy "stale closure"

Closure = hàm "nhớ" được biến ở scope nơi nó được tạo ra, kể cả khi scope đó đã kết thúc. Đây là cơ chế nền của useState, useEffect và là nguồn của bug khó nhất khi mới học hooks.

Closure cơ bản

function makeCounter() {
  let count = 0;
  return () => ++count; // nhớ "count"
}
const inc = makeCounter();
inc(); // 1
inc(); // 2  — count sống dai nhờ closure

🐛 Stale closure cổ điển

// Mỗi callback bắt CÙNG biến i (var)
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// In ra: 3, 3, 3  (không phải 0,1,2!)

// Sửa: let tạo binding mới mỗi vòng lặp
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// In ra: 0, 1, 2 ✅
Bẫy này quay lại trong React: một setInterval đặt trong useEffect sẽ "đóng băng" giá trị state tại lần render đó. Đó là lý do bạn thấy counter luôn in 0. Cách xử lý: dùng functional update setCount(c => c + 1) hoặc useRef. Sẽ học kỹ ở trang Hooks.

3. this — và vì sao React ghét nó

this trong JS không trỏ tới "object hiện tại" như Java/C#. Nó phụ thuộc vào cách hàm được gọi. Arrow function không có this riêng — nó mượn từ scope ngoài (lexical this).

const obj = {
  name: 'Chiến',
  hello() { console.log(this.name); },        // "this" = obj khi gọi obj.hello()
  helloArrow: () => console.log(this.name),  // "this" = scope ngoài, KHÔNG phải obj
};

obj.hello();        // "Chiến"
const fn = obj.hello;
fn();               // undefined — mất "this" khi tách khỏi obj
Vì sao quan trọng cho React: React hiện đại dùng function component, gần như không còn this. Đây chính là lý do hooks ra đời — để né hoàn toàn cơn ác mộng this.handleClick = this.handleClick.bind(this) của class component cũ. Hiểu this giúp bạn đọc được code legacy.

4. ES Modules — import / export

React chia code thành module. Mỗi file là một module có scope riêng. Có named export (nhiều/file) và default export (một/file).

Export

// utils.js
export const PI = 3.14;          // named
export function sum(a, b) {     // named
  return a + b;
}
export default function App() {} // default (1/file)

Import

// app.js
import App from './utils.js';        // default — tên tuỳ ý
import { PI, sum } from './utils.js'; // named — đúng tên
import { sum as add } from './utils.js'; // đổi tên
import * as utils from './utils.js';    // gom hết
Vì sao quan trọng cho React: import React from 'react', import { useState } from 'react' — bạn dùng cú pháp này ở MỌI file. Phân biệt default vs named giúp tránh lỗi "X is not exported" kinh điển.

5. Destructuring

"Bóc tách" giá trị từ object/array ra biến riêng. React dùng destructuring ở khắp nơi: props, useState, useContext.

// Object destructuring
const user = { name: 'Chiến', age: 25, city: 'HN' };
const { name, age } = user;
const { city: queQuan } = user;        // đổi tên
const { role = 'user' } = user;        // default nếu undefined

// Array destructuring — useState chính là cái này!
const [first, second] = [10, 20];
const [count, setCount] = useState(0);

// Destructuring ngay trên tham số hàm (kiểu props React)
function Card({ title, children }) { /* ... */ }

// Lồng nhau
const { data: { items = [] } = {} } = response;
Vì sao quan trọng cho React: function Comp({ name, age }) chính là destructuring props. Và const [x, setX] = useState() trả về một array được destructure — không có nó React API sẽ xấu hơn nhiều.

6. Spread ... & Rest ...

Cùng ký hiệu ... nhưng hai vai trò: spread trải phần tử ra, rest gom phần tử lại. Đây là công cụ #1 để làm immutable update trong React.

Spread — sao chép + ghi đè

// Object — copy nông + override
const a = { x: 1, y: 2 };
const b = { ...a, y: 99 }; // {x:1, y:99}

// Array — copy + thêm
const arr = [1, 2];
const arr2 = [...arr, 3];  // [1,2,3]

// Trải tham số vào hàm
Math.max(...[3, 7, 2]); // 7

Rest — gom phần còn lại

// Trong destructuring
const { id, ...rest } = user; // rest = mọi field trừ id
const [head, ...tail] = [1, 2, 3]; // tail = [2,3]

// Tham số hàm không giới hạn
function log(...args) {
  console.log(args); // luôn là array
}
Vì sao quan trọng cho React: React render lại khi reference state thay đổi. Bạn không được user.name = 'x' rồi setUser(user) — reference không đổi, React không render. Phải setUser({ ...user, name: 'x' }) để tạo object mới. Spread là cách chuẩn làm immutable update.

7. Template Literals

Chuỗi với dấu backtick `, cho phép nội suy biến ${...} và xuống dòng. Dùng để ghép className động, URL, message.

const name = 'Chiến';
const age = 25;

// Nội suy biến + biểu thức
const msg = `Xin chào ${name}, năm sau bạn ${age + 1} tuổi`;

// Multi-line
const html = `
  <div>${name}</div>
`;

// className động trong JSX (rất hay gặp)
<button className={`btn ${isActive ? 'active' : ''}`} />
Vì sao quan trọng cho React: ghép className theo điều kiện, dựng URL gọi API, hiển thị message i18n — tất cả dùng template literal. Thư viện clsx/cn bạn sẽ gặp sau cũng chỉ là bản nâng cấp của ý tưởng này.

8. Optional chaining ?. & Nullish ??

Hai toán tử cứu mạng khi làm việc với dữ liệu API có thể null/undefined.

?. — truy cập an toàn

const user = { profile: null };

user.profile.avatar;   // ❌ TypeError, app crash
user.profile?.avatar;  // ✅ undefined, không crash

// Chuỗi dài an toàn
data?.user?.address?.city;

// Gọi hàm có thể không tồn tại
onClick?.(); // chỉ gọi nếu onClick có

?? — chỉ thay khi null/undefined

// || coi 0, '', false là "rỗng" → bug
const count = data.count || 10; // count=0 → ra 10 ❌

// ?? chỉ thay khi null/undefined
const count2 = data.count ?? 10; // count=0 → ra 0 ✅

const name = user.name ?? 'Khách';
Vì sao quan trọng cho React: render trước khi data về, {user?.name ?? 'Đang tải...'} tránh crash trang trắng. Phân biệt || và ?? tránh bug số 0 bị hiểu nhầm là rỗng — cực kỳ hay gặp với badge đếm số.

9. Array methods — map / filter / reduce / find

React render list bằng .map(), lọc dữ liệu bằng .filter(). Các method này trả về array mới (immutable) — đúng triết lý React.

const nums = [1, 2, 3, 4];

// map — biến đổi từng phần tử (DÙNG ĐỂ RENDER LIST)
nums.map(n => n * 2);              // [2,4,6,8]
users.map(u => <li key={u.id}>{u.name}</li>); // JSX!

// filter — giữ phần tử thoả điều kiện
nums.filter(n => n % 2 === 0);    // [2,4]

// reduce — gộp về 1 giá trị
nums.reduce((sum, n) => sum + n, 0); // 10
cart.reduce((t, item) => t + item.price, 0); // tổng tiền

// find — phần tử đầu thoả điều kiện (hoặc undefined)
users.find(u => u.id === 3);

// some / every — kiểm tra boolean
todos.some(t => !t.done);   // còn việc chưa xong?
todos.every(t => t.done);   // xong hết chưa?
Vì sao quan trọng cho React: {items.map(...)} là cách DUY NHẤT render danh sách trong JSX. filter/map tạo array mới nên dùng update state an toàn. Tránh forEach/push (mutate, không trả giá trị) trong render.

10. Immutability Patterns

React phát hiện thay đổi bằng so sánh reference (===), không deep-compare. Vì vậy mọi update phải tạo object/array mới, không sửa cái cũ.

❌ Mutate (React không thấy)✅ Immutable (tạo mới)
arr.push(x)[...arr, x]
arr.splice(i, 1)arr.filter((_, idx) => idx !== i)
arr[i] = xarr.map((v, idx) => idx === i ? x : v)
obj.key = x{ ...obj, key: x }
arr.sort() (mutate!)[...arr].sort() hoặc arr.toSorted()
delete obj.keyconst { key, ...rest } = obj
// Cập nhật phần tử lồng trong array of objects
const nextTodos = todos.map(t =>
  t.id === id ? { ...t, done: !t.done } : t
);
setTodos(nextTodos);

// Cập nhật object lồng sâu — spread từng tầng
setState(s => ({
  ...s,
  user: { ...s.user, address: { ...s.user.address, city: 'HN' } }
}));
Vì sao quan trọng cho React: đây là lỗi #1 của người mới — "vì sao state đổi mà màn hình không update?". 90% là do mutate. Khi update lồng sâu mệt mỏi, dùng thư viện immer (sẽ học ở Patterns).

11. Promises & async/await

JS chạy bất đồng bộ. Promise là "lời hứa" sẽ có kết quả sau. async/await là cú pháp đẹp để xử lý nó như code đồng bộ.

Promise (cách cũ — then/catch)

fetch('/api/users')
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => console.error(err))
  .finally(() => setLoading(false));

async/await (chuẩn 2026)

async function loadUsers() {
  try {
    const res = await fetch('/api/users');
    if (!res.ok) throw new Error(res.status);
    const data = await res.json();
    return data;
  } catch (err) {
    console.error(err);
  } finally {
    setLoading(false);
  }
}
// Chạy SONG SONG nhiều request (nhanh hơn await tuần tự)
const [users, posts] = await Promise.all([
  fetch('/api/users').then(r => r.json()),
  fetch('/api/posts').then(r => r.json()),
]);
Vì sao quan trọng cho React: mọi lần gọi API trong useEffect hoặc event handler đều là async. Hiểu Promise giúp bạn quản lý loading/error state đúng. Lưu ý: bản thân function truyền cho useEffect KHÔNG được là async — phải khai báo hàm async bên trong rồi gọi.

12. fetch & AbortController

fetch là API gọi HTTP có sẵn trong trình duyệt. AbortController dùng để huỷ request — cực quan trọng để tránh race condition và memory leak trong React.

async function search(query, signal) {
  const res = await fetch(`/api/search?q=${query}`, {
    method: 'GET',
    headers: { 'Content-Type': 'application/json' },
    signal, // gắn signal để có thể huỷ
  });
  return res.json();
}

// Trong useEffect — huỷ request cũ khi query đổi / unmount
useEffect(() => {
  const controller = new AbortController();

  search(query, controller.signal)
    .then(setResults)
    .catch(err => {
      if (err.name !== 'AbortError') console.error(err);
    });

  return () => controller.abort(); // cleanup: huỷ request
}, [query]);
Vì sao quan trọng cho React: nếu user gõ nhanh ô search, request cũ về sau request mới sẽ ghi đè kết quả đúng (race condition). AbortController trong cleanup function của useEffect giải quyết triệt để. Đây là pattern phỏng vấn rất hay hỏi.

13. DOM & Event Model (cơ bản)

React tự quản DOM cho bạn, nhưng hiểu DOM thật giúp bạn hiểu React làm gì "dưới mui xe" và khi nào cần ref để chạm DOM trực tiếp.

DOM thuần (cái React thay thế)

const el = document.getElementById('root');
el.textContent = 'Hello';
el.addEventListener('click', handler);
// React: bạn KHÔNG viết kiểu này nữa

Event bubbling & delegation

// Click con → nổi bọt lên cha
parent.addEventListener('click', (e) => {
  console.log(e.target);  // phần tử bị click
  e.stopPropagation();    // chặn nổi bọt
  e.preventDefault();     // chặn hành vi mặc định
});
Vì sao quan trọng cho React: React dùng Virtual DOM — mô tả UI bằng object JS rồi tự tính diff để cập nhật DOM thật tối thiểu. React cũng gắn event ở root và dùng delegation (Synthetic Events). Khi cần focus input, đo kích thước, tích hợp thư viện ngoài → bạn dùng useRef để chạm DOM thật.

14. npm / npx & vai trò của Bundler

Hệ sinh thái React sống trên npm. Bundler (Vite) gom hàng trăm file module + dependency thành bundle tối ưu cho trình duyệt.

npm vs npx

# npm: cài package vào project
npm install react react-dom
npm install -D vite        # dev dependency

# npx: chạy package mà không cần cài global
npx create-vite@latest my-app

# scripts trong package.json
npm run dev     # chạy script "dev"
npm run build

Bundler làm gì?

  • Resolve modules: nối các import lại
  • Transpile: JSX/TS → JS trình duyệt hiểu (Babel/esbuild)
  • Bundle & split: gom code, tách chunk lazy-load
  • Tree-shaking: bỏ code không dùng
  • HMR: cập nhật nóng khi đang dev
  • Minify: nén code cho production
Vì sao quan trọng cho React: JSX và import './style.css' KHÔNG phải JS hợp lệ với trình duyệt — bundler biến chúng thành code chạy được. Vite là chuẩn 2026 (esbuild + Rollup): dev server khởi động tức thì, HMR nhanh. Hiểu bundler giúp bạn debug lỗi build và tối ưu bundle size.

💡 Bài tập thực hành

  1. Refactor sang ES6+
    Cho đoạn code dùng var + function + nối chuỗi bằng +. Viết lại bằng const/let, arrow, destructuring, template literal.
  2. Sửa stale closure
    Vòng for(var i...) + setTimeout in 3,3,3. Sửa thành 0,1,2 bằng cả 2 cách: dùng let và dùng IIFE.
  3. Chuỗi array methods
    Cho mảng đơn hàng. Tính tổng tiền các đơn "đã thanh toán" chỉ bằng filter + map + reduce (không dùng vòng lặp).
  4. Immutable update
    Cho object user lồng 3 tầng. Viết hàm đổi user.address.city mà KHÔNG mutate bản gốc. Kiểm tra oldUser !== newUser nhưng oldUser.posts === newUser.posts.
  5. Fetch có huỷ
    Viết hàm async gọi một public API (vd JSONPlaceholder), có try/catch, đo thời gian, và hỗ trợ huỷ bằng AbortController.
