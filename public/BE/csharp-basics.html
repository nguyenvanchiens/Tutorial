Nền tảng C# cho .NET 8/9

Tất cả những gì một backend developer cần nắm vững trước khi viết Web API: kiểu dữ liệu & memory model, biến/hằng, control flow hiện đại, collections, exceptions, nullability, records, pattern matching và string handling. Cập nhật cho C# 12/13 và .NET 8/9 năm 2026.

1. Kiểu dữ liệu — Value Types vs Reference Types

Đây là khái niệm nền tảng quan trọng nhất. Hiểu sai chỗ này sẽ dẫn tới bug copy/tham chiếu khó debug. Mọi kiểu trong C# đều thuộc một trong hai nhóm.

📦 Value Type (kiểu giá trị)

Lưu trực tiếp giá trị. Khi gán/truyền tham số → copy toàn bộ dữ liệu.

  • Các kiểu số: int, long, double, decimal
  • bool, char
  • struct (vd DateTime, Guid)
  • enum
  • Thường nằm trên stack (hoặc inline trong object)

🔗 Reference Type (kiểu tham chiếu)

Biến chỉ lưu địa chỉ (reference) trỏ tới object trên heap. Khi gán → copy địa chỉ, cùng trỏ 1 object.

  • class, record (mặc định)
  • string, object
  • Array, List<T>, delegate
  • Object luôn nằm trên heap, do GC quản lý

Copy semantics — minh hoạ rõ ràng

// VALUE TYPE — copy giá trị, độc lập hoàn toàn
int a = 10;
int b = a;        // b nhận BẢN SAO của giá trị 10
b = 20;
Console.WriteLine(a); // 10  — a KHÔNG đổi

// REFERENCE TYPE — copy địa chỉ, cùng trỏ 1 object
var list1 = new List<int> { 1, 2, 3 };
var list2 = list1;    // list2 trỏ CÙNG object với list1
list2.Add(4);
Console.WriteLine(list1.Count); // 4  — list1 BỊ ảnh hưởng!
⚠️ Bug kinh điển: gán một List<T> / object cho biến khác rồi sửa, tưởng là 2 bản riêng nhưng thực chất là cùng 1 object. Muốn copy thật sự phải tạo collection/object mới: new List<int>(list1).

struct vs class — memory model

// STRUCT — value type, copy khi truyền, không null (trừ Nullable)
public struct Point
{
    public int X { get; init; }
    public int Y { get; init; }
}

// CLASS — reference type, share qua địa chỉ, có thể null
public class Customer
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
}

var p1 = new Point { X = 1, Y = 2 };
var p2 = p1;   // COPY toàn bộ — p2 độc lập

var c1 = new Customer { Name = "An" };
var c2 = c1;   // COPY địa chỉ — c1 và c2 cùng 1 object
c2.Name = "Bình";
Console.WriteLine(c1.Name); // "Bình" — c1 thay đổi theo
💡 Khi nào dùng struct? Khi kiểu nhỏ (≤16 byte), immutable, biểu diễn 1 giá trị đơn (toạ độ, tiền, khoảng thời gian) và được tạo nhiều — tránh áp lực GC. Còn lại, mặc định dùng class.

Boxing & Unboxing

Boxing = gói một value type vào một object trên heap. Unboxing = lấy lại ra. Cả hai đều tốn allocation + ép kiểu → tránh trong hot path.

int n = 42;
object boxed = n;          // BOXING: n được copy lên heap
int back = (int)boxed;     // UNBOXING: phải ép đúng kiểu, sai → InvalidCastException

// Tránh boxing ngầm — dùng generic thay vì object
List<int> good = [1, 2, 3];   // không boxing
ArrayList bad = [1, 2, 3];     // boxing mỗi phần tử (legacy)

2. Biến & Hằng — var, const, readonly

C# là ngôn ngữ static-typed: mọi biến có kiểu xác định lúc compile. Có nhiều cách khai báo, mỗi cách phục vụ mục đích khác nhau.

// Khai báo tường minh (explicit)
int count = 0;
List<string> names = new List<string>();

// Implicit typing với var — compiler suy ra kiểu, vẫn static-typed
var total = 100;             // int
var message = "Xin chào";     // string
var items = new List<int>();  // List<int>

// Target-typed new (C# 9+) — gọn khi kiểu đã rõ ở vế trái
List<string> cities = new();        // suy ra List<string>
Dictionary<int, string> map = new(); // gọn hơn lặp lại tên kiểu

const vs readonly

Đặc điểmconstreadonly
Gán giá trịLúc khai báo (compile-time)Lúc khai báo hoặc trong constructor (runtime)
Kiểu cho phépChỉ literal hằng (số, chuỗi, bool)Bất kỳ kiểu nào kể cả object

public class Circle
{
    public const double Pi = 3.14159;          // hằng compile-time
    public readonly int Radius;                   // chỉ gán trong ctor
    public static readonly DateTime Created = DateTime.UtcNow; // runtime

    public Circle(int radius) => Radius = radius; // OK: gán readonly trong ctor
}
⚠️ Cẩn thận với const public: giá trị const được "nhúng" (inline) vào assembly gọi nó lúc compile. Nếu thay đổi const trong thư viện mà không build lại bên gọi, giá trị cũ vẫn còn. Với hằng public chia sẻ giữa nhiều project → ưu tiên static readonly.

3. Control Flow — Điều khiển luồng hiện đại

C# hiện đại khuyến khích biểu thức (expression) gọn gàng thay cho câu lệnh dài dòng. Nắm cả phong cách cũ và mới.

if / else & toán tử ba ngôi (ternary)

int score = 85;

if (score >= 90)
    Console.WriteLine("Xuất sắc");
else if (score >= 70)
    Console.WriteLine("Khá");
else
    Console.WriteLine("Cần cố gắng");

// Ternary — gọn cho gán điều kiện đơn giản
string label = score >= 50 ? "Đậu" : "Rớt";

switch expression (C# 8+) — thay cho switch statement

// CÁCH CŨ — switch statement dài dòng
string GetName(int day)
{
    switch (day)
    {
        case 1: return "Thứ Hai";
        case 2: return "Thứ Ba";
        default: return "Không rõ";
    }
}

// CÁCH MỚI — switch expression, gọn và rõ ràng
string GetDayName(int day) => day switch
{
    1 => "Thứ Hai",
    2 => "Thứ Ba",
    3 => "Thứ Tư",
    >= 4 and <= 6 => "Cuối tuần sắp tới", // relational + logical pattern
    _ => "Không rõ"                              // _ = default
};

Vòng lặp: for / foreach / while / do-while

// for — biết trước số lần lặp, cần index
for (int i = 0; i < 5; i++)
    Console.WriteLine(i);

// foreach — duyệt collection, KHÔNG sửa collection khi đang duyệt
var fruits = new[] { "Táo", "Cam", "Xoài" };
foreach (var fruit in fruits)
    Console.WriteLine(fruit);

// while — lặp khi điều kiện đúng (kiểm tra trước)
int n = 0;
while (n < 3) { Console.WriteLine(n); n++; }

// do-while — chạy ít nhất 1 lần (kiểm tra sau)
do { Console.WriteLine("Chạy ít nhất 1 lần"); } while (false);
⚠️ Không sửa collection trong foreach: thêm/xoá phần tử khi đang foreach sẽ ném InvalidOperationException ("Collection was modified"). Muốn xoá → dùng for ngược từ cuối, hoặc lọc bằng LINQ tạo list mới: list.Where(x => ...).ToList().

4. Collections — Chọn đúng cấu trúc dữ liệu

Chọn sai collection làm code chậm và rối. Mỗi loại tối ưu cho một kiểu truy cập khác nhau.

List<T>O(1) theo indexO(1) cuối, O(n) giữaMảng độngDanh sách thông thường (mặc định)

// Array — kích thước cố định
int[] numbers = [1, 2, 3, 4, 5];   // collection expression (C# 12)
Console.WriteLine(numbers[0]);          // 1
Console.WriteLine(numbers[^1]);         // 5 — index từ cuối
var middle = numbers[1..4];           // [2,3,4] — range

// List<T> — mảng động, thêm/xoá tự do
var tasks = new List<string>();
tasks.Add("Code");
tasks.AddRange(["Test", "Deploy"]);
tasks.Remove("Test");
Console.WriteLine(tasks.Count);            // 2

// Dictionary<K,V> — tra cứu theo khoá
var ages = new Dictionary<string, int>
{
    ["An"] = 25,
    ["Bình"] = 30
};
if (ages.TryGetValue("An", out var age))   // an toàn, không ném exception
    Console.WriteLine(age);                // 25

// HashSet<T> — không trùng lặp, kiểm tra tồn tại O(1)
var seen = new HashSet<int> { 1, 2, 2, 3 };
Console.WriteLine(seen.Count);             // 3 — bỏ trùng tự động
Console.WriteLine(seen.Contains(2));      // True
💡 TryGetValue vs indexer: truy cập dict["key"] với key không tồn tại sẽ ném KeyNotFoundException. Dùng TryGetValue hoặc ContainsKey khi không chắc key có sẵn. Tránh kiểm tra ContainsKey rồi lại lấy dict[key] (tra cứu 2 lần) — chỉ cần một TryGetValue.

5. Exceptions — Xử lý lỗi đúng cách

Exception biểu diễn lỗi không lường trước được. Xử lý sai (nuốt lỗi, bắt quá rộng) là nguồn bug âm thầm nguy hiểm nhất.

try
{
    var content = File.ReadAllText("data.json");
    var order = JsonSerializer.Deserialize<Order>(content);
    Process(order);
}
catch (FileNotFoundException ex)        // bắt loại cụ thể trước
{
    logger.LogWarning(ex, "Không tìm thấy file");
    throw;                              // throw; — giữ nguyên stack trace
}
catch (JsonException ex)
{
    logger.LogError(ex, "JSON sai định dạng");
    throw new InvalidDataException("File dữ liệu hỏng", ex); // wrap, giữ inner
}
finally
{
    // LUÔN chạy dù có lỗi hay không — dọn dẹp tài nguyên
    Console.WriteLine("Hoàn tất xử lý");
}

Custom exception & exception filter (when)

// Custom exception — kế thừa Exception, thêm dữ liệu ngữ cảnh
public class OrderNotFoundException : Exception
{
    public int OrderId { get; }
    public OrderNotFoundException(int orderId)
        : base($"Không tìm thấy đơn hàng {orderId}")
        => OrderId = orderId;
}

// Exception filter — chỉ bắt khi điều kiện 'when' đúng
try
{
    await CallApiAsync();
}
catch (HttpRequestException ex) when (ex.StatusCode == HttpStatusCode.TooManyRequests)
{
    await Task.Delay(1000);  // chỉ retry khi bị rate-limit (429)
    await CallApiAsync();
}

✅ NÊN làm

  • Bắt loại exception cụ thể (FileNotFoundException)
  • Dùng throw; để giữ stack trace gốc
  • Log đầy đủ context trước khi throw lại
  • Dùng finally hoặc using để dọn tài nguyên
  • Wrap exception thấp tầng thành lỗi nghiệp vụ rõ nghĩa

❌ KHÔNG nên

  • Nuốt lỗi: catch { } rỗng — bug biến mất âm thầm
  • throw ex; — reset stack trace, mất nơi lỗi gốc
  • Bắt catch (Exception) chung cho mọi thứ
  • Dùng exception cho luồng điều khiển bình thường
  • Ném exception trong vòng lặp nóng (rất chậm)
⚠️ throw; vs throw ex;: throw; ném lại exception giữ nguyên stack trace gốc. throw ex; đặt lại stack trace về dòng hiện tại → mất dấu vết nơi lỗi thực sự xảy ra. Luôn dùng throw; khi re-throw.

6. Nullability — Xử lý null an toàn

NullReferenceException là lỗi runtime phổ biến nhất lịch sử. C# hiện đại cung cấp công cụ để chặn nó ngay lúc compile.

Nullable value types — int?

int a = null;     // LỖI compile — int không thể null
int? b = null;    // OK — Nullable<int>, có thể null

if (b.HasValue)
    Console.WriteLine(b.Value);
int c = b ?? 0;   // ?? null-coalescing: nếu null thì lấy 0

Nullable Reference Types (NRT) — #nullable enable

// Bật trong .csproj: <Nullable>enable</Nullable>  (mặc định trong template .NET 6+)
// hoặc đầu file:
#nullable enable

string name = null;      // CẢNH BÁO — string không khai báo nullable
string? nickname = null;  // OK — chủ đích cho phép null

void Greet(string? n)
{
    // Phải kiểm tra null trước khi dùng, nếu không compiler cảnh báo
    if (n is not null)
        Console.WriteLine($"Chào {n.ToUpper()}");
}

Các toán tử null tiện lợi

// ?. — null-conditional: chỉ gọi nếu không null, ngược lại trả null
int? len = customer?.Name?.Length;   // null nếu customer hoặc Name null

// ?? — null-coalescing: giá trị mặc định khi null
string display = customer?.Name ?? "Khách lạ";

// ??= — gán nếu đang null
string? cache = null;
cache ??= LoadFromDb();              // chỉ gọi LoadFromDb khi cache null

// ! — null-forgiving: "tôi chắc chắn không null" (dùng dè dặt!)
string sure = GetValue()!;           // tắt cảnh báo, tự chịu trách nhiệm
⚠️ Toán tử ! (null-forgiving) chỉ tắt CẢNH BÁO, không kiểm tra runtime. Nếu giá trị thực sự null, bạn vẫn dính NullReferenceException. Chỉ dùng khi bạn chắc chắn 100% (vd sau khi đã validate). Lạm dụng ! làm vô hiệu hoá toàn bộ lợi ích của NRT.

7. Records — Kiểu dữ liệu bất biến

record (C# 9+) là class/struct được sinh sẵn value-equality, ToString(), và with-expression. Lý tưởng cho DTO, value object, message.

// Positional record — gọn nhất, sinh tự động constructor + properties (init)
public record Person(string FirstName, string LastName);

// Tương đương record với thân class — khi cần thêm logic
public record Money
{
    public decimal Amount { get; init; }   // init = chỉ gán lúc khởi tạo
    public string Currency { get; init; } = "VND";
}

Value equality & with-expression

var p1 = new Person("An", "Nguyễn");
var p2 = new Person("An", "Nguyễn");

Console.WriteLine(p1 == p2);   // True — record so sánh theo GIÁ TRỊ
// (class thường sẽ là False vì so sánh theo tham chiếu)

// with-expression — tạo bản sao và thay đổi vài thuộc tính (immutable update)
var p3 = p1 with { LastName = "Trần" };
Console.WriteLine(p3);  // Person { FirstName = An, LastName = Trần }
Console.WriteLine(p1.LastName); // "Nguyễn" — p1 KHÔNG đổi (bất biến)
Tiêu chírecordclass
So sánh bằngValue equality (theo property)Reference equality
Bất biến (immutable)Khuyến khích (init)Mặc định mutable
with-expressionCóKhông
ToString() đẹpSinh sẵnPhải tự viết
Dùng tốt choDTO, value object, message, configEntity có hành vi, service, state mutable
💡 Khi nào dùng record? Khi đối tượng được định nghĩa bởi dữ liệu chứ không phải danh tính — hai địa chỉ giống hệt nhau thì coi là bằng nhau. DTO API, event, value object (Money, DateRange) là ứng viên hoàn hảo. Entity EF Core có Id định danh thì nên giữ class.

8. Pattern Matching — Đối sánh mẫu

Pattern matching biến switch và is thành công cụ cực mạnh: kiểm tra kiểu, bóc thuộc tính, so sánh điều kiện — tất cả trong một biểu thức gọn.

Type pattern & property pattern

// Type pattern — kiểm tra kiểu + gán biến cùng lúc
object obj = "Xin chào";
if (obj is string s && s.Length > 3)
    Console.WriteLine(s.ToUpper());

// Property pattern — đối sánh theo thuộc tính của object
decimal CalcShipping(Order order) => order switch
{
    { Total: > 1_000_000 }            => 0,        // freeship đơn lớn
    { Total: > 500_000, IsVip: true } => 0,        // VIP đơn vừa
    { Country: "VN" }               => 30_000,
    _                                => 100_000    // còn lại
};

Relational & logical patterns (and / or / not)

string Classify(int temp) => temp switch
{
    < 0             => "Đóng băng",
    >= 0 and < 20  => "Lạnh",         // kết hợp 'and'
    >= 20 and < 30 => "Dễ chịu",
    >= 35           => "Nóng",
    _              => "Ấm"
};

// 'or' và 'not'
bool isWeekend = day is DayOfWeek.Saturday or DayOfWeek.Sunday;
bool hasValue = obj is not null;

List patterns (C# 11+)

int[] data = [1, 2, 3, 4, 5];

var desc = data switch
{
    []                  => "Rỗng",
    [var only]          => $"Một phần tử: {only}",
    [var first, .., var last] => $"Đầu {first}, cuối {last}", // .. = bỏ qua giữa
    _                   => "Khác"
};
Console.WriteLine(desc);  // "Đầu 1, cuối 5"
Switch on patterns giúp loại bỏ chuỗi if-else dài. Compiler còn cảnh báo nếu bạn quên xử lý trường hợp (non-exhaustive). Kết hợp với record + property pattern là cách viết business rule rất sạch và dễ test.

9. String Handling — Xử lý chuỗi hiệu quả

string trong C# là immutable — mỗi thao tác "sửa" thực ra tạo chuỗi mới. Hiểu điều này để tránh bug hiệu năng khi nối chuỗi.

Interpolation & raw string literals

string name = "An";
int age = 25;

// String interpolation — $ — rõ ràng, ưu tiên dùng
string msg = $"Tên: {name}, Tuổi: {age}, Năm sau: {age + 1}";

// Định dạng trong interpolation
decimal price = 1234567.5m;
string formatted = $"Giá: {price:N0} ₫";   // "Giá: 1,234,568 ₫"

// Raw string literal (C# 11) — không cần escape, giữ nguyên xuống dòng
string json = """
    {
        "name": "An",
        "active": true
    }
    """;   // dấu " không cần escape, lề trái tự cắt theo """ đóng

StringBuilder vs nối chuỗi trong vòng lặp

// ❌ SAI — mỗi += tạo 1 chuỗi mới → O(n²), tốn bộ nhớ khủng khiếp
string result = "";
for (int i = 0; i < 10_000; i++)
    result += i + ", ";    // tạo 10.000 chuỗi trung gian!

// ✅ ĐÚNG — StringBuilder dùng buffer nội bộ, O(n)
var sb = new StringBuilder();
for (int i = 0; i < 10_000; i++)
    sb.Append(i).Append(", ");
string output = sb.ToString();

// Nối ÍT chuỗi cố định thì interpolation/+ vẫn ổn — không cần StringBuilder
string full = firstName + " " + lastName;

Span<char> — xử lý chuỗi không cấp phát

// Span<char>/ReadOnlySpan<char> — "lát cắt" chuỗi KHÔNG tạo bản sao
string path = "/api/v1/users/42";
ReadOnlySpan<char> span = path;
ReadOnlySpan<char> lastSegment = span[(span.LastIndexOf('/') + 1)..];
Console.WriteLine(lastSegment.ToString());  // "42" — không allocate chuỗi con

// Span đặc biệt mạnh trong parsing/hot-path để giảm áp lực GC
if (int.TryParse(lastSegment, out var id))
    Console.WriteLine(id);  // 42 — parse trực tiếp từ span

Các method & cách dùng phổ biến

string raw = "  Hello, World  ";

raw.Trim();                       // "Hello, World"
raw.Trim().ToUpper();             // "HELLO, WORLD"
raw.Contains("World");          // True
raw.Replace("World", "C#");     // "  Hello, C#  "
"a,b,c".Split(',');            // ["a", "b", "c"]
string.Join("-", ["a", "b", "c"]); // "a-b-c"
string.IsNullOrWhiteSpace(raw);  // False — kiểm tra null/rỗng/toàn space

// string.Format — kiểu cũ, vẫn dùng cho template/localization
string.Format("Xin chào {0}, bạn có {1} tin nhắn", name, 5);
💡 So sánh chuỗi: dùng string.Equals(a, b, StringComparison.OrdinalIgnoreCase) để so sánh không phân biệt hoa thường một cách rõ ràng và nhanh. Tránh a.ToLower() == b.ToLower() (tạo 2 chuỗi mới mỗi lần so sánh).
