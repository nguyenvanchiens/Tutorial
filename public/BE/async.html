Async/Await & Threading trong .NET

Hiểu sâu cơ chế async/await ("there is no thread"), Task, ConfigureAwait, CancellationToken, parallel vs concurrent, deadlock, Task.WhenAll, IAsyncEnumerable và những lỗi chết người như async void, .Result/.Wait. Chính xác cho .NET 8/9.

1. Tại sao cần async?

Async giúp giải phóng thread trong lúc chờ I/O (DB, HTTP, file). Trên web server, thread là tài nguyên đắt đỏ — mỗi request blocking giữ 1 thread khỏi thread pool. Async cho phép xử lý hàng nghìn request đồng thời với ít thread.

🚫 Đồng bộ (blocking)

Thread "đứng yên" chờ DB trả về. 1000 request đồng thời = 1000 thread bị giữ. Thread pool cạn → request mới phải xếp hàng → throughput sụp.

✅ Bất đồng bộ (async)

Thread được trả lại pool trong lúc chờ I/O. Khi I/O xong, một thread bất kỳ pick up tiếp. 1000 request có thể chỉ cần vài chục thread.

Async ≠ nhanh hơn: async không làm 1 request chạy nhanh hơn. Nó làm tăng throughput (scalability) — server chịu được nhiều request đồng thời hơn với cùng số thread.

2. "There is no thread"

Câu nói nổi tiếng của Stephen Cleary. Khi bạn await một I/O operation thực sự (đọc file, gọi HTTP, query DB), không có thread nào đang chờ.

public async Task<string> DownloadAsync(string url)
{
    using var client = new HttpClient();
    // Tại điểm await này: thread KHÔNG đứng chờ.
    // Nó được trả lại thread pool. OS/network card lo việc nhận dữ liệu.
    var result = await client.GetStringAsync(url);
    // Khi dữ liệu về, runtime lấy 1 thread để chạy tiếp dòng dưới.
    return result.ToUpper();
}

Cơ chế: compiler biến method async thành một state machine. Mỗi await là 1 "checkpoint". Khi gặp await chưa hoàn thành, method return về caller (trả lại thread). Khi awaitable hoàn tất, continuation được lên lịch chạy phần còn lại.

Phân biệt: Task.Run(() => CpuWork()) THỰC SỰ dùng 1 thread (CPU-bound). Còn await httpClient.GetAsync() (I/O-bound) thì không. Đừng dùng Task.Run để "async hoá" I/O — đó là lãng phí thread.

// ValueTask: tránh allocate Task khi cache hit (đường nóng)
public ValueTask<User> GetUserAsync(int id)
{
    if (_cache.TryGetValue(id, out var user))
        return new ValueTask<User>(user);   // đồng bộ, 0 allocation

    return new ValueTask<User>(LoadFromDbAsync(id)); // bất đồng bộ
}
⚠️ ValueTask có ràng buộc: KHÔNG await/lấy kết quả 2 lần, KHÔNG dùng đồng thời, KHÔNG dùng .Result. Nếu cần lưu hoặc await nhiều lần → gọi .AsTask(). Mặc định cứ dùng Task; chỉ tối ưu sang ValueTask khi đo được là hot path.

4. ConfigureAwait(false)

Mặc định, await sẽ cố quay lại SynchronizationContext ban đầu (UI thread trong WPF/WinForms, hoặc request context trong ASP.NET cũ). ConfigureAwait(false) bỏ qua điều đó.

// Trong THƯ VIỆN (library) — luôn dùng ConfigureAwait(false)
public async Task<int> ComputeAsync()
{
    var data = await _http.GetStringAsync(_url).ConfigureAwait(false);
    return Parse(data);
}
Bối cảnhKhuyến nghị
Thư viện dùng chung (NuGet, shared lib)Luôn ConfigureAwait(false)
ASP.NET Core (controller, service)Không cần — ASP.NET Core không có SynchronizationContext
WPF / WinForms / MAUI (code cần update UI)Không dùng (cần quay lại UI thread)
WPF/WinForms code không đụng UINên ConfigureAwait(false) để tránh deadlock
ASP.NET Core đặc biệt: Từ ASP.NET Core không còn SynchronizationContext, nên ConfigureAwait(false) ở tầng app gần như vô hại/vô tác dụng. Nhưng trong thư viện tái sử dụng (có thể bị gọi từ WPF) thì vẫn nên giữ thói quen này.

5. CancellationToken

Cho phép hủy thao tác đang chạy: user đóng tab, request timeout, app shutdown. Truyền token xuyên suốt chuỗi async.

// Controller nhận token tự động từ ASP.NET Core (request aborted)
[HttpGet]
public async Task<IActionResult> Search(string q, CancellationToken ct)
{
    var results = await _service.SearchAsync(q, ct);
    return Ok(results);
}

public async Task<List<Item>> SearchAsync(string q, CancellationToken ct)
{
    // Truyền token xuống EF Core / HttpClient
    return await _db.Items
        .Where(i => i.Name.Contains(q))
        .ToListAsync(ct);
}
// Tạo timeout + kết hợp nhiều token
using var timeoutCts = new CancellationTokenSource(TimeSpan.FromSeconds(5));
using var linked = CancellationTokenSource.CreateLinkedTokenSource(
    requestAborted, timeoutCts.Token);

await DoWorkAsync(linked.Token);

// Trong vòng lặp dài, chủ động kiểm tra
while (hasMore)
{
    ct.ThrowIfCancellationRequested();
    await ProcessBatchAsync(ct);
}
💡 Nguyên tắc: mọi public async method nên nhận CancellationToken (đặt cuối, default = default) và truyền nó xuống tận đáy. Hủy là một phần của API hợp đồng async tốt.

6. Parallel vs Concurrent

Concurrency (đồng thời)

Nhiều việc tiến triển xen kẽ nhau, không nhất thiết cùng lúc. Async/await là concurrency cho I/O. Có thể chạy trên 1 thread.

Parallelism (song song)

Nhiều việc chạy thực sự cùng lúc trên nhiều CPU core. Dành cho CPU-bound: Parallel.For, PLINQ, Task.Run nhiều task.

// CONCURRENT I/O: gọi 3 API cùng lúc, await tất cả
var t1 = _http.GetStringAsync("/a");
var t2 = _http.GetStringAsync("/b");
var t3 = _http.GetStringAsync("/c");
var all = await Task.WhenAll(t1, t2, t3); // 3 việc I/O đồng thời

// PARALLEL CPU-bound: tính toán nặng trên nhiều core
Parallel.For(0, items.Length, i => Process(items[i]));

// .NET 6+: Parallel.ForEachAsync — song song có giới hạn + async
await Parallel.ForEachAsync(urls,
    new ParallelOptions { MaxDegreeOfParallelism = 4 },
    async (url, ct) => await DownloadAsync(url, ct));
⚠️ Đừng Task.Run cho I/O: Task.Run(() => httpClient.GetAsync(url)) chiếm 1 thread pool thread chỉ để đẩy việc async — vô nghĩa. Gọi thẳng await httpClient.GetAsync(url).

7. Task.WhenAll / WhenAny / WhenEach

// WhenAll: chờ tất cả xong, gom kết quả. Throughput cao.
var userIds = new[] { 1, 2, 3 };
var tasks = userIds.Select(id => _api.GetUserAsync(id));
User[] users = await Task.WhenAll(tasks);

// WhenAny: lấy task hoàn thành đầu tiên (vd: dùng cho timeout)
var work = LongOperationAsync();
var timeout = Task.Delay(TimeSpan.FromSeconds(5));
if (await Task.WhenAny(work, timeout) == timeout)
    throw new TimeoutException();
await work; // observe exception nếu có

// .NET 9: Task.WhenEach — xử lý kết quả ngay khi từng task xong
await foreach (var finished in Task.WhenEach(tasks))
{
    Console.WriteLine(await finished); // xử lý theo thứ tự hoàn thành
}
⚠️ Exception trong WhenAll: nếu nhiều task ném exception, await Task.WhenAll(...) chỉ ném ra exception đầu tiên. Để xem hết, kiểm tra task.Exception hoặc bọc trong AggregateException. Đừng quên await để không nuốt lỗi (unobserved task exception).

8. IAsyncEnumerable<T> — streaming async

Trả về dữ liệu dạng luồng (stream) không cần load hết vào memory. Lý tưởng cho query lớn, đọc file lớn, server-sent events.

// Producer: yield từng phần tử khi sẵn sàng
public async IAsyncEnumerable<Order> StreamOrdersAsync(
    [EnumeratorCancellation] CancellationToken ct = default)
{
    await foreach (var order in _db.Orders.AsAsyncEnumerable().WithCancellation(ct))
    {
        yield return Enrich(order);
    }
}

// Consumer
await foreach (var order in StreamOrdersAsync(ct))
{
    Process(order); // xử lý ngay, không chờ load hết
}
💡 ASP.NET Core: trả thẳng IAsyncEnumerable<T> từ action — framework sẽ stream JSON cho client (không buffer toàn bộ). Tốt cho dataset lớn. Nhớ truyền token qua [EnumeratorCancellation].

9. Deadlock — kẻ giết người thầm lặng

Deadlock kinh điển: blocking trên async code có SynchronizationContext (WPF, WinForms, ASP.NET cũ). Thread giữ context bị block chờ task, task lại cần context đó để chạy tiếp → kẹt vĩnh viễn.

// ❌ Code này DEADLOCK trong WPF/WinForms/ASP.NET (Framework)
public void Button_Click(...)
{
    // .Result block UI thread, nhưng continuation của GetDataAsync
    // cần đúng UI thread đó để chạy tiếp → kẹt nhau.
    var data = GetDataAsync().Result;   // 💀 DEADLOCK
}

// ✅ Sửa: async all the way
public async void Button_Click(...) // async void chỉ chấp nhận cho event handler
{
    var data = await GetDataAsync();
}
Vì sao ASP.NET Core ít deadlock hơn? Vì không có SynchronizationContext. Nhưng .Result/.Wait() vẫn nguy hiểm: gây thread pool starvation (block thread pool thread → pool phải spawn thread mới chậm chạp → throughput sụp dưới tải cao). Đừng block.

10. Những lỗi phổ biến (Do / Don't)

❌ async void (trừ event handler)

public async void ProcessAsync() { await ...; } // không await được

Caller không thể await, không bắt được exception (crash process), không test được. Dùng async Task.

❌ .Result / .Wait() / GetAwaiter().GetResult()

var x = GetAsync().Result;        // deadlock + starvation
GetAsync().Wait();

Gây deadlock (có context) hoặc thread pool starvation. Luôn await.

❌ async over sync giả tạo

public Task<int> GetAsync() => Task.Run(() => HeavySyncCpu());

Bọc CPU-sync trong Task.Run để "giả async" trên web — chỉ đẩy việc sang thread khác, không tăng scalability. Nếu thật sự CPU-bound, hãy giữ sync hoặc offload có chủ đích.

❌ Quên await (fire-and-forget vô tình)

_service.SaveAsync(data); // thiếu await → exception bị nuốt, có thể chưa chạy xong

Compiler cảnh báo CS4014. Nếu cố ý fire-and-forget, dùng pattern an toàn (Channel + background service) và log exception.

✅ Async all the way

public async Task<IActionResult> Get() => Ok(await _svc.GetAsync());

Từ endpoint xuống tới DB đều async, truyền CancellationToken xuyên suốt.

✅ Chạy đồng thời khi độc lập

var (a, b) = (GetAAsync(), GetBAsync());
await Task.WhenAll(a, b); // nhanh hơn await tuần tự

Các call I/O độc lập nên chạy song song với WhenAll thay vì await lần lượt.

🎯 Checklist Async

  • ✅ Mọi I/O đều await, không .Result / .Wait() ở bất kỳ đâu
  • ✅ Không có async void ngoài event handler
  • ✅ Public async method nhận và truyền CancellationToken
  • ✅ Library code dùng ConfigureAwait(false)
  • ✅ Call I/O độc lập chạy song song bằng Task.WhenAll
  • ✅ Không bọc I/O trong Task.Run
  • ✅ Dataset lớn dùng IAsyncEnumerable để streaming
  • ✅ Luôn await (hoặc observe) Task để không nuốt exception
  • ✅ Method async đặt hậu tố Async theo convention
