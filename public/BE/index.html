CLR & Memory Management

Hiểu máy chạy code của bạn như thế nào

🎯 Tại sao quan trọng?

Nếu không hiểu CLR, bạn không thể giải thích tại sao code chạy chậm, tại sao memory leak, tại sao GC pause. Đây là thứ phân biệt senior và junior.

💎 PHẢI BIẾT
  • Stack vs Heap — Value type nằm ở stack, Reference type nằm ở heap. Boxing/Unboxing xảy ra khi chuyển đổi.
  • Garbage Collector — Gen 0, Gen 1, Gen 2. GC chỉ thu hồi heap. Large Object Heap (LOH) cho object > 85KB.
  • IDisposable & using — Unmanaged resources (file handle, DB connection) KHÔNG được GC quản lý. Phải dispose thủ công.
  • JIT Compilation — IL code → Native code tại runtime. Tiered Compilation trong .NET Core.
  • Value type vs Reference type — struct vs class. Khi nào dùng struct? Khi data nhỏ, immutable, ngắn hạn.
📝 NÊN BIẾT
  • Span<T> và Memory<T> để tránh allocation
  • ArrayPool<T> để reuse arrays
  • Weak References cho caching
  • Finalizer và GC.SuppressFinalize
  • dotMemory / dotTrace profiling
💻 Ví dụ thực tế
// ❌ SAI - Memory leak vì không dispose
public void ProcessFile()
{
    var stream = new FileStream("data.txt", FileMode.Open);
    // Quên dispose → file bị lock, memory leak
}

// ✅ ĐÚNG - Dùng using statement
public void ProcessFile()
{
    using var stream = new FileStream("data.txt", FileMode.Open);
    // Tự động dispose khi ra khỏi scope
}

// ❌ SAI - Boxing gây allocation không cần thiết
object boxed = 42; // int → object = BOXING (heap allocation)
int unboxed = (int)boxed; // UNBOXING

// ✅ ĐÚNG - Dùng generic để tránh boxing
List<int> numbers = new(); // Không boxing

Async/Await & Threading

Bản chất của lập trình bất đồng bộ

🎯 Tại sao quan trọng?

90% code backend là I/O bound (DB query, HTTP call, file read). Không hiểu async = không tối ưu được throughput = server chịu tải kém.

💎 PHẢI BIẾT
  • async/await KHÔNG tạo thread mới — Nó giải phóng thread hiện tại khi chờ I/O. Thread pool thread được trả lại.
  • Task vs Thread — Task là abstraction cao hơn, chạy trên ThreadPool. Thread là OS-level.
  • ConfigureAwait(false) — Trong library code, dùng để tránh deadlock và không cần capture SynchronizationContext.
  • Deadlock pattern — .Result hoặc .Wait() trên async method = DEADLOCK trong ASP.NET (trước .NET Core).
  • CancellationToken — Cơ chế cooperative cancellation. LUÔN truyền CancellationToken cho async methods.
  • ValueTask vs Task — ValueTask tránh allocation khi result đã sẵn sàng (cache hit, sync completion).
📝 NÊN BIẾT
  • SemaphoreSlim cho async locking
  • Channel<T> cho producer-consumer pattern
  • Parallel.ForEachAsync trong .NET 6+
  • IAsyncEnumerable<T> cho streaming data
  • Task.WhenAll vs Task.WhenAny
💻 Ví dụ thực tế
// ❌ SAI - Block async code = Deadlock risk
public string GetData()
{
    return GetDataAsync().Result; // DEADLOCK!
}

// ✅ ĐÚNG - Async all the way
public async Task<string> GetDataAsync(CancellationToken ct = default)
{
    using var client = new HttpClient();
    return await client.GetStringAsync("https://api.example.com", ct);
}

// ❌ SAI - Tạo task không cần thiết cho I/O
public async Task SaveAsync(Data data)
{
    await Task.Run(() => _db.SaveChanges()); // Lãng phí thread!
}

// ✅ ĐÚNG - Dùng async I/O native
public async Task SaveAsync(Data data, CancellationToken ct)
{
    await _db.SaveChangesAsync(ct); // Thread được giải phóng khi chờ DB
}

// Chạy song song nhiều tasks
var tasks = users.Select(u => SendEmailAsync(u, ct));
await Task.WhenAll(tasks);

SOLID Principles & Design Patterns

Kiến trúc code bền vững

🎯 Tại sao quan trọng?

Là Lead, bạn review code hàng ngày. SOLID giúp bạn nhận ra code smell ngay lập tức và hướng dẫn team viết code dễ maintain, dễ test.

💎 PHẢI BIẾT
  • S - Single Responsibility — Mỗi class chỉ có MỘT lý do để thay đổi. UserService không nên gửi email.
  • O - Open/Closed — Mở cho mở rộng, đóng cho sửa đổi. Dùng abstraction thay vì if/else chain.
  • L - Liskov Substitution — Subclass phải thay thế được parent class mà không break logic.
  • I - Interface Segregation — Interface nhỏ, cụ thể tốt hơn interface lớn, chung chung.
  • D - Dependency Inversion — Depend on abstractions, not concretions. High-level module không phụ thuộc low-level.
📝 PATTERNS THƯỜNG DÙNG
  • Repository Pattern — Abstraction cho data access
  • Strategy Pattern — Thay đổi algorithm runtime
  • Factory Pattern — Tạo object phức tạp
  • Mediator (MediatR) — Decouple request/handler
  • Decorator Pattern — Thêm behavior mà không sửa code
  • Observer Pattern — Event-driven communication
💻 Ví dụ thực tế
// ❌ Vi phạm SRP - Class làm quá nhiều việc
public class UserService
{
    public void Register(User user) { /* save to DB */ }
    public void SendWelcomeEmail(User user) { /* gửi email */ }
    public void GenerateReport(User user) { /* tạo report */ }
}

// ✅ Tách responsibility
public class UserService
{
    private readonly IEmailService _email;
    private readonly IUserRepository _repo;

    public async Task RegisterAsync(User user, CancellationToken ct)
    {
        await _repo.AddAsync(user, ct);
        await _email.SendWelcomeAsync(user, ct);
    }
}

// ❌ Vi phạm OCP - Thêm loại mới phải sửa code cũ
public decimal CalculateDiscount(string customerType)
{
    if (customerType == "Gold") return 0.2m;
    if (customerType == "Silver") return 0.1m;
    // Thêm loại mới = sửa method này
}

// ✅ Open/Closed - Mở rộng bằng abstraction
public interface IDiscountStrategy
{
    decimal Calculate(Order order);
}
public class GoldDiscount : IDiscountStrategy
{
    public decimal Calculate(Order order) => order.Total * 0.2m;
}

SQL & Database Internals

Hiểu database không chỉ là viết query

🎯 Tại sao quan trọng?

80% performance issues đến từ database. Biết viết query thì ai cũng biết, nhưng hiểu TẠI SAO query chậm, INDEX hoạt động thế nào mới là bản chất.

💎 PHẢI BIẾT
  • Index B-Tree — Index là cây cân bằng. Clustered index = thứ tự vật lý của data. Non-clustered = con trỏ đến data.
  • Execution Plan — PHẢI biết đọc execution plan. Table Scan (xấu) vs Index Seek (tốt).
  • Transaction & Isolation Level — READ COMMITTED (default), READ UNCOMMITTED, REPEATABLE READ, SERIALIZABLE. Hiểu dirty read, phantom read.
  • N+1 Query Problem — Lỗi phổ biến nhất khi dùng ORM. 1 query lấy list + N query lấy detail.
  • Normalization vs Denormalization — Khi nào chuẩn hóa (giảm redundancy), khi nào phi chuẩn hóa (tăng read performance).
  • Deadlock — 2 transactions lock lẫn nhau. Cách phòng tránh: lock ordering, keep transactions short.
📝 NÊN BIẾT
  • Covering Index — Include columns trong index
  • Partitioning — Chia table lớn thành phần nhỏ
  • Query Store — Monitor query performance
  • Temporal Tables — Lưu lịch sử thay đổi
  • Row-level Security
💻 Ví dụ thực tế
-- ❌ SAI - Full table scan, không dùng index
SELECT * FROM Orders WHERE YEAR(CreatedDate) = 2024;
-- Hàm YEAR() khiến SQL không dùng được index trên CreatedDate

-- ✅ ĐÚNG - Sargable query, dùng được index
SELECT * FROM Orders
WHERE CreatedDate >= '2024-01-01' AND CreatedDate < '2025-01-01';

-- ❌ SAI - SELECT * lấy hết columns
SELECT * FROM Users WHERE Status = 'Active';

-- ✅ ĐÚNG - Chỉ lấy columns cần thiết
SELECT Id, Name, Email FROM Users WHERE Status = 'Active';

-- Covering Index - tránh Key Lookup
CREATE NONCLUSTERED INDEX IX_Users_Status
ON Users(Status) INCLUDE (Id, Name, Email);

-- Kiểm tra Execution Plan
SET STATISTICS IO ON;
SET STATISTICS TIME ON;

HTTP Protocol & REST API Design

Ngôn ngữ giao tiếp của web

🎯 Tại sao quan trọng?

Mọi API bạn viết đều dựa trên HTTP. Hiểu HTTP sâu giúp bạn debug nhanh, design API đúng chuẩn, và xử lý edge cases.

💎 PHẢI BIẾT
  • HTTP Methods semantics — GET (idempotent, safe), POST (create), PUT (replace), PATCH (partial update), DELETE.
  • Status Codes — 200 OK, 201 Created, 204 No Content, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 409 Conflict, 429 Too Many Requests, 500 Internal Server Error.
  • Idempotency — GET, PUT, DELETE là idempotent. POST không phải. Tại sao quan trọng? Retry logic, distributed systems.
  • Content Negotiation — Accept header, Content-Type header. JSON vs XML.
  • CORS — Cross-Origin Resource Sharing. Preflight request (OPTIONS). Cách cấu hình trong ASP.NET Core.
  • REST Maturity Model — Level 0 (RPC) → Level 1 (Resources) → Level 2 (HTTP Verbs) → Level 3 (HATEOAS).
📝 NÊN BIẾT
  • HTTP/2 multiplexing & server push
  • ETag & Conditional requests (304)
  • Rate Limiting strategies
  • API Versioning (URL vs Header)
  • Problem Details (RFC 7807)
💻 Ví dụ thực tế
// ✅ RESTful API Design trong ASP.NET Core
[ApiController]
[Route("api/[controller]")]
public class OrdersController : ControllerBase
{
    // GET api/orders — Lấy danh sách
    [HttpGet]
    public async Task<ActionResult<PagedResult<OrderDto>>>
        GetOrders([FromQuery] OrderQuery query, CancellationToken ct)
    {
        var result = await _service.GetPagedAsync(query, ct);
        return Ok(result);
    }

    // GET api/orders/123 — Lấy chi tiết
    [HttpGet("{id}")]
    [ProducesResponseType(200)]
    [ProducesResponseType(404)]
    public async Task<ActionResult<OrderDto>> GetOrder(int id, CancellationToken ct)
    {
        var order = await _service.GetByIdAsync(id, ct);
        return order is null ? NotFound() : Ok(order);
    }

    // POST api/orders — Tạo mới, return 201 + Location header
    [HttpPost]
    [ProducesResponseType(201)]
    public async Task<ActionResult<OrderDto>> CreateOrder(
        CreateOrderRequest request, CancellationToken ct)
    {
        var order = await _service.CreateAsync(request, ct);
        return CreatedAtAction(nameof(GetOrder), new { id = order.Id }, order);
    }
}

Dependency Injection & IoC

Xương sống của ASP.NET Core

🎯 Tại sao quan trọng?

DI là trái tim của ASP.NET Core. Mọi thứ đều đi qua DI container. Hiểu sai lifetime = memory leak, hiểu sai scope = bug khó debug.

💎 PHẢI BIẾT
  • 3 Lifetimes — Transient (mỗi lần inject = instance mới), Scoped (1 per request), Singleton (1 per app).
  • Captive Dependency — Singleton chứa Scoped = BUG! Scoped service bị giữ mãi trong singleton.
  • Constructor Injection — Cách chính để inject. Không dùng property injection, không dùng Service Locator.
  • IServiceProvider — Khi nào cần resolve manually (factory pattern, background service).
  • Options Pattern — IOptions<T>, IOptionsSnapshot<T>, IOptionsMonitor<T> cho configuration.
💻 Ví dụ thực tế
// Registration
builder.Services.AddScoped<IOrderService, OrderService>();
builder.Services.AddSingleton<ICacheService, RedisCacheService>();
builder.Services.AddTransient<IEmailService, SmtpEmailService>();

// ❌ SAI - Captive Dependency (Singleton giữ Scoped)
public class CacheService // Singleton
{
    private readonly IOrderService _orderService; // Scoped bị capture!
    public CacheService(IOrderService orderService)
    {
        _orderService = orderService; // Bug: same instance mãi mãi
    }
}

// ✅ ĐÚNG - Dùng IServiceScopeFactory
public class CacheService
{
    private readonly IServiceScopeFactory _scopeFactory;
    public CacheService(IServiceScopeFactory scopeFactory)
    {
        _scopeFactory = scopeFactory;
    }

    public async Task RefreshAsync(CancellationToken ct)
    {
        using var scope = _scopeFactory.CreateScope();
        var orderService = scope.ServiceProvider
            .GetRequiredService<IOrderService>();
        // Scoped service được tạo và dispose đúng cách
    }
}

// Options Pattern
builder.Services.Configure<SmtpSettings>(
    builder.Configuration.GetSection("Smtp"));

public class EmailService
{
    private readonly SmtpSettings _settings;
    public EmailService(IOptions<SmtpSettings> options)
    {
        _settings = options.Value;
    }
}

Security Fundamentals

Bảo mật không phải optional

🎯 Tại sao quan trọng?

Là Lead, bạn chịu trách nhiệm về security của cả team. Một lỗ hổng SQL Injection có thể phá hủy cả công ty.

💎 PHẢI BIẾT
  • Authentication vs Authorization — AuthN = "Bạn là ai?" (JWT, Cookie). AuthZ = "Bạn được làm gì?" (Roles, Claims, Policies).
  • JWT Token — Header.Payload.Signature. Access Token (ngắn hạn) + Refresh Token (dài hạn). KHÔNG lưu sensitive data trong payload (nó chỉ Base64).
  • OWASP Top 10 — SQL Injection, XSS, CSRF, Broken Auth, Security Misconfiguration, etc.
  • Password Hashing — KHÔNG dùng MD5/SHA. Dùng BCrypt/Argon2/PBKDF2 với salt.
  • HTTPS & TLS — Tại sao bắt buộc. HSTS header. Certificate pinning.
  • Input Validation — LUÔN validate ở server. Client validation chỉ là UX.
💻 Ví dụ thực tế
// ❌ SAI - SQL Injection
var query = $"SELECT * FROM Users WHERE Name = '{userName}'";
// Input: ' OR 1=1 -- → Lấy được TẤT CẢ users!

// ✅ ĐÚNG - Parameterized query
var query = "SELECT * FROM Users WHERE Name = @name";
command.Parameters.AddWithValue("@name", userName);

// JWT Authentication trong ASP.NET Core
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidateLifetime = true,
            ValidateIssuerSigningKey = true,
            ClockSkew = TimeSpan.Zero // Không cho phép token hết hạn
        };
    });

// Authorization Policy
builder.Services.AddAuthorization(options =>
{
    options.AddPolicy("AdminOnly", policy =>
        policy.RequireRole("Admin")
              .RequireClaim("department", "IT"));
});

[Authorize(Policy = "AdminOnly")]
[HttpDelete("{id}")]
public async Task<IActionResult> DeleteUser(int id, CancellationToken ct)
{
    // Chỉ Admin trong IT department mới xóa được
}

Testing Strategy

Code không có test = code tạm thời

🎯 Tại sao quan trọng?

Là Lead, bạn phải đảm bảo team viết test. Không có test = mỗi lần deploy là một canh bạc. Test tốt = team tự tin refactor và ship nhanh.

💎 PHẢI BIẾT
  • Test Pyramid — Unit Test (nhiều, nhanh) → Integration Test (vừa) → E2E Test (ít, chậm).
  • AAA Pattern — Arrange (setup) → Act (thực hiện) → Assert (kiểm tra). Mỗi test chỉ test MỘT behavior.
  • Mocking — Mock external dependencies (DB, API), KHÔNG mock internal logic. Dùng Moq hoặc NSubstitute.
  • Integration Test — WebApplicationFactory trong ASP.NET Core. Test real HTTP pipeline.
  • Test Naming — MethodName_Scenario_ExpectedResult. Ví dụ: CreateOrder_WhenOutOfStock_ThrowsException.
💻 Ví dụ thực tế
// Unit Test với xUnit + Moq
public class OrderServiceTests
{
    private readonly Mock<IOrderRepository> _repoMock = new();
    private readonly Mock<IEmailService> _emailMock = new();
    private readonly OrderService _sut; // System Under Test

    public OrderServiceTests()
    {
        _sut = new OrderService(_repoMock.Object, _emailMock.Object);
    }

    [Fact]
    public async Task CreateOrder_WhenValid_SavesAndSendsEmail()
    {
        // Arrange
        var request = new CreateOrderRequest { ProductId = 1, Quantity = 2 };
        _repoMock.Setup(r => r.AddAsync(It.IsAny<Order>(), default))
                 .ReturnsAsync(new Order { Id = 1 });

        // Act
        var result = await _sut.CreateOrderAsync(request);

        // Assert
        Assert.NotNull(result);
        _repoMock.Verify(r => r.AddAsync(It.IsAny<Order>(), default), Times.Once);
        _emailMock.Verify(e => e.SendOrderConfirmationAsync(
            It.IsAny<Order>(), default), Times.Once);
    }

    [Fact]
    public async Task CreateOrder_WhenOutOfStock_ThrowsException()
    {
        // Arrange
        _repoMock.Setup(r => r.CheckStockAsync(1, default))
                 .ReturnsAsync(0);

        // Act & Assert
        await Assert.ThrowsAsync<OutOfStockException>(
            () => _sut.CreateOrderAsync(new() { ProductId = 1 }));
    }
}

// Integration Test
public class OrdersApiTests : IClassFixture<WebApplicationFactory<Program>>
{
    private readonly HttpClient _client;

    public OrdersApiTests(WebApplicationFactory<Program> factory)
    {
        _client = factory.CreateClient();
    }

    [Fact]
    public async Task GetOrders_ReturnsOk()
    {
        var response = await _client.GetAsync("/api/orders");
        response.EnsureSuccessStatusCode();
    }
}

Code Review

Review không phải để bắt lỗi, mà để nâng level cả team.

  • Tập trung vào logic & design, không nitpick style
  • Giải thích TẠI SAO, không chỉ nói SAI
  • Dùng PR template & checklist
  • Automate được gì thì automate (linter, formatter)

Architecture Decision

Chọn đúng architecture cho đúng bài toán.

  • Monolith → Modular Monolith → Microservices
  • ADR (Architecture Decision Records)
  • Trade-off analysis (CAP theorem)
  • KISS > YAGNI > DRY (thứ tự ưu tiên)
👥

Team Management

Giỏi code mà không lead được người thì vẫn thất bại.

  • Tạo coding standards & conventions
  • Mentoring & knowledge sharing

Technical Estimation

  • Planning Poker với team
  • Track velocity để cải thiện estimation

Incident Management

  • Runbook & Playbook cho common issues
  • Blameless post-mortem
  • Monitoring & Alerting setup
  • On-call rotation
