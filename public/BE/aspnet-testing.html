Unit & Integration Test cho ASP.NET Core

Chuyên sâu về testing web app ASP.NET Core: Controllers, Minimal API, Middleware, Filters, Auth, EF Core, SignalR, Background Service. Full stack từ unit test nhanh đến integration test với container thật.

1. Testing Strategy cho ASP.NET Core

Web app có nhiều "layer" mỗi layer test khác nhau. Hiểu đúng chiến lược trước khi chọn tool.

🧩 Unit Test

Test 1 class cô lập, mock mọi dependency. Nhanh <10ms.

  • Business service
  • Validator
  • Mapper
  • Helper/extension

🔗 Integration Test

Test qua HTTP pipeline thật (DI, middleware, routing). Chậm hơn ~100-500ms.

  • WebApplicationFactory<T>
  • Endpoint contract test
  • Auth flow end-to-end
  • DB test với Testcontainers

🌐 E2E Test

Test toàn stack từ client thật (Playwright, Selenium).

  • User journey
  • Browser interaction
  • Chỉ cho flow quan trọng
Tỉ lệ khuyến nghị: 70% unit · 25% integration · 5% E2E. Unit nhanh bắt bug logic. Integration verify routing/DI/middleware/auth thật sự work. E2E test happy path quan trọng.

📐 Cấu trúc solution chuẩn

MyApp.sln
├── src/
│   ├── MyApp.Api/                // ASP.NET Core project
│   ├── MyApp.Core/               // business logic, không ref ASP.NET
│   └── MyApp.Infrastructure/     // EF Core, external clients
└── tests/
    ├── MyApp.UnitTests/          // test Core + Infrastructure thuần
    └── MyApp.IntegrationTests/   // test qua WebApplicationFactory

3. Unit Test Controller

Controller nên mỏng. Test nhanh bằng cách khởi tạo controller với mocked dependencies — không cần HTTP pipeline.

// UsersController.cs
[ApiController, Route("api/users")]
public class UsersController : ControllerBase
{
    private readonly IUserService _service;
    public UsersController(IUserService service) => _service = service;

    [HttpGet("{id:int}")]
    public async Task<IActionResult> Get(int id)
    {
        var user = await _service.GetAsync(id);
        return user is null ? NotFound() : Ok(user);
    }

    [HttpPost]
    public async Task<IActionResult> Create(CreateUserDto dto)
    {
        if (!ModelState.IsValid) return BadRequest(ModelState);
        var user = await _service.CreateAsync(dto);
        return CreatedAtAction(nameof(Get), new { id = user.Id }, user);
    }
}
// UsersControllerTests.cs
public class UsersControllerTests
{
    private readonly Mock<IUserService> _service = new();
    private readonly UsersController _sut;

    public UsersControllerTests() => _sut = new(_service.Object);

    [Fact]
    public async Task Get_ExistingId_ReturnsOkWithUser()
    {
        var user = new UserDto(5, "Chien");
        _service.Setup(s => s.GetAsync(5)).ReturnsAsync(user);

        var result = await _sut.Get(5);

        result.Should().BeOfType<OkObjectResult>()
              .Which.Value.Should().Be(user);
    }

    [Fact]
    public async Task Get_NotFound_Returns404()
    {
        _service.Setup(s => s.GetAsync(999)).ReturnsAsync((UserDto)null!);

        var result = await _sut.Get(999);

        result.Should().BeOfType<NotFoundResult>();
    }

    [Fact]
    public async Task Create_InvalidModelState_ReturnsBadRequest()
    {
        _sut.ModelState.AddModelError("Name", "Required");

        var result = await _sut.Create(new CreateUserDto());

        result.Should().BeOfType<BadRequestObjectResult>();
    }
}
💡 Mẹo test IActionResult: dùng BeOfType<T>().Which để xuyên qua type và assert property. Trường hợp cần HTTP status code cụ thể → check .Which.StatusCode.Should().Be(201).

4. Integration Test với WebApplicationFactory

Khởi tạo app thật trong memory, test qua HttpClient. Bao phủ: routing, DI, middleware, model binding, auth filter.

// UsersApiTests.cs
public class UsersApiTests : IClassFixture<WebApplicationFactory<Program>>
{
    private readonly HttpClient _client;

    public UsersApiTests(WebApplicationFactory<Program> factory)
    {
        _client = factory.CreateClient();
    }

    [Fact]
    public async Task GET_Users_ReturnsList()
    {
        var response = await _client.GetAsync("/api/users");

        response.StatusCode.Should().Be(HttpStatusCode.OK);
        var users = await response.Content.ReadFromJsonAsync<List<UserDto>>();
        users.Should().NotBeNull();
    }

    [Fact]
    public async Task POST_User_InvalidPayload_Returns400()
    {
        var payload = new { Name = "" };  // required violation

        var response = await _client.PostAsJsonAsync("/api/users", payload);

        response.StatusCode.Should().Be(HttpStatusCode.BadRequest);
    }
}

Customize factory — thay service thật bằng mock/fake

public class CustomWebAppFactory : WebApplicationFactory<Program>
{
    protected override void ConfigureWebHost(IWebHostBuilder builder)
    {
        builder.UseEnvironment("Testing");

        builder.ConfigureTestServices(services =>
        {
            // Replace real email sender with a fake

                opt.UseInMemoryDatabase("test-db-" + Guid.NewGuid()));
        });
    }
}

// Dùng

    ...
}

6. Test Authentication & Authorization

Endpoint có [Authorize] → test phải giả lập user login. 3 cách:

Cách A: Test auth handler

// Test/TestAuthHandler.cs
public class TestAuthHandler : AuthenticationHandler<AuthenticationSchemeOptions>
{
    public TestAuthHandler(
        IOptionsMonitor<AuthenticationSchemeOptions> o,
        ILoggerFactory logger,
        UrlEncoder encoder)
        : base(o, logger, encoder) { }

    protected override Task<AuthenticateResult> HandleAuthenticateAsync()
    {
        var claims = new[] {
            new Claim(ClaimTypes.Name, "TestUser"),
            new Claim(ClaimTypes.NameIdentifier, "1"),
            new Claim(ClaimTypes.Role, "Admin")
        };
        var identity = new ClaimsIdentity(claims, "Test");
        var principal = new ClaimsPrincipal(identity);
        var ticket = new AuthenticationTicket(principal, "Test");
        return Task.FromResult(AuthenticateResult.Success(ticket));
    }
}

// Factory đăng ký handler
builder.ConfigureTestServices(services =>
{
    services.AddAuthentication("Test")
        .AddScheme<AuthenticationSchemeOptions, TestAuthHandler>("Test", _ => { });
});

// Trong test
_client.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Test");

7. Test Middleware

Test middleware bằng RequestDelegate giả + DefaultHttpContext. Không cần WebApplicationFactory.

// Middleware thực tế
public class RequestIdMiddleware
{
    private readonly RequestDelegate _next;
    public RequestIdMiddleware(RequestDelegate next) => _next = next;

    public async Task InvokeAsync(HttpContext ctx)
    {
        var id = Guid.NewGuid().ToString("N")[..8];
        ctx.Response.Headers["X-Request-Id"] = id;
        await _next(ctx);
    }
}
[Fact]
public async Task Middleware_AddsRequestId()
{
    // Arrange
    RequestDelegate next = _ => Task.CompletedTask;
    var middleware = new RequestIdMiddleware(next);
    var ctx = new DefaultHttpContext();

    // Act
    await middleware.InvokeAsync(ctx);

    // Assert
    ctx.Response.Headers["X-Request-Id"].ToString()
        .Should().NotBeNullOrEmpty()
        .And.HaveLength(8);
}

[Fact]
public async Task Middleware_CallsNext()
{
    var nextCalled = false;
    RequestDelegate next = _ => { nextCalled = true; return Task.CompletedTask; };

    await new RequestIdMiddleware(next).InvokeAsync(new DefaultHttpContext());

    nextCalled.Should().BeTrue();
}

8. Test Action Filters & Exception Filters

// ValidateGuidFilter.cs
public class ValidateGuidFilter : IActionFilter
{
    public void OnActionExecuting(ActionExecutingContext ctx)
    {
        if (ctx.ActionArguments.TryGetValue("id", out var val)
            && val is string s
            && !Guid.TryParse(s, out _))
        {
            ctx.Result = new BadRequestObjectResult("Invalid GUID");
        }
    }

    public void OnActionExecuted(ActionExecutedContext ctx) { }
}
[Fact]
public void Filter_InvalidGuid_SetsBadRequest()
{
    var filter = new ValidateGuidFilter();
    var ctx = new ActionExecutingContext(
        new ActionContext {
            HttpContext = new DefaultHttpContext(),
            RouteData = new(),
            ActionDescriptor = new()
        },
        new List<IFilterMetadata>(),
        new Dictionary<string, object?> { ["id"] = "not-a-guid" },
        controller: new object());

    filter.OnActionExecuting(ctx);

    ctx.Result.Should().BeOfType<BadRequestObjectResult>()
        .Which.Value.Should().Be("Invalid GUID");
}
Exception filter: test tương tự — gọi OnException(ExceptionContext) với exception giả. Assert ctx.Result + ctx.ExceptionHandled.

9. Test với EF Core — 3 cách

In-Memory Provider

  • Nhanh nhất
  • Không giống SQL thật
  • Không transaction, không unique constraint
  • Dùng: test logic service
services.AddDbContext<AppDbContext>(o =>
    o.UseInMemoryDatabase(Guid.NewGuid().ToString()));

SQLite In-Memory

  • SQL thật nhưng trong RAM
  • Support transaction, constraint
  • Không giống Postgres/SQL Server 100%
  • Dùng: test query phức tạp
var conn = new SqliteConnection("DataSource=:memory:");
conn.Open();
services.AddDbContext<AppDbContext>(o => o.UseSqlite(conn));

Testcontainers (khuyên)

  • Postgres/SQL Server thật trong Docker
  • Giống 100% prod environment
  • Chậm hơn (~3-5s start)
  • Dùng: integration test quan trọng

Ví dụ Testcontainers + Postgres

10. Test Background Service (IHostedService)

// OrderWorker.cs
public class OrderWorker : BackgroundService
{
    private readonly IOrderQueue _queue;
    private readonly IOrderProcessor _processor;

    public OrderWorker(IOrderQueue q, IOrderProcessor p)
        => (_queue, _processor) = (q, p);

    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            var order = await _queue.DequeueAsync(ct);
            await _processor.ProcessAsync(order);
        }
    }
}
[Fact]
public async Task Worker_ProcessesDequeuedOrder()
{
    // Arrange
    var queue = new Mock<IOrderQueue>();
    var processor = new Mock<IOrderProcessor>();
    var order = new Order(1);

    queue.SetupSequence(q => q.DequeueAsync(It.IsAny<CancellationToken>()))
         .ReturnsAsync(order)
         .ThrowsAsync(new OperationCanceledException());  // vòng 2 huỷ

    var worker = new OrderWorker(queue.Object, processor.Object);
    using var cts = new CancellationTokenSource();

    // Act
    await worker.StartAsync(cts.Token);
    await Task.Delay(50);  // cho worker loop 1 vòng
    await worker.StopAsync(cts.Token);

    // Assert
    processor.Verify(p => p.ProcessAsync(order), Times.Once);
}

13. Respawn — Reset DB giữa test

Chạy 100 integration test trên DB chung → state lẫn nhau → test fail ngẫu nhiên. Respawn truncate toàn bộ table nhanh chóng.

using Respawn;
using Respawn.Graph;

public class DbFixture : IAsyncLifetime
{
    public Respawner Respawner { get; private set; } = null!;
    public string ConnectionString { get; private set; } = null!;

    public async Task InitializeAsync()
    {
        // Tạo Postgres container, migrate schema
        ConnectionString = "Host=localhost;Database=test;Username=test;Password=test";
        Respawner = await Respawner.CreateAsync(ConnectionString,
            new RespawnerOptions
            {
                DbAdapter = DbAdapter.Postgres,
                TablesToIgnore = [new Table("__EFMigrationsHistory")],
            });
    }

    public Task DisposeAsync() => Task.CompletedTask;
}

// Trong test
[Fact]
public async Task SomeTest()
{
    await _fixture.Respawner.ResetAsync(_fixture.ConnectionString);
    // DB sạch — chạy test
}
Hiệu năng: Respawner.ResetAsync() chạy vài millisecond vs drop+recreate mất vài giây. Cho phép dùng chung container cho cả test suite.

16. Common Pitfalls cho ASP.NET Core testing

❌ Quên expose Program class

Minimal API mặc định Program là internal. WebApplicationFactory fail với "Program class must be public".

Fix: public partial class Program { } ở cuối Program.cs.

❌ Share factory giữa test không cần thiết

Mỗi test thay đổi DB state → test khác đọc state cũ → flaky.

Fix: dùng IClassFixture chỉ khi test read-only, hoặc reset DB với Respawn giữa test.

❌ Test với appsettings.json production

Test chạy với connection string prod → data bẩn / lỗi kết nối.

Fix: override environment sang "Testing" + tạo appsettings.Testing.json.

❌ Không dispose HttpClient

Tạo nhiều WebApplicationFactory không dispose → process hog port, memory leak.

Fix: IClassFixture hoặc IAsyncLifetime + implement IDisposable.

❌ Assert text content thay vì structure

response.Content.ReadAsString() == "{\"id\":1}" fail khi JSON format đổi.

Fix: ReadFromJsonAsync<T>() rồi assert object properties.

❌ Test auth với password thật

Hardcode "admin123" trong test → ai xem source cũng biết.

Fix: dùng TestAuthHandler giả lập identity, không cần login thật.

🎯 Checklist pre-commit

  • ✅ Unit test cho mỗi business service
  • ✅ Integration test cho mỗi endpoint chính (GET/POST/PUT/DELETE)
  • ✅ Auth flow có test (401, 403, success)
  • ✅ Validation rules có test (happy + edge case)
  • ✅ DB migration an toàn — test Up/Down trên Testcontainers
  • ✅ Code coverage >70% cho business layer
  • ✅ Không có .Result / .Wait() — luôn async/await
  • ✅ Test chạy <30s cả suite (unit) / <2 phút (integration)
  • ✅ CI xanh trước khi merge
  • ✅ Không hardcode secret — dùng appsettings.Testing.json + env var
