Security Deep-Dive cho .NET

OWASP Top 10 (2021) với mitigation cụ thể trên ASP.NET Core, các flow OAuth2/OIDC, hashing mật khẩu đúng cách, quản lý secret với Key Vault, HTTPS/TLS, CORS, security headers và input validation. Bảo mật là chiều sâu phòng thủ, không phải một checkbox.

1. OWASP Top 10 — mitigation trên .NET

Danh sách 2021 (bản chính thức hiện hành tại 2026). Mỗi mục kèm cách phòng cụ thể trong ASP.NET Core.

A01

Broken Access Control

User truy cập tài nguyên không thuộc quyền (IDOR: đổi /orders/123 thành /orders/124).

Fix: authorize ở server theo resource ownership, không tin client. Dùng [Authorize] + policy/resource-based authorization. Deny-by-default.

A02

Cryptographic Failures

Truyền/lưu dữ liệu nhạy cảm không mã hoá, dùng thuật toán yếu (MD5, SHA1, DES).

Fix: HTTPS bắt buộc (HSTS), mã hoá at-rest, hash mật khẩu bằng PBKDF2/bcrypt/Argon2, dùng System.Security.Cryptography hiện đại (AES-GCM).

A03

Injection (SQL, NoSQL, Command)

Input chưa kiểm soát trộn vào query/command.

Fix: parameterized query / EF Core (LINQ tự tham số hoá). KHÔNG nối chuỗi SQL. Với raw SQL dùng FromSqlInterpolated.

A04

Insecure Design

Thiếu thiết kế an toàn từ đầu (không threat modeling, không rate limit, business logic flaw).

Fix: threat modeling sớm, rate limiting, validate business rule ở domain, secure-by-design.

A05

Security Misconfiguration

Default credential, để chế độ dev/verbose error ở prod, header lộ thông tin, CORS mở toang.

Fix: tắt UseDeveloperExceptionPage ở prod, ẩn Server header, CORS allowlist, cấu hình tối thiểu cần thiết.

A06

Vulnerable & Outdated Components

Dùng package/runtime có CVE đã biết.

Fix: dotnet list package --vulnerable, Dependabot, cập nhật định kỳ, dùng .NET LTS được support.

A07

Identification & Authentication Failures

Mật khẩu yếu, không khoá brute-force, session không hết hạn, không MFA.

Fix: ASP.NET Core Identity (lockout, password policy), MFA, JWT/cookie có expiry hợp lý, chống credential stuffing.

A08

Software & Data Integrity Failures

Deserialize dữ liệu không tin cậy, CI/CD không ký, cập nhật không kiểm tra toàn vẹn.

Fix: không dùng BinaryFormatter (đã bỏ trong .NET 9+), ký artifact, kiểm tra checksum, deserialize an toàn với System.Text.Json.

A09

Security Logging & Monitoring Failures

Không log sự kiện bảo mật, không alert, không phát hiện được tấn công.

Fix: log auth fail/access denied/thay đổi quyền (KHÔNG log secret/PII), structured logging + SIEM + alert.

A10

Server-Side Request Forgery (SSRF)

Server bị lừa gọi tới URL nội bộ (metadata cloud, localhost) do nhận URL từ user.

Fix: allowlist domain/IP đích, chặn IP nội bộ (169.254.x, 10.x, localhost), không follow redirect tuỳ tiện.

2. Injection & Input Validation — code

❌ SQL Injection

// NGUY HIỂM — nối chuỗi
var sql = $"SELECT * FROM Users WHERE Name = '{name}'";
_db.Users.FromSqlRaw(sql);  // name = "' OR '1'='1"

✅ Parameterized

// LINQ — EF tự tham số hoá
_db.Users.Where(u => u.Name == name);

// Raw SQL an toàn — interpolated thành tham số
_db.Users.FromSqlInterpolated(
    $"SELECT * FROM Users WHERE Name = {name}");
💡 Validate input ở biên (model binding) + escape ở output: dùng FluentValidation/DataAnnotations cho input; Razor tự HTML-encode output (chống XSS). XSS reflected/stored xảy ra khi bạn render dữ liệu user mà bỏ encode — tránh @Html.Raw với data không tin cậy.

3. Hashing mật khẩu

KHÔNG bao giờ lưu mật khẩu plaintext hay hash nhanh (MD5/SHA256). Dùng hàm chậm có salt: PBKDF2, bcrypt, hoặc Argon2id (khuyến nghị hiện đại).

// Đơn giản nhất: dùng ASP.NET Core Identity PasswordHasher (PBKDF2, có salt + iteration)
var hasher = new PasswordHasher<User>();

// Đăng ký
user.PasswordHash = hasher.HashPassword(user, plainPassword);

// Đăng nhập — so sánh constant-time, hỗ trợ rehash khi tăng iteration
var result = hasher.VerifyHashedPassword(user, user.PasswordHash, plainPassword);
if (result == PasswordVerificationResult.Failed)
    return Unauthorized();
if (result == PasswordVerificationResult.SuccessRehashNeeded)
    user.PasswordHash = hasher.HashPassword(user, plainPassword);  // nâng cấp ngầm

Salt

Chuỗi ngẫu nhiên duy nhất mỗi user, chống rainbow table. PasswordHasher tự sinh và nhúng salt.

Work factor

Iteration cao → brute-force chậm. Tăng theo phần cứng theo thời gian (rehash).

Argon2id

Memory-hard, chống GPU/ASIC tốt nhất hiện nay. Dùng qua thư viện (Konscious.Security.Cryptography) cho hệ mới.

Tuyệt đối tránh: MD5/SHA1/SHA256 trần cho mật khẩu (quá nhanh), salt cố định toàn hệ thống, "encrypt" mật khẩu (phải hash, không encrypt vì không cần giải ngược), so sánh hash bằng == không constant-time.

4. OAuth2 & OpenID Connect

OAuth2 = ủy quyền (authorization — cấp quyền truy cập tài nguyên). OIDC = lớp xác thực (authentication — "bạn là ai") xây trên OAuth2, thêm ID Token (JWT).

Authorization Code + PKCE (flow chuẩn 2026)

// ASP.NET Core — xác thực qua OIDC provider (Entra ID/Auth0/Keycloak/IdentityServer)
builder.Services.AddAuthentication(OpenIdConnectDefaults.AuthenticationScheme)
    .AddCookie()
    .AddOpenIdConnect(o =>
    {
        o.Authority = "https://login.example.com";
        o.ClientId = builder.Configuration["Oidc:ClientId"];
        o.ClientSecret = builder.Configuration["Oidc:ClientSecret"];  // từ Key Vault
        o.ResponseType = "code";                  // Authorization Code
        o.UsePkce = true;                         // PKCE bật
        o.SaveTokens = true;
        o.Scope.Add("openid");
        o.Scope.Add("profile");
        o.GetClaimsFromUserInfoEndpoint = true;
    });
// Bảo vệ API bằng JWT Bearer — luôn validate issuer/audience/signature
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(o =>
    {
        o.Authority = "https://login.example.com";
        o.TokenValidationParameters = new()
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidAudience = "api://my-api",
            ValidateLifetime = true,
            ValidateIssuerSigningKey = true     // chống token giả
        };
    });
⚠️ Token storage ở SPA: Đừng lưu access token trong localStorage (XSS đọc được). Pattern an toàn 2026 là BFF (Backend-for-Frontend): token giữ ở server, browser chỉ có cookie HttpOnly + SameSite.

5. Secrets Management

Secret KHÔNG bao giờ hardcode hay commit. Tách theo môi trường, dùng kho secret chuyên dụng ở prod.

  1. Dev local: User Secrets (không vào git) 
    dotnet user-secrets init
dotnet user-secrets set "Oidc:ClientSecret" "dev-secret"
  2. Production: Azure Key Vault (hoặc AWS Secrets Manager / HashiCorp Vault) + Managed Identity (không cần lưu credential để truy cập Key Vault) 
    // Program.cs — nạp config từ Key Vault qua Managed Identity
builder.Configuration.AddAzureKeyVault(
    new Uri("https://my-vault.vault.azure.net/"),
    new DefaultAzureCredential());  // dùng MI, không secret

// Đọc như config bình thường
var conn = builder.Configuration["Db:ConnectionString"];
Secret đã commit coi như đã lộ. Dù xoá commit sau, nó vẫn trong git history. Phải revoke + rotate ngay. Dùng git-secrets/GitHub secret scanning + pre-commit hook để chặn từ đầu.

6. HTTPS / TLS, CORS & Security Headers

// Program.cs — cấu hình bảo mật transport & headers
var app = builder.Build();

if (!app.Environment.IsDevelopment())
{
    app.UseHsts();           // ép HTTPS ở browser (Strict-Transport-Security)
}
app.UseHttpsRedirection();   // HTTP → HTTPS

// Security headers
app.Use(async (ctx, next) =>
{
    ctx.Response.Headers["X-Content-Type-Options"] = "nosniff";
    ctx.Response.Headers["X-Frame-Options"] = "DENY";            // chống clickjacking
    ctx.Response.Headers["Referrer-Policy"] = "no-referrer";
    ctx.Response.Headers["Content-Security-Policy"] =
        "default-src 'self'; object-src 'none'; frame-ancestors 'none'";  // chống XSS
    await next();
});

CORS — allowlist, không wildcard

builder.Services.AddCors(o => o.AddPolicy("app", p =>
    p.WithOrigins("https://app.example.com")   // origin cụ thể, KHÔNG AllowAnyOrigin
     .WithMethods("GET", "POST")
     .AllowCredentials()));                     // credentials + wildcard là cấm

app.UseCors("app");
❌ AllowAnyOrigin().AllowCredentials() bị runtime chặn — và đúng vậy: nó cho phép mọi site đọc response có cookie của user. Luôn allowlist origin tin cậy.
TLS 2026: Dùng TLS 1.2/1.3, tắt TLS 1.0/1.1 và SSLv3. Cert tự động qua Let's Encrypt/ACME hoặc managed cert của cloud. Bật OCSP stapling. CORS không phải cơ chế bảo mật — nó chỉ là chính sách của browser; bảo vệ thật vẫn là authn/authz phía server.

7. Defense in Depth

Không có lớp phòng thủ nào hoàn hảo. Xếp nhiều lớp để một lớp thủng không sập toàn bộ.

Mạng

  • WAF, DDoS protection
  • Private subnet cho DB
  • Least-privilege network

Ứng dụng

  • Authn + authz mọi endpoint
  • Validate input, encode output
  • Rate limit, anti-CSRF

Dữ liệu

  • Mã hoá at-rest & in-transit
  • Hash mật khẩu
  • Least-privilege DB account

🎯 Checklist Security

  • ✅ Authorization theo resource ownership, deny-by-default (A01)
  • ✅ HTTPS + HSTS; mã hoá dữ liệu nhạy cảm at-rest (A02)
  • ✅ Parameterized query / EF Core; không nối chuỗi SQL (A03)
  • ✅ Hash mật khẩu PBKDF2/bcrypt/Argon2id + salt; không lưu plaintext
  • ✅ OAuth2 Authorization Code + PKCE; validate issuer/audience/signature JWT
  • ✅ Token SPA qua BFF/cookie HttpOnly, không localStorage
  • ✅ Secret ở User Secrets (dev) / Key Vault + Managed Identity (prod)
  • ✅ Security headers: CSP, X-Content-Type-Options, X-Frame-Options, HSTS
  • ✅ CORS allowlist origin cụ thể, không wildcard + credentials
  • ✅ dotnet list package --vulnerable + cập nhật định kỳ (A06)
  • ✅ Log sự kiện bảo mật (không log secret/PII) + alert (A09)
  • ✅ Tắt verbose error ở prod; threat modeling từ thiết kế
