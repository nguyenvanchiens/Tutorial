Xây dựng ASP.NET Core Web API đầu tiên

Từ dotnet new webapi đến một REST API CRUD hoàn chỉnh trên .NET 8/9: minimal hosting model, Controller, routing, model binding, DTO, kết quả trả về chuẩn RFC, Swagger/OpenAPI. Mọi thứ bạn cần để viết endpoint đầu tiên một cách chuyên nghiệp.

1. Web API là gì & tại sao chọn ASP.NET Core

Web API là một dịch vụ HTTP trả về dữ liệu (thường là JSON) thay vì HTML. Client có thể là SPA (React/Angular), mobile app, dịch vụ khác, hoặc Postman.

🌐 REST trên HTTP

Tài nguyên (resource) được định danh bằng URL, thao tác bằng HTTP verb.

  • GET — đọc
  • POST — tạo mới
  • PUT/PATCH — cập nhật
  • DELETE — xoá

⚡ Hiệu năng cao

Kestrel server là một trong những web server nhanh nhất hiện nay. Hỗ trợ AOT, HTTP/3.

  • Cross-platform (Win/Linux/macOS)
  • Async/await native
  • DI tích hợp sẵn

🧰 Hệ sinh thái

EF Core, Identity, SignalR, gRPC, Authentication/Authorization — tất cả first-party.

  • OpenAPI/Swagger
  • Middleware pipeline
  • Config & Logging chuẩn
Phiên bản 2026: .NET 8 là LTS (hỗ trợ tới 11/2026), .NET 9 là STS (mới hơn, có cải tiến OpenAPI built-in). Bài này dùng cú pháp chung cho cả hai; chỗ nào khác biệt sẽ ghi chú rõ.

3. Program.cs — Minimal Hosting Model (.NET 8/9)

Từ .NET 6, không còn Startup.cs. Mọi cấu hình gói gọn trong Program.cs với top-level statements. Có 2 nửa rõ ràng: builder (đăng ký service) và app (cấu hình pipeline).

// Program.cs — phiên bản dùng Controller
var builder = WebApplication.CreateBuilder(args);

// === 1. ĐĂNG KÝ SERVICE (DI container) — trước khi Build() ===
builder.Services.AddControllers();          // bật MVC Controller
builder.Services.AddEndpointsApiExplorer(); // metadata cho OpenAPI
builder.Services.AddSwaggerGen();           // sinh Swagger doc

// Đăng ký service riêng của app (sẽ dùng ở phần CRUD)
builder.Services.AddSingleton<IProductService, InMemoryProductService>();

var app = builder.Build();

// === 2. CẤU HÌNH MIDDLEWARE PIPELINE — thứ tự QUAN TRỌNG ===
if (app.Environment.IsDevelopment())
{
    app.UseSwagger();      // expose /swagger/v1/swagger.json
    app.UseSwaggerUI();    // giao diện web /swagger
}

app.UseHttpsRedirection(); // ép HTTP -> HTTPS
app.UseAuthorization();    // kiểm tra quyền (nếu có [Authorize])

app.MapControllers();      // map route tới các Controller

app.Run();                 // chạy app (blocking)

// Cuối file: expose Program cho integration test (tùy chọn)
public partial class Program { }
⚠️ Thứ tự middleware là sống còn: request đi từ trên xuống, response đi ngược lại. UseAuthentication() phải đứng TRƯỚC UseAuthorization(). MapControllers() nên ở gần cuối. Sai thứ tự = auth không chạy hoặc CORS không áp dụng.

Vòng đời một request

Client  ──HTTP──>  Kestrel  ──>  Middleware pipeline
                                   │  HttpsRedirection
                                   │  Routing
                                   │  Authentication / Authorization
                                   ▼
                              Endpoint (Controller action)
                                   │  Model binding + validation
                                   │  Logic + gọi service
                                   ▼
                              IActionResult  ──>  JSON response  ──>  Client

4. Controller — [ApiController] & ControllerBase

Controller nhóm các endpoint liên quan. Kế thừa ControllerBase (KHÔNG phải Controller — cái đó dành cho MVC trả View HTML). Attribute [ApiController] bật một loạt hành vi tiện lợi cho API.

// Controllers/PingController.cs
using Microsoft.AspNetCore.Mvc;

[ApiController]
[Route("api/[controller]")]   // [controller] = "ping" (bỏ hậu tố Controller)
public class PingController : ControllerBase
{
    [HttpGet]
    public IActionResult Get() => Ok(new { status = "alive", time = DateTime.UtcNow });
}
Hành vi của [ApiController]Ý nghĩa
Auto 400 khi model invalidKhông cần tự kiểm tra ModelState.IsValid — tự trả ValidationProblemDetails
Binding source suy luậnTham số complex type tự bind từ body, simple type từ route/query
Bắt buộc attribute routingKhông dùng convention routing — phải khai báo [Route]/[HttpGet]
ProblemDetails cho lỗiLỗi trả về đúng chuẩn RFC 9457 (mã, type, title, detail)
Minimal API — lựa chọn thay thế: với API nhỏ, có thể bỏ Controller và map endpoint thẳng trong Program.cs: app.MapGet("/ping", () => Results.Ok("alive"));. Gọn cho microservice nhỏ, nhưng Controller dễ tổ chức hơn khi project lớn. Phần 9 sẽ minh hoạ Minimal API CRUD tương đương.

5. Routing & Attribute Routing

URL nào gọi tới action nào được quyết định bằng attribute đặt trên class/method. [Route] định nghĩa template, các [HttpVerb] định nghĩa method + segment con.

[ApiController]
[Route("api/products")]              // prefix cố định cho cả controller
public class ProductsController : ControllerBase
{
    [HttpGet]                          // GET  /api/products
    public IActionResult GetAll() => Ok();

    [HttpGet("{id:int}")]                // GET  /api/products/42  (id phải là int)
    public IActionResult GetById(int id) => Ok(id);

    [HttpGet("search")]                  // GET  /api/products/search?q=abc
    public IActionResult Search([FromQuery] string q) => Ok(q);

    [HttpPost]                         // POST /api/products
    public IActionResult Create() => Ok();

    [HttpPut("{id:int}")]                // PUT  /api/products/42
    public IActionResult Update(int id) => Ok();

    [HttpDelete("{id:int}")]             // DELETE /api/products/42
    public IActionResult Delete(int id) => Ok();
}

Route constraint thường gặp

ConstraintVí dụKhớp
:int{id:int}Số nguyên: /products/42
:guid{id:guid}GUID hợp lệ
:min(n) / :max(n){id:int:min(1)}int ≥ 1
:alpha{slug:alpha}Chỉ chữ cái
:length(n){code:length(6)}Chuỗi đúng 6 ký tự
? (optional){page:int?}Có thể không truyền
Route param vs Query param: dùng route cho thứ định danh tài nguyên (/products/42). Dùng query cho lọc/phân trang/sắp xếp (/products?page=2&sort=price). Đừng nhét filter vào route.

6. Model Binding & Validation

Model binding tự động ánh xạ dữ liệu HTTP (route, query, body, header, form) vào tham số method. Với [ApiComplexType] mặc định bind từ body, simple type bind từ route/query.

AttributeNguồn dữ liệuVí dụ
[FromRoute]Segment trong URL/products/42
[FromQuery]Query string?page=2
[FromBody]Body JSONPayload POST/PUT
[FromHeader]HTTP headerX-Tenant-Id: abc
[FromForm]multipart/form-dataUpload file, form HTML
[FromServices]DI containerInject service vào action
[HttpGet("{id:int}")]
public IActionResult GetOne(
    [FromRoute] int id,                 // từ URL
    [FromQuery] bool includeReviews,    // ?includeReviews=true
    [FromHeader(Name = "X-Tenant-Id")] string? tenant)
{
    return Ok(new { id, includeReviews, tenant });
}

[HttpPost]
public IActionResult Create([FromBody] CreateProductDto dto)
{
    // Nhờ [ApiController], nếu dto không hợp lệ -> tự trả 400 ở đây
    return Ok(dto);
}

Validation bằng Data Annotation

Gắn attribute lên property của DTO. [ApiController] tự kiểm tra và trả 400 với chi tiết lỗi — bạn không cần viết tay.

using System.ComponentModel.DataAnnotations;

public class CreateProductDto
{
    [Required, StringLength(120, MinimumLength = 2)]
    public string Name { get; set; } = string.Empty;

    [Range(0.01, 1_000_000)]
    public decimal Price { get; set; }

    [Required, MinLength(1)]
    public string Category { get; set; } = string.Empty;
}
// Khi gửi { "name": "", "price": -5 } -> tự động nhận response 400:
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
    "Name":  ["The Name field is required."],
    "Price": ["The field Price must be between 0.01 and 1000000."]
  }
}
Validation phức tạp? Data Annotation đủ cho rule đơn giản. Với rule liên-thuộc-tính hoặc cần gọi DB, dùng thư viện FluentValidation — tách rule ra class riêng, dễ test, dễ tái sử dụng.

7. DTO — Đừng phơi bày Entity

DTO (Data Transfer Object) là model riêng cho input/output của API, tách khỏi entity của database. Đây là một trong những thói quen quan trọng nhất của API chuyên nghiệp.

❌ Trả thẳng Entity

[HttpGet("{id:int}")]
public IActionResult Get(int id)
{
    Product p = _db.Find(id);
    return Ok(p); // lộ cả PasswordHash,
}                  // CostPrice, navigation...

Lộ field nhạy cảm, gắn chặt schema DB với hợp đồng API, dễ lỗi vòng lặp serialize (cyclic reference).

✅ Map sang DTO

[HttpGet("{id:int}")]
public IActionResult Get(int id)
{
    Product p = _db.Find(id);
    return Ok(new ProductDto(
        p.Id, p.Name, p.Price));
}

Chỉ expose đúng field cần thiết. API contract ổn định kể cả khi DB đổi. An toàn.

// Request DTO — dữ liệu client GỬI LÊN (không có Id, không có audit field)
public record CreateProductDto(string Name, decimal Price, string Category);

// Response DTO — dữ liệu API TRẢ VỀ (có Id, định dạng theo nhu cầu client)
public record ProductDto(int Id, string Name, decimal Price, string Category);

// Entity — model của DATABASE (có field nội bộ)
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public decimal Price { get; set; }
    public string Category { get; set; } = "";
    public decimal CostPrice { get; set; }   // KHÔNG bao giờ lộ ra ngoài
    public DateTime CreatedAt { get; set; }
}
💡 Mapping: với DTO nhỏ, map tay (như trên) là rõ ràng nhất và không tốn thư viện. Khi số lượng nhiều, cân nhắc Mapster (nhanh, source-generated) hoặc AutoMapper. Tránh lạm dụng auto-mapper cho logic phức tạp — nó che giấu lỗi.

8. Trả kết quả — IActionResult, ActionResult<T>, Results

ASP.NET Core có nhiều kiểu trả về. Hiểu rõ để vừa đúng HTTP status code, vừa rõ ràng cho Swagger sinh tài liệu.

Kiểu trả vềDùng khiƯu / Nhược
IActionResultAction có thể trả nhiều status khác nhauLinh hoạt; nhưng Swagger không biết kiểu body
ActionResult<T>Controller — vừa trả T vừa trả statusKhuyên dùng: vừa rõ kiểu, vừa linh hoạt
T (trực tiếp)Luôn trả 200 với objectGọn nhất nhưng không trả được 404/400
Results / TypedResultsMinimal APITypedResults rõ kiểu, tốt cho test & OpenAPI

Các helper method của ControllerBase

return Ok(dto);                        // 200 + body
return CreatedAtAction(nameof(GetById), new { id }, dto); // 201 + Location header
return NoContent();                    // 204 (PUT/DELETE thành công)
return NotFound();                     // 404
return BadRequest("thông điệp");       // 400
return Conflict();                     // 409 (trùng dữ liệu)
return Unauthorized();                 // 401
return Forbid();                       // 403
return Problem(detail: "Lỗi hệ thống", statusCode: 500); // ProblemDetails
// ActionResult<T> — kiểu trả về được khuyên dùng nhất
[HttpGet("{id:int}")]
public ActionResult<ProductDto> GetById(int id)
{
    var product = _service.Find(id);
    if (product is null)
        return NotFound();      // trả 404

    return product;             // trả 200 + body (implicit conversion)
}
ProblemDetails & RFC 9457: chuẩn mới (thay RFC 7807) định nghĩa format JSON cho lỗi: type, title, status, detail, instance. [ApiController] tự dùng format này. Bật toàn cục bằng builder.Services.AddProblemDetails(); để cả lỗi 500 cũng theo chuẩn — client xử lý lỗi đồng nhất.
⚠️ CreatedAtAction cần tên action tồn tại và có route khớp tham số. Nếu sai tên (hoặc dùng nameof sai), runtime ném InvalidOperationException khi sinh URL. Luôn dùng nameof(GetById) thay vì chuỗi hardcode.

9. Swagger / OpenAPI

OpenAPI mô tả API dưới dạng máy đọc được. Từ đó sinh tài liệu tương tác (Swagger UI / Scalar) và client SDK tự động.

Cách 1: Swashbuckle (.NET 8 — phổ biến nhất)

// Cài (template webapi của .NET 8 đã có sẵn)
dotnet add package Swashbuckle.AspNetCore
// Program.cs
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();   // /swagger
}

Cách 2: OpenAPI built-in (.NET 9 — mới)

.NET 9 có package first-party Microsoft.AspNetCore.OpenApi, sinh document mà không cần Swashbuckle. Tuy nhiên nó CHỈ sinh JSON document, không kèm UI — ghép với Scalar để có giao diện đẹp.

// .NET 9
dotnet add package Microsoft.AspNetCore.OpenApi
dotnet add package Scalar.AspNetCore
// Program.cs (.NET 9)
builder.Services.AddOpenApi();          // đăng ký generator built-in

if (app.Environment.IsDevelopment())
{
    app.MapOpenApi();                   // /openapi/v1.json
    app.MapScalarApiReference();        // /scalar/v1 — UI hiện đại
}
💡 Tài liệu đẹp hơn: thêm XML comment (///) cho action và bật <GenerateDocumentationFile>true</> trong .csproj — Swagger hiển thị mô tả. Dùng [ProducesResponseType(StatusCodes.Status404NotFound)] để khai báo các status code action có thể trả, giúp doc chính xác.

10.2 — Service (inject qua DI)

// Services/IProductService.cs
public interface IProductService
{
    IEnumerable<Product> GetAll();
    Product? GetById(int id);
    Product Add(Product product);
    bool Update(int id, Product updated);
    bool Delete(int id);
}

// Services/InMemoryProductService.cs — lưu trong List (thay bằng EF Core sau)
public class InMemoryProductService : IProductService
{
    private readonly List<Product> _items = new()
    {
        new() { Id = 1, Name = "Bàn phím cơ", Price = 990_000, Category = "Phụ kiện" },
        new() { Id = 2, Name = "Chuột không dây", Price = 450_000, Category = "Phụ kiện" },
    };
    private int _nextId = 3;

    public IEnumerable<Product> GetAll() => _items;

    public Product? GetById(int id) =>
        _items.FirstOrDefault(p => p.Id == id);

    public Product Add(Product product)
    {
        product.Id = _nextId++;
        _items.Add(product);
        return product;
    }

    public bool Update(int id, Product updated)
    {
        var existing = GetById(id);
        if (existing is null) return false;
        existing.Name = updated.Name;
        existing.Price = updated.Price;
        existing.Category = updated.Category;
        return true;
    }

    public bool Delete(int id)
    {
        var existing = GetById(id);
        if (existing is null) return false;
        _items.Remove(existing);
        return true;
    }
}
⚠️ In-memory chỉ để học. AddSingleton giữ data sống suốt vòng đời app nhưng MẤT khi restart và KHÔNG thread-safe nếu nhiều request ghi đồng thời. Production: thay service này bằng repository dùng EF Core (xem bài EF Core).

10.3 — Controller đầy đủ

// Controllers/ProductsController.cs
using Microsoft.AspNetCore.Mvc;

[ApiController]
[Route("api/products")]
[Produces("application/json")]
public class ProductsController : ControllerBase
{
    private readonly IProductService _service;

    // Constructor injection — DI tự cấp IProductService
    public ProductsController(IProductService service) => _service = service;

    // GET /api/products?category=Phụ kiện
    [HttpGet]
    [ProducesResponseType(StatusCodes.Status200OK)]
    public ActionResult<IEnumerable<ProductDto>> GetAll([FromQuery] string? category)
    {
        var items = _service.GetAll();
        if (!string.IsNullOrWhiteSpace(category))
            items = items.Where(p => p.Category == category);

        var result = items.Select(ToDto);
        return Ok(result);
    }

    // GET /api/products/42
    [HttpGet("{id:int}", Name = nameof(GetById))]
    [ProducesResponseType(StatusCodes.Status200OK)]
    [ProducesResponseType(StatusCodes.Status404NotFound)]
    public ActionResult<ProductDto> GetById(int id)
    {
        var product = _service.GetById(id);
        if (product is null)
            return NotFound();

        return Ok(ToDto(product));
    }

    // POST /api/products
    [HttpPost]
    [ProducesResponseType(StatusCodes.Status201Created)]
    [ProducesResponseType(StatusCodes.Status400BadRequest)]
    public ActionResult<ProductDto> Create([FromBody] CreateProductDto dto)
    {
        // [ApiController] đã tự validate dto -> 400 nếu sai
        var created = _service.Add(new Product
        {
            Name = dto.Name,
            Price = dto.Price,
            Category = dto.Category
        });

        // 201 + header Location trỏ tới resource mới tạo
        return CreatedAtAction(nameof(GetById),
            new { id = created.Id }, ToDto(created));
    }

    // PUT /api/products/42
    [HttpPut("{id:int}")]
    [ProducesResponseType(StatusCodes.Status204NoContent)]
    [ProducesResponseType(StatusCodes.Status404NotFound)]
    public IActionResult Update(int id, [FromBody] UpdateProductDto dto)
    {
        var ok = _service.Update(id, new Product
        {
            Name = dto.Name,
            Price = dto.Price,
            Category = dto.Category
        });

        return ok ? NoContent() : NotFound();
    }

    // DELETE /api/products/42
    [HttpDelete("{id:int}")]
    [ProducesResponseType(StatusCodes.Status204NoContent)]
    [ProducesResponseType(StatusCodes.Status404NotFound)]
    public IActionResult Delete(int id) =>
        _service.Delete(id) ? NoContent() : NotFound();

    // Map entity -> DTO (gom 1 chỗ)
    private static ProductDto ToDto(Product p) =>
        new(p.Id, p.Name, p.Price, p.Category);
}

10.4 — Cùng API viết bằng Minimal API

// Program.cs — tương đương, gọn cho microservice nhỏ
var group = app.MapGroup("/api/products");

group.MapGet("/", (IProductService svc) =>
    TypedResults.Ok(svc.GetAll().Select(p =>
        new ProductDto(p.Id, p.Name, p.Price, p.Category))));

group.MapGet("/{id:int}", (int id, IProductService svc) =>
{
    var p = svc.GetById(id);
    return p is null
        ? Results.NotFound()
        : Results.Ok(new ProductDto(p.Id, p.Name, p.Price, p.Category));
});

group.MapPost("/", (CreateProductDto dto, IProductService svc) =>
{
    var created = svc.Add(new Product { Name = dto.Name, Price = dto.Price, Category = dto.Category });
    return Results.Created($"/api/products/{created.Id}", created);
});

12. Quy ước & lỗi thường gặp

✅ Dùng đúng HTTP status

201 cho tạo mới (kèm Location), 204 cho update/delete thành công, 404 khi không thấy, 400 khi input sai. Đừng trả 200 cho mọi thứ.

❌ Nhồi logic vào Controller

Controller nên mỏng: bind input → gọi service → trả kết quả. Logic nghiệp vụ đặt ở service/domain để dễ test và tái sử dụng.

✅ Async cho I/O

Khi gọi DB/HTTP, dùng async Task<ActionResult<T>> + await. Tăng throughput, không block thread pool.

❌ Quên [ApiController]

Thiếu attribute này thì không có auto-400, không suy luận binding source — phải tự kiểm ModelState thủ công khắp nơi.

✅ Versioning sớm

Đặt prefix /api/v1/... ngay từ đầu. Khi cần đổi contract, thêm v2 mà không phá client cũ.

❌ Trả message lỗi lộ nội bộ

Đừng trả stack trace / chi tiết DB ra client production. Dùng ProblemDetails với thông điệp an toàn, log chi tiết ở server.

🎯 Checklist — Web API đầu tiên

  • ✅ Tạo project bằng dotnet new webapi --use-controllers và chạy được dotnet run
  • ✅ Hiểu 2 nửa của Program.cs: builder.Services (đăng ký) và app.Use... (pipeline)
  • ✅ Controller kế thừa ControllerBase + gắn [ApiController] và [Route]
  • ✅ Dùng attribute routing với constraint ({id:int}) thay vì route lỏng lẻo
  • ✅ Phân biệt route param (định danh) vs query param (lọc/phân trang)
  • ✅ Dùng [FromBody]/[FromQuery]/[FromRoute] đúng nguồn dữ liệu
  • ✅ Validation bằng Data Annotation — tận dụng auto-400 của [ApiController]
  • ✅ Tách DTO ra khỏi Entity — KHÔNG bao giờ trả thẳng entity DB
  • ✅ Trả đúng status: 200 / 201 (CreatedAtAction) / 204 / 400 / 404
  • ✅ Dùng ActionResult<T> để vừa rõ kiểu vừa linh hoạt status
  • ✅ Bật ProblemDetails (AddProblemDetails()) cho lỗi chuẩn RFC 9457
  • ✅ Bật Swagger/OpenAPI và test được toàn bộ CRUD trên UI
  • ✅ Inject service qua constructor (DI) — controller mỏng, logic ở service
