Tuỳ biến Claude Code

Viết slash command riêng, hooks tự động, skills tái sử dụng, gọi subagents. Biến Claude Code thành assistant đúng workflow của bạn.

1. Custom Slash Commands

Viết 1 file Markdown, gõ /tên-file để thực thi. Đơn giản nhưng cực mạnh.

Tạo command "test-changes"

# Tạo file
mkdir -p .claude/commands
touch .claude/commands/test-changes.md
# .claude/commands/test-changes.md
---
name: test-changes
description: Chạy test chỉ cho những file đã thay đổi trong branch
---

Do the following:
1. Run `git diff --name-only origin/main` to get changed files
2. For each .ts/.tsx file, find the matching test file
3. Run `npx vitest run <test-files>` with only those tests
4. Report pass/fail + list of untested changed files

Sau đó trong session: gõ /test-changes → Claude thực hiện đúng quy trình.

Command nhận argument

# .claude/commands/deploy-feature.md
---
name: deploy-feature
description: Deploy feature branch lên staging với tên tuỳ ý
argument-hint: "<branch-name>"
---

Deploy branch $ARGUMENTS to staging:
1. git checkout $ARGUMENTS
2. npm run build
3. Upload dist/ to staging bucket
4. Invalidate CDN cache
5. Report staging URL
# Dùng
/deploy-feature feature/new-auth

User-global vs Project command

Vị tríScopeƯu tiên
.claude/commands/*.md (project)Chỉ repo nàyCao
~/.claude/commands/*.md (user)Mọi projectThấp hơn
Namespace: tổ chức theo folder — .claude/commands/git/release.md → gõ /git:release.

Ví dụ command hay gặp

/fix-lint

---
name: fix-lint
---
Run npm run lint. Auto-fix what can be fixed.
For remaining errors, analyze and fix them.
Verify with npm run lint again.

/write-test

---
name: write-test
argument-hint: "<file-path>"
---
Read $ARGUMENTS and write unit tests:
- Use existing test framework (check package.json)
- Test happy path + 2 edge cases + error case
- Keep under 80 lines
- Place in same folder with .test. suffix

/changelog

---
name: changelog
---
Scan `git log` since last release tag.
Group by feat/fix/chore.
Write CHANGELOG.md entry in standard format.
Do NOT commit — let me review first.

/explain

---
name: explain
argument-hint: "<file-or-symbol>"
---
Read $ARGUMENTS. Explain in Vietnamese:
1. What it does (1-2 sentences)
2. Why it exists (design intent)
3. Key gotchas or non-obvious behavior
4. Where it's called from

2. Skills — "Biết làm gì khi gặp X"

Skill = hướng dẫn chi tiết cho một loại task. Claude tự invoke khi gặp tình huống phù hợp. Khác slash command ở chỗ: user không phải gõ lệnh.

Skill đơn giản

# .claude/skills/database-migration.md
---
name: database-migration
description: Viết Prisma migration an toàn — reversible,
  có rollback, test trên staging trước prod
when-to-use: Khi user yêu cầu đổi schema DB, thêm/xoá column,
  migrate data
---

Quy trình bắt buộc khi viết migration:

1. Tạo migration qua `prisma migrate dev --create-only`
2. Mở file .sql sinh ra, review từng lệnh
3. **Bắt buộc có rollback** — viết down migration
4. Nếu migration breaking (drop column, rename):
   - Chia 2 phase: add column mới → migrate data → drop cũ
   - Không được 1 deployment
5. Test trên local DB copy trước
6. Update schema.prisma để match
7. Commit với message: `db: <description>`

Ví dụ breaking migration tốt:
```sql
-- Phase 1 (deploy trước)
ALTER TABLE users ADD COLUMN email_verified BOOLEAN DEFAULT false;

-- Phase 2 (backfill, chạy sau deploy phase 1)
UPDATE users SET email_verified = (verified_at IS NOT NULL);

-- Phase 3 (deploy sau)
ALTER TABLE users DROP COLUMN verified_at;
```

Bất cứ khi nào user prompt có "add column", "migration", "đổi schema" → Claude tự nhớ và follow skill này.

Skill có công cụ

# .claude/skills/screenshot-bug/SKILL.md
---
name: screenshot-bug
description: Capture browser screenshot + console log khi debug UI
allowed-tools:
  - Bash(npx playwright*)
  - Read
  - Write
---

Khi user báo UI bug, làm:
1. Chạy `npx playwright screenshot <URL> bug.png`
2. Mở DevTools console, copy errors
3. Save vào `./debug/<timestamp>/` cả 2
4. Analyze screenshot + log, propose fix
Skill folder structure: 
.claude/skills/
  my-skill/
    SKILL.md              # required — metadata + instructions
    template.ts           # optional — file template
    example.md            # optional — example output
    references/           # optional — subfolders for deep context

3. Hooks — Event-driven automation

Shell command chạy tự động khi có event (trước/sau tool call). Dùng cho: auto-format, auto-test, log, notify.

Hooks events

EventKhi nào triggerUse case
PreToolUseTrước Claude chạy 1 toolBlock dangerous commands, log
PostToolUseSau tool chạyAuto-format file sau Edit
UserPromptSubmitUser vừa gửi promptInject context (ngày hiện tại, env info)
StopClaude xong turnNotify, summary
SubagentStopSubagent xongAggregate results
NotificationClaude cần attentionDesktop notification

Ví dụ 1: Auto-format sau Edit

# .claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "npx prettier --write $CLAUDE_TOOL_INPUT_FILE_PATH"
          }
        ]
      }
    ]
  }
}

Mỗi lần Claude edit file → Prettier tự format ngay. Code luôn đẹp mà Claude không cần nhớ.

Ví dụ 2: Block rm -rf nguy hiểm

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "echo $CLAUDE_TOOL_INPUT_COMMAND | grep -qE 'rm -rf /' && echo BLOCKED || exit 0"
          }
        ]
      }
    ]
  }
}

Ví dụ 3: Desktop notify khi xong task

{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "notify-send 'Claude Code' 'Task done!'"
          }
        ]
      }
    ]
  }
}
⚠️ Hooks chạy với quyền user: nếu viết sai (vô hạn loop, rm thư mục) có thể phá máy. Test ở repo throwaway trước.

4. Subagents — Claude gọi Claude khác

Subagent là session Claude riêng biệt với prompt/tool/context riêng. Dùng để isolate workload hoặc parallel.

Subagent built-in

AgentMô tảKhi Claude tự dùng
ExploreAgent chuyên search/explore codebaseCần tìm file/pattern tốn >3 query
PlanArchitect agent — thiết kế implementation planTask lớn cần plan chi tiết
general-purposeClaude fresh session, full toolTask độc lập không cần context hiện tại
Lợi ích subagent:
  • Context isolation — main session không bị nhồi output raw của tool
  • Parallel — 3 subagent chạy cùng lúc → nhanh 3×
  • Specialized — subagent có prompt/tool riêng

Viết subagent riêng

# .claude/agents/code-reviewer.md
---
name: code-reviewer
description: Independent code reviewer — senior dev hảo hạng,
  review diff giống đồng nghiệp khó tính
tools:
  - Read
  - Grep
  - Bash(git diff*, git log*)
model: opus
---

You are a senior code reviewer. Your job:
1. Read the diff / files the user points to
2. Check for:
   - Logic bugs, edge cases
   - Security issues (SQLi, XSS, secrets)
   - Performance concerns
   - Test coverage gaps
   - Code smells (duplication, god objects)
   - Naming, convention consistency
3. Group findings by severity: Critical / Major / Minor / Nit
4. For each finding: file:line, issue, suggested fix
5. Be direct. No "this looks fine" if there are issues.

Don't fix code — only review. User will fix.

Trong session Claude chính: gõ Use the code-reviewer agent to review this PR, Claude sẽ spawn agent với prompt trên.

5. settings.json — Cấu hình tổng

File cấu hình chính. 3 cấp: user global, project shared, project local.

FileVị tríCommitMục đích
User~/.claude/settings.json❌Preferences cá nhân xuyên project
Project shared.claude/settings.json✅Team convention
Project local.claude/settings.local.json❌ (gitignored)Override cá nhân trong project

Ví dụ settings.json đầy đủ

{
  "theme": "dark",
  "model": "claude-sonnet-4-6",

  "permissions": {
    "allow": [
      "Bash(npm *)",
      "Bash(git *)",
      "Bash(node *)",
      "Read",
      "Write",
      "Edit"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Bash(sudo *)",
      "Bash(curl * | sh)"
    ]
  },

  "env": {
    "NODE_ENV": "development"
  },

  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "npx prettier --write $CLAUDE_TOOL_INPUT_FILE_PATH 2>/dev/null || true" }
        ]
      }
    ]
  }
}
Allow/deny patterns: glob-like. Bash(npm *) cho phép mọi lệnh npm. Bash(rm -rf /*) chặn xoá root. Deny luôn thắng allow.

6. Cấu trúc folder .claude/ hoàn chỉnh

my-project/
├── CLAUDE.md                    # project instructions
├── CLAUDE.local.md              # personal (gitignored)
└── .claude/
    ├── settings.json            # team shared
    ├── settings.local.json      # personal (gitignored)
    ├── commands/
    │   ├── test-changes.md
    │   ├── fix-lint.md
    │   └── git/
    │       └── release.md       # → /git:release
    ├── skills/
    │   ├── database-migration.md
    │   └── screenshot-bug/
    │       ├── SKILL.md
    │       └── template.sh
    └── agents/
        ├── code-reviewer.md
        └── data-scientist.md
Best practice team: commit .claude/settings.json, commands/, skills/, agents/. settings.local.json và CLAUDE.local.md đặt trong .gitignore.

💡 Bài tập

  1. Viết command /explain — nhận argument file path, giải thích code file đó. Test với 3 file khác nhau.
  2. Skill riêng — viết skill "git-commit-conventional" dạy Claude viết commit theo chuẩn Conventional Commits của team bạn.
  3. Hook auto-format — setup Prettier chạy sau Edit. Verify: yêu cầu Claude sửa 1 file có indent xấu → check file sau khi xong phải đẹp.
  4. Subagent review — tạo code-reviewer agent, trigger: "Use code-reviewer to review my recent commit". Xem kết quả.
  5. Deny rule — thêm deny Bash(rm *) vào settings, thử yêu cầu Claude xoá file → phải bị chặn.
