Claude Code Cơ Bản

Cài đặt, login, prompt đầu tiên, permission modes, hiểu output của Claude, và cách dùng CLAUDE.md để dạy Claude về project của bạn.

1. Cài đặt Claude Code CLI

Yêu cầu

  • Node.js 18+ — kiểm tra node --version
  • Tài khoản Claude.ai (Free / Pro / Max)
  • Windows 10+, macOS, hoặc Linux

Cài 1 lệnh

# Cài global qua npm
npm install -g @anthropic-ai/claude-code

# Kiểm tra
claude --version

Lần chạy đầu tiên

$ cd my-project $ claude # Browser mở, login bằng tài khoản Claude.ai # Sau khi auth xong, quay lại terminal → session bắt đầu Welcome to Claude Code! I'm running in d:/my-project You: _
Tip: Claude chỉ hoạt động với file trong thư mục bạn đang cd. Muốn Claude xử lý project khác → cd vào đó rồi gõ claude. Không cần mở IDE.

2. Prompt đầu tiên — Tập gõ có chủ đích

Claude Code hiểu tiếng Việt tốt. Prompt càng cụ thể, kết quả càng đúng.

❌ Prompt yếu

# Quá mơ hồ
fix the bug

# Không nói file/hành vi
make the login better

# Thiếu context
optimize performance

Claude sẽ phải hỏi lại, hoặc đoán sai.

✅ Prompt chất lượng

# Cụ thể file, triệu chứng, expected
In src/auth/login.ts, the password
validation regex rejects valid emails
containing '+'. Fix it and add a test.

# Có context
Review src/components/Sidebar.jsx.
I suspect the re-render happens every
keystroke — profile it and propose fix.

Công thức prompt tốt

  1. Context — đang ở đâu trong codebase, tình huống
  2. Goal — muốn Claude làm gì
  3. Constraint — giới hạn (không được đổi API, giữ backward-compat…)
  4. Verification — cách check đã xong (test pass, output đúng…)
// Ví dụ gộp đủ 4 yếu tố
Context: File src/api/user.ts có hàm fetchUser() đang
  block UI khi API chậm.
Goal: Convert thành async + add loading state.
Constraint: Không đổi signature export, không break
  file nào import nó.
Verify: Chạy npm test, tất cả 42 test phải pass.

3. Permission Modes — Ai cho phép Claude chạy lệnh?

Claude không tự ý chạy bất kỳ lệnh nào. Bạn kiểm soát bằng 3 chế độ.

🔒 Ask (mặc định)

Claude hỏi trước mọi tool call quan trọng (ghi file, chạy shell, git).

  • An toàn nhất
  • Chậm — mỗi thao tác 1 dialog
  • Dùng khi: lần đầu, repo quan trọng

✅ Accept Edits

Tự động accept edit file trong workspace. Shell command vẫn hỏi.

  • Cân bằng tốt
  • Flow mượt
  • Dùng khi: task rõ, đã review plan

⚡ YOLO / Bypass

Claude chạy mọi thứ không hỏi. Dùng khi bạn thực sự tin task.

  • Nhanh nhất
  • Nguy hiểm nếu task sai
  • Dùng khi: container disposable, sandbox, CI

Đổi mode giữa session

# Khi đang trong session, gõ:
Shift + Tab → cycle qua các mode
# Hoặc gõ lệnh
/permissions
⚠️ YOLO mode: tuyệt đối KHÔNG dùng trong repo có secret/key thật. Claude có thể (vô tình) chạy rm -rf hoặc commit key. Dùng trong Docker container / worktree riêng.

4. Đọc output Claude đúng cách

Claude trình bày theo cấu trúc cố định. Học đọc chúng sẽ giúp bạn can thiệp đúng lúc.

You: Add a "Remember me" checkbox to the login form. Claude: I'll plan the changes first. ← (1) Claude nói intent ● Read(src/pages/Login.tsx) ← (2) Tool call ⎿ Read 87 lines ● Read(src/store/authStore.ts) ⎿ Read 45 lines Plan: ← (3) Kế hoạch 1. Add `rememberMe` field to Login form state 2. Persist to localStorage when checked 3. Restore on next page load via authStore init 4. Add unit test for persist/restore ● Edit(src/pages/Login.tsx) ← (4) Edit ⎿ Updated 12 lines ● Bash(npm test) ← (5) Verify ⎿ 5 passed, 0 failed ✓ Done. Added checkbox + persistence + test. Review diff? ← (6) Summary

Các "tín hiệu" cần chú ý

  • ● Read(...) — Claude đang đọc file. Nếu đọc quá nhiều file không liên quan → interrupt, prompt cụ thể hơn.
  • ● Bash(...) — Claude đang chạy shell. Đọc lệnh trước khi accept!
  • ⎿ — output tóm tắt của tool call
  • Plan: — Claude đang đề xuất plan, bạn có thể chỉnh (plan mode)
  • ✓ Done — claim là xong. Luôn verify bằng git diff hoặc chạy test.
Khi nào interrupt Claude? Bấm Esc. Nên interrupt khi:
  • Claude đọc file không liên quan lặp lại
  • Plan sai hướng ngay từ đầu
  • Chạy lệnh shell đáng ngờ
  • Loop tìm file mãi không ra

5. CLAUDE.md — Dạy Claude về project của bạn

File cấu hình quan trọng nhất. Đặt ở root repo. Claude đọc tự động mỗi session.

🎯 CLAUDE.md làm gì?

  • Mô tả project: tên, stack, cấu trúc
  • Commands: npm run dev, npm test, build
  • Conventions: naming, folder structure, code style
  • Gotchas: "file X đừng động, có bug đang fix ngoài Claude"
  • Business context: workflow, stakeholders

Kết quả: Claude đoán đúng hơn, đỡ phải explore lại mỗi lần.

📏 Nguyên tắc viết

  • Ngắn gọn — 100-300 dòng là đủ. Trên 500 dòng là quá tải context.
  • Actionable — "chạy npm run lint trước commit" tốt hơn "hãy follow quality standards"
  • Cập nhật — đổi architecture → update CLAUDE.md
  • Không lặp — thứ Claude đọc được từ package.json thì không cần ghi

Template CLAUDE.md đầy đủ

# CLAUDE.md

This file provides guidance to Claude Code when working with this repo.

## Project Overview

MyApp — SaaS e-commerce cho thị trường VN. Next.js frontend +
Express backend + Postgres. Đang ở giai đoạn beta, traffic ~10k/ngày.

## Commands

- `npm run dev` — start Next.js + Express concurrently
- `npm test` — Vitest (unit) + Playwright (E2E)
- `npm run db:migrate` — run Prisma migrations
- `npm run build` — production build

## Architecture

- **Frontend:** Next.js 15 App Router, Tailwind, shadcn/ui, Zustand
- **Backend:** Express + Prisma, PostgreSQL, Redis session
- **Auth:** NextAuth with Google + email OTP
- **Folder:** feature-based (src/features/auth, src/features/cart)

## Code Conventions

- TypeScript strict mode — no `any` unless có comment giải thích
- Test naming: `describe('ComponentName', ...)` matches file
- Commit: conventional (feat/fix/refactor/docs/chore)
- PR: 1 feature / PR, phải có test

## Gotchas

- `src/legacy/` — code cũ đang migrate sang src/features/. ĐỪNG touch.
- File `.env.production.example` phải sync với vault Vercel.
- Không dùng Math.random() cho ID — dùng nanoid().

## Team workflow

- Issues tracked in Linear (team ECOMM-*)
- Staging: deploy từ branch `develop` tự động
- Production: chỉ merge `main` sau QA pass trên staging
Pro tip: chạy /init lần đầu — Claude sẽ tự phân tích repo và đề xuất 1 CLAUDE.md khởi điểm. Bạn edit lại cho chuẩn.

6. CLAUDE.md phân cấp — project + user + team

Có 3 level CLAUDE.md, Claude đọc cả ba và merge context.

File Vị trí Commit? Dùng cho
Project ./CLAUDE.md (root repo) ✅ Commit Thông tin project, chia sẻ cả team
User global ~/.claude/CLAUDE.md ❌ Không Thói quen cá nhân áp dụng mọi project
Project local ./CLAUDE.local.md ❌ Không (gitignore) Ghi chú cá nhân trong project này

Ví dụ user global

# ~/.claude/CLAUDE.md

## My preferences

- Tôi thích code ngắn gọn, ít comment thừa
- Prefer TypeScript over JavaScript
- Hỏi confirm trước khi chạy `git push --force`
- Không giải thích dài dòng sau khi xong task,
  chỉ liệt kê file đã sửa
- Tiếng Việt cho giải thích, code comment tiếng Anh

File này tồn tại trên máy của bạn, áp dụng cho mọi project. Đồng nghiệp sẽ có file khác hoàn toàn.

💡 Bài tập

  1. Cài Claude Code — cài CLI hoặc mở claude.ai/code. Login xong.
  2. First session — trong bất kỳ repo nào, chạy claude, hỏi "Summarize this project in 3 sentences".
  3. Tạo CLAUDE.md — gõ /init, Claude gen xong đọc lại và sửa cho phù hợp.
  4. Mini task đầu tiên — yêu cầu Claude thêm comment JSDoc cho 1 function bất kỳ. Quan sát flow tool call.
  5. Thử permission mode — Shift+Tab để cycle. Cảm nhận khác biệt.
  6. Interrupt Claude — trong task dài, bấm Esc lúc Claude đang làm, quan sát Claude dừng đúng chỗ.
Sẵn sàng lên L2? Khi bạn đã prompt tự nhiên, biết đọc plan, dùng thoả hiệp mode → chuyển qua Commands để học slash commands built-in.
