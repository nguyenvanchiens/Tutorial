Tips, Patterns & FAQ

Prompt patterns cho task khó, workflow bài bản, anti-patterns cần tránh, debug khi Claude "đi sai hướng", và FAQ từ cộng đồng.

1. 10 Prompt Patterns hiệu quả

① Context → Goal → Constraint → Verify

Công thức chuẩn đã gặp ở trang Cơ Bản. Dùng cho mọi task không trivial.

② Explore first, act second

Before making changes, explore:
1. Read related files
2. Run tests to establish baseline
3. Show me your understanding

I'll approve before you edit.

③ Pinpoint the WHY

Không phải "fix bug", mà "fix bug VÌ..." → Claude hiểu đúng intent.

Fix the slow load on /dashboard.
// vì: user complaint tăng 30% tuần qua
// giả thuyết: N+1 query trong widget C
// ưu tiên: sửa cause, không caching workaround

④ Negative constraint

Nêu rõ thứ không được làm.

Refactor this service. BUT:
- Don't touch the public interface
- Don't add new dependencies
- Don't rename files
- Don't modify tests (they should still pass)

⑤ Style match existing

Add new feature X.
Follow exactly the pattern in src/features/Y/ —
  folder structure, naming, test style.
Don't invent new conventions.

⑥ Show don't tell

Thay vì mô tả, cho example.

Add a "Currency" formatter util.
Example I want:
  format(1234.5)         => "1,234.50 ₫"
  format(1_000_000)      => "1,000,000.00 ₫"
  format(0.5, { short: true }) => "0.5"

⑦ Think step by step + reflect

Task: migrate auth from JWT to session cookies.

Before coding, list:
1. All files affected
2. Breaking changes for client
3. Deployment order (migrate order matters)
4. Rollback plan

⑧ Try smaller scope first

Start with just /pages/login.tsx — convert that
one file to new auth pattern. Show me the result.
If I approve, continue with rest of the pages.

⑨ Compare options

Implement rate limiting. Compare 3 approaches:
A) Middleware with Redis (sliding window)
B) In-memory (no Redis)
C) Third-party lib

Recommend one. I'll approve before coding.

⑩ Role prompt

You are a senior security engineer reviewing this
code pre-release. Your job: find vulnerabilities,
not to bless the code.

Be paranoid. List every concern, no matter how small.

2. Workflow "Explore → Plan → Act → Verify"

Framework mạnh nhất cho task lớn. Dùng Plan Mode + subagents.

🔍 Phase 1: Explore

Mục tiêu: hiểu trước khi đụng vào.

Use the Explore agent.
Research: how does auth currently work?
Where is token created, validated, refreshed?
List files + functions involved.

Dùng Explore subagent → không nhồi main context

📝 Phase 2: Plan

Dựa vào kết quả explore, lập plan.

/plan
Based on what we learned in exploration, design
migration plan from JWT to sessions.

Include: order of file changes, deploy steps,
client breaking changes, rollback.

⚡ Phase 3: Act

Chia nhỏ theo plan, approve từng bước.

Execute step 1 of the plan: create new
session store module. Don't touch anything
else yet.

Show me diff before writing.

✅ Phase 4: Verify

Kiểm tra với code-reviewer agent.

Use the code-reviewer agent.
Review my changes in this branch.
Compare against requirements in plan.
Report gaps or concerns.
Tại sao pattern này work? Tách bạch nghiên cứu khỏi hành động. Claude không rush vào code khi chưa hiểu. Subagent giữ main context gọn.

3. Multi-agent Workflow

Chạy 2-3 subagent song song cho task lớn. Mỗi agent có vai trò riêng.

You: Migrate 30 React class components to function components. Claude: I'll parallelize across 3 worker agents for speed. ● Agent(general-purpose) — Worker 1 Migrating src/legacy/auth/*.jsx (10 files) ● Agent(general-purpose) — Worker 2 Migrating src/legacy/dashboard/*.jsx (10 files) ● Agent(general-purpose) — Worker 3 Migrating src/legacy/settings/*.jsx (10 files) [All 3 running in parallel, takes ~4 min] All workers done. Now verifying with code-reviewer. ● Agent(code-reviewer) Reviewed 30 files. Found: - 2 hooks misused (worker 1, file X, Y) - All tests still pass Want me to fix those 2 issues?
Khi nào parallel? Task độc lập giữa các chunk. Không parallel nếu các task depend nhau (ví dụ: refactor module A phải xong trước khi refactor B dùng nó).

4. Context Engineering — CLAUDE.md strategy

CLAUDE.md là "system prompt" của bạn. Viết giỏi = Claude làm tốt hơn 2-3× mà không phải prompt hay.

✅ CLAUDE.md nên có

  • Stack + version chính xác (Next 15, React 19, Node 22)
  • Commands quan trọng (npm run dev, test, migrate)
  • Folder structure + convention
  • Non-obvious rules ("không dùng X vì Y")
  • Gotchas, legacy areas
  • Testing strategy (unit/integration/E2E)
  • Git workflow (branch naming, PR rules)

❌ Không cần có

  • Thứ đọc được từ package.json, README
  • Marketing copy ("our app is amazing")
  • File list dài (Claude đọc được qua Glob)
  • Code example dài >30 dòng
  • Hướng dẫn general về React/TypeScript
Mẹo: Cứ 2-3 tuần, review CLAUDE.md một lần. Xem Claude có hay mắc lỗi gì có thể ngăn bằng document rule? Nếu có → thêm vào.

Dấu hiệu CLAUDE.md cần fix

Triệu chứngFix
Claude hay hỏi "which file?" cho thứ rõ ràngThêm folder structure vào doc
Claude dùng lib cũ đã deprecateGhi version và "KHÔNG dùng lib X, dùng Y"
Claude viết test sai frameworkSpecify "Test framework: Vitest. Examples in tests/example.test.ts"
Claude commit format saiGhi rõ Conventional Commits examples
Claude touch file không nên đụngThêm section "DO NOT MODIFY: src/legacy/"

5. Anti-patterns cần tránh

❌ Prompt 1 dòng cho task phức tạp

// Dở
"migrate to v2"

// Tốt — 10 giây gõ thêm = 10 phút save
"Migrate from v1 API to v2.
 Files affected: src/api/client.ts + all call sites.
 Breaking changes: endpoint prefix /api/v1 → /api/v2,
 auth header format changed (see v2 docs).
 Preserve all existing tests.
 Plan first before editing."

❌ Không đọc diff Claude làm

Luôn git diff sau khi Claude xong. Không tin blindly "✓ Done". Claude đôi khi claim xong nhưng:

  • Fix 1 trong 3 file, bỏ 2 file
  • Xoá test không báo
  • Thêm any type để bypass TS error

❌ Dùng YOLO mode mọi nơi

Tiện nhưng nguy hiểm. Claude có thể:

  • Xoá file uncommitted
  • Push force lên main
  • Chạy migration destructive

Dùng YOLO chỉ trong: container sandbox, git worktree riêng, hoặc Docker throwaway.

❌ Context quá nặng

Dumping 50 file vào context = Claude confused, miss chi tiết. Thay vì:

  • Dùng Explore subagent để isolate
  • /compact định kỳ
  • Chia task nhỏ hơn

❌ Bỏ qua Plan Mode cho task lớn

Task >5 file thay đổi, không dùng Plan Mode = gamble. 50% Claude làm sai hướng, bạn phát hiện khi đã quá muộn.

❌ Không version control giữa chừng

Claude làm 2h không commit → sai ở bước cuối → mất hết. Commit checkpoint sau mỗi milestone.

6. Debug khi Claude sai

🔴 Claude loop tìm file không ra

Nguyên nhân: glob pattern sai, hoặc file thật không tồn tại.

Fix: Esc → cho Claude đường dẫn cụ thể: The file is at src/X/Y.ts, not src/Y.ts.

🔴 Claude tạo code không compile

Fix: sau khi Claude xong, prompt: Run npm run build. Fix errors. Claude tự iterate đến khi green.

🔴 Claude hallucination (tên hàm/file không có)

Nguyên nhân: thiếu context, Claude đoán.

Fix: add CLAUDE.md về dependencies, hoặc prompt: Don't assume. Read actual source to verify names exist.

🔴 Claude đi sai hướng ngay từ đầu

Fix: Esc Esc rewind. Viết lại prompt rõ hơn. Hoặc dùng Plan Mode để kiểm duyệt trước khi act.

🔴 Claude đòi hỏi quá nhiều xác nhận

Fix: Shift+Tab chuyển sang Accept Edits. Hoặc thêm file pattern vào allow trong settings.json.

🔴 Performance chậm / lag

  • /compact nén context
  • /model haiku cho task đơn giản
  • /fast toggle Fast Mode (Opus nhanh hơn)
  • Restart session (/clear)

7. FAQ

❓ Claude Code miễn phí không?

CLI + extension cài miễn phí. Để chạy cần tài khoản:

  • Claude Pro ($20/tháng) — đủ cho dev cá nhân
  • Claude Max ($100-200/tháng) — heavy usage
  • API key — pay-per-token, tốt cho automation

❓ Claude có đọc được private repo/code của tôi?

Khi dùng CLI local: code trên máy bạn, gửi từng bit Claude cần tới API Anthropic. Anthropic không train từ data bạn gửi (Zero Data Retention có thể bật).

Khi dùng claude.ai/code web: code clone vào sandbox của Anthropic — vẫn tuân thủ privacy, nhưng nếu data siêu nhạy cảm → ưu tiên CLI local.

❓ Khác gì Cursor / GitHub Copilot?

Ngắn gọn: Claude Code agentic + terminal-first + 1M context. Copilot chủ yếu autocomplete. Cursor là IDE fork với agent mode. Xem bảng so sánh ở trang Roadmap.

❓ Claude Code có chạy offline không?

Không. Cần internet để gọi API Anthropic. Dùng model local → tools khác (Aider + Ollama, LM Studio).

❓ Dùng với codebase 1M+ LOC có nổi không?

Có. Context Opus 1M token (~750k LOC). Với repo lớn hơn: dùng Explore agent để focus 1 subsection. CLAUDE.md chỉ Claude tới folder quan trọng.

❓ Có thể dùng Claude Code cho ngôn ngữ non-English không?

Prompt/response bằng tiếng Việt OK. Code comment bằng tiếng Việt cũng OK nếu CLAUDE.md nói rõ. Claude hiểu 100+ ngôn ngữ tự nhiên.

❓ Claude có "quên" sau session không?

Có — mỗi session là context riêng. Muốn nhớ xuyên session: dùng CLAUDE.md, hoặc memory MCP server, hoặc slash command /memory.

❓ Làm sao share Claude Code config với team?

Commit CLAUDE.md + .claude/settings.json + .claude/commands/ + .claude/skills/ vào repo. Mỗi dev clone repo xong là có sẵn config.

❓ Debug Claude bị đơ / không respond?

Thứ tự check:

  1. /doctor — scan setup
  2. /status — session info
  3. Check Anthropic status: status.anthropic.com
  4. Logout + login lại
  5. Update: npm i -g @anthropic-ai/claude-code@latest
  6. Submit /bug

❓ Làm sao hạn chế token cost?

  • Dùng Haiku cho task đơn giản
  • /compact thường xuyên
  • CLAUDE.md ngắn gọn — đừng 1000 dòng
  • Giới hạn scope mỗi session
  • Explore subagent thay vì nhồi file vào main context
  • Theo dõi qua /cost

8. Tóm tắt — 10 nguyên tắc vàng

  1. Context rõ, goal rõ, constraint rõ, verify rõ — công thức 4C của prompt tốt.
  2. Đọc plan trước khi accept — dùng Plan Mode cho task lớn.
  3. CLAUDE.md là đầu tư — 1 giờ viết, tiết kiệm nhiều ngày prompt lặp.
  4. Git commit thường xuyên — checkpoint sau mỗi milestone, dễ revert.
  5. Tin nhưng verify — git diff mỗi lần Claude claim "done".
  6. Isolate với subagents — Explore để không nhồi main context.
  7. Interrupt khi thấy sai — Esc Esc rẻ hơn để Claude đi xa rồi sửa.
  8. Model đúng cho task đúng — Opus khó, Sonnet default, Haiku vặt.
  9. Hooks cho việc lặp lại — auto-format, auto-test sau edit.
  10. Coi Claude như đồng nghiệp — sếp giỏi điều hành team, không micromanage từng dòng.
Hành trình học: đọc xong 6 trang này rồi thực hành 1 tuần với project thật. Sau đó quay lại scan các mục bạn cần sâu hơn. Mastery = kiến thức × thực hành.
