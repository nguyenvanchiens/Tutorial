Cài đặt Redis & redis-cli

Cài Redis trên Linux, macOS, Docker, WSL. Hiểu redis.conf, làm chủ redis-cli, RESP protocol và kết nối từ .NET / Node.js. Cập nhật cho Redis 7.4 / 8.0 (2026).

1. Redis là gì & phiên bản nào?

Redis là in-memory data store. Tính tới 2026, hệ sinh thái đã tách đôi sau đợt đổi license năm 2024 — bạn nên biết để chọn đúng bản.

📦 Redis (Redis Inc.)

Bản gốc. Từ Redis 7.4 dùng license kép RSALv2 / SSPLv1 (không còn BSD thuần). Redis 8.0 (2025) thêm lại tùy chọn AGPLv3. Có RediSearch, JSON, TimeSeries tích hợp.

# Kiểm tra version sau khi cài
redis-server --version
Redis server v=8.0.x

🍴 Valkey (Linux Foundation)

Fork BSD mã nguồn mở ra đời tháng 3/2024 do AWS, Google, Oracle hậu thuẫn sau khi Redis đổi license. API tương thích Redis 7.2. Nhiều cloud (ElastiCache, Memorystore) đã chuyển sang Valkey mặc định.

2026: drop-in cho hầu hết use case. Client (StackExchange.Redis, ioredis) dùng y nguyên. Chi tiết khác biệt xem trang Internals.

2. Cài trên Linux

2 hướng: package manager (nhanh, có thể cũ) hoặc build from source (mới nhất, kiểm soát flag).

Ubuntu / Debian — repo chính thức của Redis

# Thêm GPG key + repo chính thức (mới hơn apt mặc định)
sudo apt-get install -y lsb-release curl gpg
curl -fsSL https://packages.redis.io/gpg | sudo gpg --dearmor -o /usr/share/keyrings/redis-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/redis-archive-keyring.gpg] https://packages.redis.io/deb $(lsb_release -cs) main" \
  | sudo tee /etc/apt/sources.list.d/redis.list

sudo apt-get update
sudo apt-get install -y redis        # cài redis-server + redis-cli

# Chạy như systemd service
sudo systemctl enable --now redis-server
sudo systemctl status redis-server

RHEL / Rocky / Fedora

sudo dnf install -y redis
sudo systemctl enable --now redis

Build from source — kiểm soát hoàn toàn

# Cần build tools
sudo apt-get install -y build-essential tcl pkg-config

# Tải bản ổn định, build có TLS
wget https://download.redis.io/redis-stable.tar.gz
tar xzf redis-stable.tar.gz
cd redis-stable
make BUILD_TLS=yes              # bật TLS support
make test                       # chạy test suite (tùy chọn)
sudo make install               # cài vào /usr/local/bin

# Verify
redis-server --version
which redis-cli
Vì sao build from source? Bản apt/dnf của distro thường trễ vài version. Nếu cần feature mới (Functions, RESP3 client tracking, mới nhất từ Redis 8) thì build hoặc dùng repo chính thức ở trên.

3. Cài trên macOS & WSL

🍎 macOS — Homebrew

brew install redis

# Chạy nền như service (tự start lúc boot)
brew services start redis

# Hoặc chạy foreground để xem log
redis-server /opt/homebrew/etc/redis.conf

# Dừng service
brew services stop redis

File config ở /opt/homebrew/etc/redis.conf (Apple Silicon) hoặc /usr/local/etc/redis.conf (Intel).

🪟 Windows — dùng WSL2

Redis không hỗ trợ Windows native. Cách đúng năm 2026 là chạy trong WSL2 (Ubuntu).

# PowerShell (admin), một lần
wsl --install -d Ubuntu

# Trong shell Ubuntu của WSL, làm theo mục Linux
sudo apt-get update
sudo apt-get install -y redis
sudo service redis-server start

# Test từ Windows: localhost:6379 đã forward
redis-cli ping
Lưu ý: Microsoft từng có port Memurai/MSOpenTech nhưng đã lỗi thời. Đừng dùng cho dev mới — Docker hoặc WSL2 là lựa chọn chuẩn.

4. Docker — nhanh nhất cho dev

Không cài gì lên máy, container hoá. Lý tưởng cho local dev và CI.

# Chạy nhanh, port mặc định
docker run --name redis -p 6379:6379 -d redis:8-alpine

# Vào redis-cli bên trong container
docker exec -it redis redis-cli

# Có persistence + custom config + password
docker run --name redis -d \
  -p 6379:6379 \
  -v redis-data:/data \
  -v $(pwd)/redis.conf:/usr/local/etc/redis/redis.conf \
  redis:8-alpine \
  redis-server /usr/local/etc/redis/redis.conf --requirepass mypassword

docker-compose.yml

services:
  redis:
    image: redis:8-alpine
    ports: ["6379:6379"]
    command: redis-server --appendonly yes --requirepass devpass
    volumes: [redis-data:/data]
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
volumes:
  redis-data:
Image tip: redis:8-alpine nhỏ (~15MB). Cần module RediSearch/JSON thì dùng redis/redis-stack (có GUI Redis Insight ở cổng 8001). Muốn fork mã nguồn mở thì valkey/valkey.

5. redis.conf — Các tham số phải biết

File config chính. Dưới đây là các directive bạn sẽ chạm tới ngay từ ngày đầu.

# ===== Network =====
bind 127.0.0.1 -::1     # chỉ nghe localhost (an toàn mặc định)
                          # prod: bind IP private, KHÔNG bao giờ 0.0.0.0 lộ internet
port 6379               # cổng; đặt 0 để tắt plaintext (chỉ TLS)
protected-mode yes        # chặn connect ngoài khi chưa auth
timeout 0                 # giây idle trước khi đóng client (0 = không)

# ===== Security =====
requirepass your-strong-password   # mật khẩu (dùng AUTH để đăng nhập)

# ===== Memory =====
maxmemory 2gb             # trần RAM; tới ngưỡng thì eviction
maxmemory-policy allkeys-lru   # xoá key ít dùng nhất khi đầy (cache)
                              # noeviction nếu Redis là DB không được mất

# ===== Persistence =====
appendonly yes            # bật AOF — mất tối đa ~1s khi crash
appendfsync everysec      # fsync mỗi giây (cân bằng tốc độ/an toàn)
save 3600 1             # RDB snapshot: ≥1 thay đổi trong 1h
save 300 100           # hoặc ≥100 thay đổi trong 5 phút
dir /var/lib/redis        # thư mục lưu dump.rdb / appendonly

# ===== Logging =====
logfile /var/log/redis/redis.log
loglevel notice           # debug / verbose / notice / warning
DirectiveMặc địnhKhi nào chỉnh
bind127.0.0.1Để app server khác máy connect → bind IP private
port6379Tránh xung đột / multi-instance trên 1 máy
maxmemory0 (không giới hạn)Luôn set trên prod kẻo OOM kill
appendonlynoBật khi không được mất data lúc crash
requirepass(trống)Luôn bật trừ khi localhost-only dev
# Đổi config runtime không cần restart
redis-cli CONFIG SET maxmemory 3gb
redis-cli CONFIG GET maxmemory-policy
redis-cli CONFIG REWRITE        # ghi config hiện tại trở lại file

6. redis-cli — Công cụ bạn sống chung mỗi ngày

CLI đi kèm Redis. Đây là những thao tác bạn sẽ dùng liên tục.

$ redis-cli # connect localhost:6379 $ redis-cli -h 10.0.0.5 -p 6380 # host/port khác $ redis-cli -a mypassword # auth (hoặc dùng AUTH sau khi vào) $ redis-cli -u redis://user:pass@host:6379/0 # connection URI > PING PONG > SELECT 1 # chuyển sang DB số 1 (mặc định 0..15) OK > SET hello "world" OK > GET hello "world" > DBSIZE # số key trong DB hiện tại (integer) 1 > INFO server # thông tin server > CLIENT LIST # client đang kết nối

🔎 --scan — duyệt key an toàn

# Liệt kê key theo pattern, KHÔNG block (dùng SCAN bên trong)
redis-cli --scan --pattern 'user:*'

# Đếm tổng key match
redis-cli --scan --pattern 'cache:*' | wc -l

# Xoá hàng loạt an toàn
redis-cli --scan --pattern 'session:*' | xargs redis-cli DEL
Không dùng KEYS * — chặn server single-thread. --scan chia batch nên an toàn prod.

🔭 MONITOR — xem lệnh realtime

> MONITOR
OK
1718....123 [0 127.0.0.1:54021] "GET" "hello"
1718....456 [0 127.0.0.1:54021] "SET" "x" "1"

In mọi command đang chạy. Cực hữu ích để debug "app gọi cái gì?". Chỉ bật ngắn vì làm chậm server.

# Thống kê độ trễ ngay tại terminal
redis-cli --latency
redis-cli --stat            # ops/s, mem, clients mỗi giây
redis-cli --bigkeys         # tìm key tốn RAM nhất
# Chạy lệnh một phát rồi thoát (script hoá)
redis-cli SET counter 0
redis-cli INCR counter
redis-cli -n 2 GET counter      # -n chọn DB index trực tiếp

# Đưa file lệnh hàng loạt (pipe mode, cực nhanh)
cat commands.txt | redis-cli --pipe

7. RESP — Giao thức Redis nói chuyện

RESP (REdis Serialization Protocol) là protocol text trên TCP. Hiểu nó giúp bạn debug bằng telnet và biết client làm gì dưới mui xe.

Các kiểu RESP (RESP2)

Byte đầuKiểuVí dụ
+Simple String+OK\r\n
-Error-ERR ...\r\n
:Integer:1000\r\n
$Bulk String$5\r\nhello\r\n
*Array*2\r\n...\r\n

RESP3 (Redis 6+)

Phiên bản mới thêm kiểu: _ (null), # (boolean), , (double), % (map), ~ (set), > (push). Map giúp HGETALL trả object thay vì mảng phẳng, và bật được client-side caching.

> HELLO 3          # nâng cấp connection lên RESP3

Tự gửi RESP bằng tay

# Lệnh SET foo bar dưới dạng RESP raw:
# *3  = mảng 3 phần tử (SET, foo, bar)
*3\r\n$3\r\nSET\r\n$3\r\nfoo\r\n$3\r\nbar\r\n

# Thử trực tiếp qua nc — sẽ thấy server trả +OK
printf '*3\r\n$3\r\nSET\r\n$3\r\nfoo\r\n$3\r\nbar\r\n' | nc localhost 6379
+OK
Vì sao đáng học: Khi viết client, mock test, hoặc debug "tại sao client X gửi sai", đọc được RESP cho bạn nhìn xuyên tầng abstraction. Cả Redis lẫn Valkey đều dùng RESP — protocol không đổi sau fork.

8. Kết nối từ code

C# / .NET — StackExchange.Redis

// dotnet add package StackExchange.Redis
using StackExchange.Redis;

// Connection string đầy đủ: host, password, TLS, abortConnect
var config = ConfigurationOptions.Parse(
    "localhost:6379,password=mypassword,abortConnect=false,ssl=false");
config.ConnectRetry = 3;

// Multiplexer là SINGLETON — tạo 1 lần, dùng chung toàn app
var mux = await ConnectionMultiplexer.ConnectAsync(config);
var db = mux.GetDatabase(0);     // chọn DB index

await db.StringSetAsync("hello", "world", TimeSpan.FromMinutes(10));
var v = await db.StringGetAsync("hello");
var pong = await db.PingAsync();

// ASP.NET Core DI
builder.Services.AddSingleton<IConnectionMultiplexer>(
    _ => ConnectionMultiplexer.Connect(config));

Node.js — ioredis

// npm install ioredis
import Redis from 'ioredis';

// Cách 1: connection URL
const redis = new Redis('redis://:mypassword@localhost:6379/0');

// Cách 2: object — rõ ràng hơn, có retry strategy
const redis2 = new Redis({
  host: 'localhost',
  port: 6379,
  password: 'mypassword',
  db: 0,
  retryStrategy: (times) => Math.min(times * 50, 2000),
});

await redis.set('hello', 'world', 'EX', 600);
const v = await redis.get('hello');

redis.on('error', (e) => console.error('Redis error', e));
redis.on('connect', () => console.log('Connected'));
Quy tắc vàng: 1 connection multiplexer dùng chung toàn app (singleton). Đừng tạo connection mới mỗi request. Cả StackExchange.Redis lẫn ioredis đều multiplex command qua 1 socket — hiệu quả hơn connection pool kiểu SQL.

💡 Checklist sau khi cài

  1. Verify: redis-cli ping trả PONG.
  2. Bảo mật ngay: set requirepass, bind private IP, protected-mode yes — đừng để Redis trần ra internet.
  3. Set maxmemory + maxmemory-policy để tránh OOM kill.
  4. Bật persistence (appendonly yes) nếu data quan trọng.
  5. Thử --scan, --stat, --bigkeys để quen tooling.
  6. Kết nối từ app bằng singleton multiplexer, test một SET/GET.
