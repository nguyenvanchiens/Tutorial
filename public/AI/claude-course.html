Mục Tiêu & Lộ Trình Khoá Học

Mục tiêu cốt lõi

Khoá học này không chỉ dạy bạn sử dụng một công cụ AI. Mục tiêu thực sự là thay đổi cách bạn tư duy khi làm việc với AI. Sau khoá học, bạn sẽ chuyển từ người dùng AI thụ động (hỏi gì cũng copy-paste) sang người điều khiển AI chủ động — biết ra lệnh chính xác, review kết quả, và xây dựng sản phẩm chất lượng.

Cụ thể, bạn sẽ:

  • Hiểu cách AI hoạt động (LLM, token, context window) để biết giới hạn của nó
  • Thao tác thành thạo Claude Code trên CLI và IDE
  • Áp dụng quy trình: Lên kế hoạch → Ra lệnh → Review → Phản hồi → Hoàn thiện
  • Xây dựng dự án full-stack thực tế với sự hỗ trợ của AI
  • Tạo workflow tự động (Skill) để tái sử dụng cho nhiều dự án

MODULE 01

Setup Dự Án

Claude AI là gì?

Claude là một mô hình ngôn ngữ lớn (LLM) do công ty Anthropic phát triển. Anthropic được thành lập bởi các cựu thành viên của OpenAI, tập trung vào việc xây dựng AI an toàn và hữu ích. Claude nổi bật với khả năng:

  • Hiểu ngôn ngữ tự nhiên cực tốt — đọc hiểu code, viết văn bản, phân tích vấn đề
  • Context window lớn — có thể xử lý hàng trăm nghìn token trong 1 cuộc hội thoại
  • Claude Code — công cụ CLI/IDE cho phép AI trực tiếp đọc, viết, và chỉnh sửa code trong dự án của bạn

Tạo tài khoản & Cài đặt

  1. Tạo tài khoản tại claude.ai — Đăng ký bằng email, xác nhận. Gói Free có giới hạn, nên nâng cấp lên Pro ($20/tháng) để có đủ token thực hành, hoặc Max ($100/tháng) nếu dùng nhiều.
  2. Cài Claude Code CLI — Mở terminal và chạy: 
    npm install -g @anthropic-ai/claude-code
    Sau khi cài xong, gõ claude trong terminal để bắt đầu. Lần đầu sẽ yêu cầu đăng nhập.
  3. Cài extension VS Code — Tìm "Claude" trong VS Code Extensions marketplace, cài đặt, đăng nhập. Sau đó bạn có thể mở Claude panel ngay trong IDE.
  4. Kiểm tra — Chạy claude --version để xác nhận đã cài thành công. Chạy claude trong thư mục dự án để bắt đầu làm việc.

Token là gì? Tại sao quan trọng?

Mỗi khi bạn gửi prompt cho AI và nhận phản hồi, hệ thống đếm số lượng token — đơn vị nhỏ nhất mà AI xử lý (khoảng 3/4 từ tiếng Anh = 1 token, tiếng Việt có thể nhiều token hơn do dấu).

LoạiGiải thíchVí dụ
Input tokenNhững gì bạn gửi cho AI (prompt, code, file đính kèm)Bạn paste 200 dòng code + câu hỏi = ~1500 input token
Output tokenNhững gì AI trả về (câu trả lời, code mới)AI viết lại 200 dòng code + giải thích = ~2000 output token
Mẹo tiết kiệm token: Không paste toàn bộ file khi chỉ cần hỏi về 1 function. Chỉ định rõ file và dòng cần sửa. Dùng /clear để xoá lịch sử khi chuyển sang chủ đề mới.

Context Window — Tại sao AI "quên"?

Context Window là giới hạn tổng số token mà AI có thể "nhớ" trong 1 cuộc hội thoại. Ví dụ, Claude Sonnet có context window ~200K token.

Khi cuộc hội thoại vượt quá giới hạn này, AI bắt đầu bỏ bớt những nội dung cũ đi — đây là lý do bạn thấy AI "quên" những gì đã nói trước đó. Hậu quả:

  • AI làm lại những gì đã làm
  • AI thay đổi phong cách code giữa chừng (vì "quên" phong cách ban đầu)
  • AI nói "tôi chưa thấy file đó" dù bạn đã gửi trước đó
Giải pháp: Chia công việc thành nhiều phiên ngắn. Dùng CLAUDE.md (Module 05) để lưu thông tin quan trọng mà AI cần nhớ xuyên suốt dự án. Dùng /clear và bắt đầu phiên mới khi cuộc hội thoại quá dài.
MODULE 02

Sử Dụng Claude Code Như Beginner

Giao diện và các lệnh cơ bản

Khi bạn gõ claude trong terminal (tại thư mục dự án), một phiên làm việc sẽ bắt đầu. Bạn có thể gõ câu hỏi trực tiếp và AI sẽ trả lời, đọc file, hoặc chỉnh sửa code.

Các lệnh thường dùng trong CLI:

LệnhChức năng
claudeBắt đầu phiên làm việc mới trong thư mục hiện tại
/helpXem danh sách các lệnh có sẵn
/clearXoá toàn bộ lịch sử cuộc hội thoại (giải phóng context)
/statusKiểm tra trạng thái: model đang dùng, token đã sử dụng
/modelChuyển đổi model (Haiku, Sonnet, Opus)
/costXem chi phí token của phiên hiện tại

Sử dụng trong IDE (VS Code)

Sau khi cài extension, bạn mở Claude panel (thường ở sidebar). Quy trình cơ bản:

  1. Mở file cần làm việc — Claude sẽ tự động nhận biết file đang mở
  2. Gõ prompt — Mô tả những gì bạn muốn, ví dụ: "Thêm validation cho form đăng ký"
  3. Review thay đổi — AI sẽ hiển thị diff (phần thay đổi). Bạn đọc kỹ rồi chọn Accept hoặc Reject từng thay đổi
  4. Tiếp tục phản hồi — Nếu chưa ưng ý, gõ tiếp yêu cầu chỉnh sửa cụ thể

Kỹ thuật prompt cơ bản

Cách bạn đặt câu hỏi quyết định 80% chất lượng câu trả lời. Nguyên tắc cơ bản:

1. Mô tả rõ ràng, cụ thể

// TỆ:
"Sửa lỗi form"

// TỐT:
"Trong file src/components/LoginForm.jsx, form submit không hiển thị
error message khi email không hợp lệ. Hãy thêm validation email và
hiển thị lỗi phía dưới input field."

2. Dùng tên cụ thể (file, function, biến)

// TỆ:
"Sửa cái function xử lý dữ liệu"

// TỐT:
"Trong file src/utils/api.js, function fetchUserData() đang trả về
undefined khi API lỗi 404. Hãy thêm error handling để throw error
với message rõ ràng."

3. Prompt theo từng bước (Step by Step)

"Tạo API endpoint GET /api/users với các bước:
1. Tạo route trong routes/users.js
2. Tạo controller function trong controllers/userController.js
3. Query database lấy danh sách users, có pagination
4. Trả về JSON với format: { data: [], total, page, limit }"

4. Cung cấp context

"Dự án dùng React 19 + Vite, backend là Express + PostgreSQL.
Đang có file structure như sau: src/components/, src/hooks/,
server/routes/, server/controllers/.
Hãy tạo component UserProfile theo đúng pattern của các component
đang có trong dự án."

Copy/Paste vs Inline Edit

Giới hạn của cách dùng Beginner

Nếu bạn chỉ dùng AI theo kiểu "hỏi — copy — paste", bạn sẽ gặp những vấn đề sau khi dự án lớn lên:

  • Code chạy được nhưng chất lượng thấp: Không có error handling, không có validation, không có test. "Nó chạy" không có nghĩa là "nó tốt".
  • AI làm sai nhưng bạn không biết kiểm tra: AI rất tự tin khi trả lời sai. Nếu bạn không hiểu code, bạn không phát hiện được bug.
  • Dự án lớn thì AI bắt đầu "loạn": Khi project có nhiều file, AI không nhớ hết context, bắt đầu tạo code trùng lặp, phong cách không nhất quán, thậm chí ghi đè code cũ.
Đây là lý do bạn cần Module 03 trở đi: Để thực sự hiệu quả với AI, bạn phải thay đổi tư duy — từ "người hỏi" thành "người điều khiển".
MODULE 03

Thay Đổi Tư Duy

"Sản phẩm chạy được" khác "Sản phẩm chất lượng"

Nhiều người nghĩ rằng nếu code chạy được là xong. Nhưng trong thực tế, code chất lượng phải đạt nhiều tiêu chí:

Tiêu chíCode "chạy được"Code chất lượng
Đọc hiểuTên biến x, d, tempTên biến rõ nghĩa: userEmail, isLoading
Bảo trìTất cả logic trong 1 file 500 dòngTách thành modules, mỗi file 1 trách nhiệm
Error handlingKhông có try-catchXử lý mọi trường hợp lỗi có thể xảy ra
SecurityQuery SQL trực tiếp từ inputDùng parameterized queries, validate input
TestTest thủ bằng tay, "thấy chạy là OK"Unit test, integration test tự động

AI hoạt động như thế nào? (LLM cơ bản)

Claude (và các AI ngôn ngữ khác) là Large Language Model — mô hình dự đoán token tiếp theo dựa trên xác suất. Điều này có nghĩa:

  • AI không "hiểu" như con người. Nó tính xác suất token nào có khả năng xuất hiện tiếp theo cao nhất dựa trên dữ liệu đã học.
  • Hallucination: AI có thể tự tin nói sai. Ví dụ, nó có thể "phát minh" ra một API không tồn tại, hoặc nói một thư viện có function mà thực tế không có.
  • Kết quả không nhất quán: Cùng 1 câu hỏi, hỏi 2 lần có thể cho 2 câu trả lời khác nhau. Đây không phải lỗi — đây là bản chất của mô hình xác suất.
Hệ quả thực tế: Không bao giờ tin AI 100%. Luôn kiểm tra code AI viết, đặc biệt là: tên hàm/thư viện có tồn tại không, logic có đúng không, có bảo mật không.

Tư duy đúng: BẠN là Kiến Trúc Sư, AI là Thợ Xây

Đây là thay đổi quan trọng nhất trong khoá học. Thay vì để AI quyết định mọi thứ, bạn phải:

  • BẠN quyết định WHAT (làm gì) và HOW (làm như thế nào)
  • AI thực thi theo chỉ dẫn của bạn

Quy trình làm việc đúng:

  1. Bạn ra yêu cầu cụ thể — "Tạo function validateEmail nhận string, trả về boolean, dùng regex"
  2. AI làm — AI viết code theo yêu cầu
  3. BẠN review — Đọc code, kiểm tra logic, test thử
  4. Bạn phản hồi — "Regex này không bắt được email có dấu +. Sửa lại dùng RFC 5322"
  5. AI sửa — AI cập nhật theo feedback của bạn

Checklist review code AI tạo ra

Mỗi khi AI trả về code, hãy kiểm tra:

  • Logic có đúng với yêu cầu không? (không phải chỉ "chạy được" là đúng)
  • Có xử lý trường hợp lỗi (error handling) không?
  • Có xử lý trường hợp biên (edge cases) không? (array rỗng, null, undefined)
  • Tên biến, tên function có rõ nghĩa không?
  • Có code trùng lặp (duplicate) không?
  • Có import đúng thư viện không? Thư viện đó có tồn tại và đúng version không?
  • Có vấn đề bảo mật không? (SQL injection, XSS, lộ secret)
Lỗi thường gặp của AI: Import thư viện không tồn tại, dùng API deprecated, hardcode secret, không close database connection, tạo code trùng lặp với code đã có trong project.

Tư duy Chia Nhỏ Vấn Đề (Divide & Conquer)

Sai lầm lớn nhất của người mới là prompt 1 cục lớn: "Tạo cho tôi app e-commerce với đăng nhập, giỏ hàng, thanh toán, quản lý đơn hàng". Kết quả sẽ rất tệ.

Cách đúng:

// THAY VÌ:
"Tạo app e-commerce hoàn chỉnh"

// HÃY CHIA NHỎ:
Phiên 1: "Thiết kế database schema cho sản phẩm (products table)"
Phiên 2: "Tạo API GET /api/products với pagination và filter"
Phiên 3: "Tạo component ProductList hiển thị danh sách"
Phiên 4: "Thêm chức năng search và filter theo category"
...

Mỗi phiên tập trung 1 nhiệm vụ nhỏ, AI sẽ làm tốt hơn rất nhiều. Sau mỗi phiên, bạn review và đảm bảo code chuẩn trước khi chuyển sang phiên tiếp.

MODULE 04

Plan Mode — Lên Kế Hoạch Trước Khi Code

Plan Mode là gì?

Plan Mode là chế độ trong Claude Code nơi AI chỉ lên kế hoạch mà không viết code. Đây là bước cực kỳ quan trọng mà nhiều người bỏ qua.

Tại sao cần Plan Mode?

  • Tránh tình trạng AI viết code sai hướng ngay từ đầu
  • Bạn nhìn thấy "bức tranh toàn cảnh" trước khi đi vào chi tiết
  • Dễ phát hiện vấn đề thiết kế sớm, trước khi lãng phí thời gian code
  • Tiết kiệm token — sửa kế hoạch rẻ hơn sửa code

Cách sử dụng Plan Mode

Trong CLI:

# Bật Plan Mode khi bắt đầu phiên
claude --plan

# Hoặc trong phiên, yêu cầu AI chỉ lên kế hoạch
"Hãy lên kế hoạch chi tiết để implement chức năng authentication.
KHÔNG viết code, chỉ mô tả kế hoạch từng bước."

Trong IDE: Khi dùng Claude panel, bắt đầu prompt với chỉ dẫn rõ ràng rằng chỉ muốn kế hoạch, chưa muốn code.

Mẹo: Viết rõ "KHÔNG viết code" hoặc "Chỉ lên kế hoạch" trong prompt. AI đôi khi sẽ "nóng vội" và bắt đầu code nếu bạn không nói rõ.

Thành phần của kế hoạch tốt

Thành phầnMô tảVí dụ
Mục tiêuKết quả cuối cùng cần đạt"User có thể đăng ký và đăng nhập bằng email/password"
Các bước thực hiệnTừng bước cụ thể, có thứ tự"1. Tạo User model 2. Tạo auth routes 3. Implement JWT..."

Phản biện kế hoạch — Câu hỏi nên đặt

Sau khi AI đưa ra kế hoạch, đừng chấp nhận ngay. Hãy hỏi:

  • "Cách này có scale được khi có 10.000 users không?"
  • "Có cách nào đơn giản hơn không?"
  • "Nếu X xảy ra thì sao?" (X = lỗi mạng, dữ liệu sai, user hack...)
  • "Tại sao chọn thư viện A mà không phải B?"
  • "Bước nào có thể gặp vấn đề nhất?"

Iterative Planning (lập kế hoạch nhiều vòng): Vòng 1: AI đưa kế hoạch → Vòng 2: Bạn phản biện, AI sửa → Vòng 3: Bạn duyệt kế hoạch cuối → Bắt đầu code.

Red flags — Kế hoạch tệ

  • Kế hoạch quá chung chung, không có tên file/function cụ thể
  • Bỏ qua error handling và security
  • Không đề cập đến edge cases
  • Dùng quá nhiều thư viện không cần thiết
  • Không có bước testing
  • Cấu trúc thư mục phức tạp không cần thiết cho dự án nhỏ
Nhớ: Cung cấp càng nhiều context (tech stack, cấu trúc hiện tại, yêu cầu cụ thể), AI sẽ lên kế hoạch càng tốt. Kế hoạch mơ hồ ← prompt mơ hồ.
MODULE 05

Quản Lý Bộ Nhớ Với CLAUDE.md

Tại sao AI bị quên?

Như đã học ở Module 01, AI có Context Window giới hạn. Khi cuộc hội thoại dài, AI "quên" những gì bạn nói trước đó. Với dự án thực tế kéo dài nhiều ngày, vấn đề này rất nghiêm trọng:

  • Ngày 1: Bạn nói "Dùng camelCase cho tất cả biến" — Ngày 3: AI bắt đầu dùng snake_case
  • Bạn đã thống nhất cấu trúc folder, nhưng phiên mới AI tạo file ở nơi khác
  • AI tạo function trùng với function đã có vì không nhớ

Giải pháp: CLAUDE.md — file bộ nhớ dài hạn cho AI.

CLAUDE.md là gì?

CLAUDE.md là file đặt ở thư mục gốc của dự án. Mỗi khi bắt đầu phiên làm việc, Claude Code tự động đọc file này và "nhớ" tất cả nội dung trong đó. Nó giống như bạn viết brief cho nhân viên mới để họ hiểu dự án ngay.

MODULE 06

Dự Án Thực Hành Full-Stack

Quy trình làm dự án full-stack với AI

Khi xây dựng dự án thực tế với Claude Code, hãy tuân thủ quy trình 8 bước:

  1. Phân tích yêu cầu — Liệt kê tất cả tính năng cần có. Dùng Plan Mode hỏi AI giúp phân tích. Kết quả: danh sách features rõ ràng.
  2. Thiết kế — Database schema, API endpoints, cấu trúc thư mục. Đây là bước quan trọng nhất — sai ở đây thì toàn bộ project lệch.
  3. Setup project — Init project, cài dependencies, cấu hình. Yêu cầu AI tạo cấu trúc folder chuẩn.
  4. Code Backend — CRUD, middleware, validation. Làm từng API, test xong mới chuyển sang API tiếp.
  5. Code Frontend — Layout, components, kết nối API. Làm từng trang, không làm 1 lúc tất cả.
  6. Authentication — Đăng ký, đăng nhập, JWT, protected routes. Làm sau khi CRUD chạy ổn định.
  7. Review & Test — Kiểm tra toàn bộ, fix bug, tối ưu. Yêu cầu AI review code và viết test.
  8. Deploy — Chuẩn bị environment, deploy lên cloud.

Thiết kế Database Schema

Trước khi code, bạn cần thiết kế cơ sở dữ liệu. Prompt mẫu:

"Thiết kế database schema cho ứng dụng Task Manager với các yêu cầu:
- User có thể đăng ký/đăng nhập
- Mỗi User có nhiều Projects
- Mỗi Project có nhiều Tasks
- Task có trạng thái: todo, in_progress, done
- Task có độ ưu tiên: low, medium, high

Hãy tạo SQL schema với các bảng, foreign keys, và indexes.
Dùng PostgreSQL syntax."

Sau khi AI trả về, bạn review: các bảng đã có đủ trường chưa? Relationships có đúng không? Có cần thêm index nào không?

Backend: CRUD và Middleware

Khi code backend, chia thành nhiều phiên nhỏ:

Phiên 1: Setup và Model

"Tạo Express server với cấu trúc:
server/
  index.js        # Entry point
  config/db.js    # Database connection
  models/User.js  # User model
  models/Task.js  # Task model
Dùng PostgreSQL với thư viện pg. Thiết kế theo pattern đã thống nhất."

Phiên 2: CRUD cho 1 resource

"Tạo CRUD API cho Tasks:
- GET /api/tasks — lấy danh sách, có pagination và filter theo status
- GET /api/tasks/:id — lấy chi tiết
- POST /api/tasks — tạo mới, validate: title bắt buộc, status mặc định 'todo'
- PUT /api/tasks/:id — cập nhật
- DELETE /api/tasks/:id — xoá (soft delete)
Tạo riêng: route file, controller file, validation middleware."

Middleware quan trọng

  • Error handling middleware: Bắt tất cả lỗi, trả về format nhất quán
  • Auth middleware: Kiểm tra JWT token
  • Validation middleware: Kiểm tra input trước khi xử lý
  • CORS middleware: Cho phép frontend gọi API

Frontend: Components và Kết nối API

Ở frontend, làm theo thứ tự: Layout → Components tĩnh → Kết nối API → State management.

"Tạo component TaskList trong src/components/TaskList.jsx:
- Gọi API GET /api/tasks để lấy danh sách
- Hiển thị dạng table với các cột: Title, Status, Priority, Created
- Có loading state và error state
- Có nút 'Thêm Task' mở modal tạo mới
- Dùng fetch API (không cài axios)
- Styling dùng CSS module hoặc CSS thuần theo pattern của dự án"
Mẹo: Làm xong phần hiển thị trước (với dữ liệu giả), test layout OK rồi mới kết nối API thực. Như vậy nếu API lỗi, bạn biết lỗi ở đâu.

Authentication: JWT

Quy trình authentication với JWT:

  1. Đăng ký: User gửi email + password → Server hash password (bcrypt) → Lưu vào DB → Trả về thành công
  2. Đăng nhập: User gửi email + password → Server kiểm tra email tồn tại → So sánh password với hash → Tạo JWT token → Trả về token
  3. Protected route: Frontend gửi token trong header Authorization: Bearer <token> → Middleware kiểm tra token → Nếu hợp lệ: cho phép truy cập → Nếu không: trả về 401
// Ví dụ auth middleware
const authMiddleware = (req, res, next) => {
    const token = req.headers.authorization?.split(' ')[1];
    if (!token) return res.status(401).json({ error: 'Không có token' });

    try {
        const decoded = jwt.verify(token, process.env.JWT_SECRET);
        req.user = decoded;
        next();
    } catch (err) {
        res.status(401).json({ error: 'Token không hợp lệ' });
    }
};

MODULE 07

Skill & Workflow

Skill là gì?

Skill trong Claude Code là workflow được đóng gói thành file, có thể tái sử dụng nhiều lần. Thay vì gõ lại prompt dài mỗi lần muốn làm 1 việc, bạn viết 1 lần thành Skill và chạy bằng lệnh ngắn.

Tưởng tượng Skill như macro hoặc script — nhưng thay vì code, nó là tập hợp chỉ dẫn cho AI.

Cấu trúc file Skill

Skill là các file .md đặt trong thư mục .claude/commands/ của dự án:

project/
  .claude/
    commands/
      create-crud.md      # Skill tạo CRUD
      write-test.md       # Skill viết test
      explain-code.md     # Skill giải thích code
      review.md           # Skill review code
  src/
  ...

Sau khi tạo, bạn chạy Skill bằng: /create-crud, /write-test,... ngay trong Claude Code.

Cú pháp viết Skill

Một file Skill là Markdown với chỉ dẫn cho AI. Ví dụ .claude/commands/create-crud.md:

# Tạo CRUD API

Tạo đầy đủ CRUD API cho resource được chỉ định.

## Input
- $ARGUMENTS: tên resource (ví dụ: "product", "order")

## Các bước thực hiện
1. Tạo model file trong `server/models/{Resource}.js`
   - Định nghĩa schema với các trường phù hợp
   - Export model

2. Tạo controller trong `server/controllers/{resource}Controller.js`
   - getAll: pagination, filter, sort
   - getById: kiểm tra tồn tại
   - create: validate input
   - update: kiểm tra tồn tại, validate
   - delete: soft delete (set deletedAt)

3. Tạo routes trong `server/routes/{resource}Routes.js`
   - GET /{resources} -> getAll
   - GET /{resources}/:id -> getById
   - POST /{resources} -> create
   - PUT /{resources}/:id -> update
   - DELETE /{resources}/:id -> delete

4. Thêm route vào server/index.js

## Quy tắc
- Dùng try-catch trong mọi controller
- Trả về JSON format: { success, data, message }
- Status code đúng chuẩn: 200, 201, 400, 404, 500

Chạy: gõ /create-crud product và AI sẽ tự động làm tất cả các bước trên.

Các Skill hữu ích nên tạo

Skill CRUD

Tự động tạo model, controller, route, validation cho bất kỳ resource nào. Tiết kiệm 30–60 phút mỗi lần.

Skill Unit Test

Truyền vào file, AI tự động viết test cho tất cả các function trong đó. Bao gồm happy path và edge cases.

Skill Explain

AI đọc file và giải thích từng phần: mục đích, logic, dependencies. Hữu ích khi đọc code người khác.

Skill Review

AI review code theo checklist: security, performance, readability, error handling. Đưa ra gợi ý cải thiện.

Kết hợp nhiều Skill: Quy trình hoàn chỉnh

Sức mạnh thực sự của Skill là khi bạn kết hợp chúng thành quy trình:

# Quy trình thêm feature mới:

1. /plan "Thêm chức năng comment cho blog posts"
   → AI lên kế hoạch chi tiết

2. /create-crud comment
   → AI tạo model, controller, route

3. /write-test server/controllers/commentController.js
   → AI viết unit test

4. /review server/controllers/commentController.js
   → AI review code và gợi ý cải thiện

# Tổng thời gian: 15–20 phút thay vì 2–3 giờ

Chia sẻ Skill qua Git

Vì Skill nằm trong .claude/commands/ của dự án, bạn có thể:

  • Commit vào git: Cả team dùng chung Skill, đảm bảo nhất quán
  • Copy giữa dự án: Skill CRUD tạo cho project A dùng được cho project B (chỉ cần chỉnh template)
  • Tạo bộ sưu tập: Theo thời gian, bạn sẽ có "kho" Skill cho nhiều loại công việc
Mẹo: Bắt đầu với 2–3 Skill đơn giản. Sau mỗi dự án, review và cải thiện chúng. Skill tốt nhất là Skill được tinh chỉnh qua nhiều lần sử dụng thực tế.
MODULE 08

Git, Debug & Rewind

Git cơ bản với Claude Code

Claude Code tích hợp sâu với Git. Bạn có thể yêu cầu AI thực hiện các thao tác Git trực tiếp:

# Khởi tạo Git
"Init git repo, tạo .gitignore cho Node.js project"

# Commit
"Commit những thay đổi hiện tại với message mô tả"

# AI sẽ tự động:
# 1. git add các file phù hợp (không add .env, node_modules)
# 2. Viết commit message chuẩn
# 3. Thực hiện commit

Conventional Commits

Conventional Commits là quy ước viết commit message giúp lịch sử Git rõ ràng và có thể tự động hoá:

PrefixKhi nào dùngVí dụ
feat:Thêm tính năng mớifeat: add user registration form
fix:Sửa lỗifix: resolve login timeout issue
refactor:Sửa code mà không đổi chức năngrefactor: extract validation logic
docs:Thêm/sửa tài liệudocs: update API documentation
test:Thêm/sửa testtest: add unit tests for auth
chore:Công việc bảo trìchore: update dependencies
style:Định dạng code, không đổi logicstyle: fix indentation

Định nghĩa trong CLAUDE.md

## Git Convention
- Dùng Conventional Commits: feat|fix|refactor|docs|test|chore
- Commit message bằng tiếng Anh, ngắn gọn (<72 ký tự)
- Mỗi commit chỉ làm 1 việc (atomic commits)
- KHÔNG commit file .env, node_modules, dist/

Giải quyết Merge Conflict với AI

Khi gặp merge conflict, thay vì tự đọc và sửa, bạn có thể nhờ AI:

"Đang có merge conflict trong file src/components/UserList.jsx.
Branch main có version mới của function fetchUsers dùng pagination.
Branch feature/search có version thêm chức năng search.
Hãy merge cả 2 thay đổi: giữ pagination và thêm search."

AI sẽ đọc cả 2 version, hiểu ý đồ của từng bên, và gộp lại hợp lý. Bạn chỉ cần review kết quả.

Lưu ý: Luôn giải thích cho AI ý đồ của mỗi bên trong conflict. Nếu chỉ nói "giải quyết conflict", AI có thể chọn sai bên.

Rewind — Quay lại code quá khứ

Rewind là tính năng của Claude Code cho phép quay lại trạng thái code trước đó trong phiên làm việc. Nó khác với git reset:

Rewind (Claude Code)git reset
Phạm viNhững thay đổi AI làm trong phiên hiện tạiBất kỳ commit nào trong lịch sử Git
Cách dùngChọn điểm trong timeline phiên làm việcgit reset --hard <commit>
An toànRất an toàn, chỉ ảnh hưởng phiên hiện tạiNguy hiểm nếu dùng sai, mất code
Khi nào dùngAI làm sai, muốn quay lại bước trướcMuốn bỏ commit đã push/chưa push
Mẹo: Commit thường xuyên! Mỗi khi AI làm xong 1 bước và bạn đã review OK, hãy commit ngay. Như vậy nếu bước sau AI làm hỏng, bạn có thể quay lại commit trước đó an toàn.

Debug hiệu quả với AI

Debug là kỹ năng quan trọng nhất khi làm việc với AI. Quy trình debug chuẩn:

  1. Mô tả bug rõ ràng 
    "Khi bấm nút 'Save' trong form tạo Task, trang bị reload nhưng
Task không được lưu vào database. Console hiện lỗi 400 Bad Request."
  2. Cung cấp error log — Copy chính xác lỗi từ console, terminal, hoặc log file. AI cần thấy lỗi gốc, không phải mô tả của bạn.
  3. Thu hẹp phạm vi 
    "Lỗi xảy ra ở API POST /api/tasks. Tôi đã kiểm tra:
- Frontend gửi đúng dữ liệu (đã log request body)
- Server nhận được request (có log 'Request received')
- Lỗi xảy ra ở bước validation — req.body.title là undefined"
  4. Kiểm tra giả thuyết — Yêu cầu AI đưa ra giả thuyết và kiểm tra từng cái: 
    "Giả thuyết 1: Frontend không gửi Content-Type header
Giả thuyết 2: Body parser chưa được cấu hình
Giả thuyết 3: Tên field không khớp giữa FE và BE
Hãy kiểm tra từng giả thuyết."
  5. Xác nhận fix — Sau khi AI sửa, test lại. Nếu vẫn lỗi, quay lại bước 1 với thông tin mới.

Tổng Kết Khoá Học

Sau 8 module, bạn đã có đầy đủ kiến thức để làm việc hiệu quả với Claude Code:

  • Tư duy đúng: Bạn là kiến trúc sư, AI là thợ xây. Bạn review, AI thực thi
  • Quy trình: Plan → Code → Review → Test → Commit

Bước tiếp theo: Áp dụng ngay vào dự án thực tế. Bắt đầu với dự án nhỏ, làm quen quy trình, rồi tăng dần độ phức tạp. Mỗi dự án hoàn thành, bạn lại giỏi hơn — không chỉ về code, mà về cách làm việc với AI.
