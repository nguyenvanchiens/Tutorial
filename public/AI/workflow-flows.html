2 LUỒNG CHUẨN

Vòng lặp code + 2 luồng kết

Hai luồng làm việc theo vai trò, dùng chung một vòng lặp code ở giữa — chỉ khác phần kết. Mỗi bước ghi sẵn trigger để gõ thẳng cho skill.

Mục lục

🔧 Phần chung — Vòng lặp code 🅰️ Luồng CÓ Merge Request 🅱️ Luồng KHÔNG có MR
🅰️ LUỒNG CÓ MR
Team GitLab chuẩn
Có reviewer thứ 2. Developer (Pro) code nhẹ, mọi review nặng dồn cho reviewer (Pro Max) trên MR.
🅱️ LUỒNG KHÔNG MR
Dự án nhỏ / commit thẳng
Không ai review hộ → bạn tự gánh. Bắt buộc review toàn branch trước khi nhập code.
🔧
Phần chung — Vòng lặp code
Cả 2 luồng đều giống nhau · member làm hằng ngày, nhẹ token
1
Tạo nhánh từ task
Skill đề xuất tên nhánh, hỏi base (main/dev), tạo feature/WRA-40-.... (Hoặc bạn tự tạo/nhảy nhánh bằng SourceTree cũng được.)
create branch from task WRA-40 giới hạn domain account
2
Paste mô tả task Jira
Dán mô tả task → Claude sinh code.
3
Review thay đổi vừa rồi
Soi nhanh phần code mới sinh, fix issue tại chỗ.
review the last change
⟲ Lặp 2 ↔ 3 tới khi xong 1 mảng việc
4
Commit & push
Commit local, skill hỏi bạn rồi mới push.
commit and push
⟲ Lặp 2 → 4 cho từng mảng việc
Đây là phần member làm hằng ngày — toàn review nhẹ, tốn rất ít token.
🅰️
Luồng CÓ Merge Request
Team GitLab chuẩn · phân vai Developer ↔ Reviewer
DEVELOPER member · Pro
Chạy trọn vòng lặp code (bước 1–4) ở phần chung, sau đó:
5
Tạo Merge Request
Skill xác định target (main/dev), tạo MR, trả về !N.
create a merge request
⚠️ Member KHÔNG cần chạy "review the whole branch" — để dành cho reviewer.
REVIEWER bạn · Pro Max
6
Review trên MR
Review full diff của MR (inline, KHÔNG cần nhảy nhánh).
review the MR !<N>
  • MR thường → đủ rồi, sang bước 7.
  • MR to / hiểm → (SourceTree) nhảy sang nhánh MR → chạy review the whole branch (3-agent, đọc full file) → quay lại.
7
Đẩy kết quả review lên MR
Post comment + APPROVE / REQUEST_CHANGES lên GitLab.
post review result to the MR
DEVELOPER member
8
Fix toàn bộ issue
Fix → đề xuất commit msg → đợi bạn xác nhận.
fix all issues
9
(Xác nhận) commit & push
Push các fix lên, MR tự cập nhật.
commit and push
⟲ Lặp 6 → 9 nếu còn REQUEST_CHANGES — lần sau skill tự đối chiếu issue cũ
MERGE
10
Merge request
Check approve + CI → merge --squash, xoá nhánh.
merge the request
💰 Token: member chỉ tốn ở bước 1–4 và 8–9 (toàn review nhẹ). Mọi review nặng dồn vào bạn (Max) ở bước 6.
🅱️
Luồng KHÔNG có Merge Request
Dự án nhỏ / commit thẳng nhánh tích hợp · bạn tự gánh review
Không có reviewer thứ 2 → bạn tự review, nên phải soi kỹ trước khi nhập code.
DEVELOPER = REVIEWER một mình bạn
Chạy trọn vòng lặp code (bước 1–4) ở phần chung, sau đó:
5
Review toàn branch — BẮT BUỘC
3-agent đọc full file. Vì không ai review hộ, đây là lưới an toàn cuối. Skill hỏi base main/dev (không có MR để tự dò).
review the whole branch
6
Commit & push
Commit các fix từ bước 5 (nếu có).
commit and push
7
Tích hợp vào base — làm tay
KHÔNG có trigger glab. (SourceTree) merge nhánh feature vào main/dev, hoặc push thẳng theo cách dự án bạn vẫn làm.
🔑 Khác biệt cốt lõi với luồng A: ở luồng A bạn skip "review the whole branch" phía developer (reviewer lo); ở luồng B không được skip vì bạn là người duy nhất review.
