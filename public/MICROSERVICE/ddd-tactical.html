DDD cho Microservices

Domain-Driven Design là la bàn để vẽ ranh giới service đúng. Bounded context → service boundary, aggregate → đơn vị nhất quán, domain event → giao tiếp. Học tactical patterns với code C# thực chiến.

Bounded Context = Service Boundary

Bounded Context là ranh giới ngôn ngữ: cùng một từ mang nghĩa khác nhau ở các context khác nhau. Đây là ứng cử viên tự nhiên nhất cho ranh giới service — không phải bảng dữ liệu, không phải layer kỹ thuật.

"Product" trong Catalog

Có tên, mô tả, hình ảnh, danh mục, thuộc tính SEO, đánh giá. Quan tâm: trình bày & tìm kiếm.

"Product" trong Inventory

Chỉ có SKU, số lượng tồn, vị trí kho, ngưỡng reorder. Không quan tâm mô tả hay hình ảnh.

📐 Bài học: Cùng "Product" nhưng 2 model hoàn toàn khác → 2 bounded context → 2 service. Cố gò chung 1 "God Product entity" là sai lầm kinh điển dẫn tới coupling.

Building blocks — Tactical DDD

🧩 Entity

Có identity (Id) bền vững qua thời gian. Hai entity bằng nhau khi cùng Id, dù thuộc tính khác. Vd: Order, Customer.

💎 Value Object

Không có identity, định nghĩa bởi giá trị. Bất biến (immutable). Vd: Money, Address, DateRange. Hai cái bằng nhau khi mọi field bằng nhau.

📦 Aggregate

Cụm entity + value object được xem là một đơn vị cho thay đổi dữ liệu. Có 1 root duy nhất là cổng vào.

👑 Aggregate Root

Entity duy nhất bên ngoài được phép tham chiếu. Bảo vệ invariant của cả aggregate. Là ranh giới transaction.

⚡ Domain Event

Sự kiện nghiệp vụ đã xảy ra trong quá khứ: OrderPlaced, PaymentReceived. Cách aggregate "báo" cho phần còn lại.

🏭 Repository

Trừu tượng lưu trữ theo aggregate root (1 repo / 1 aggregate). Load và save toàn bộ aggregate như một khối.

Value Object trong C#

record của C# là công cụ tuyệt vời cho value object: bất biến + so sánh theo giá trị sẵn có.

// Money — value object bất biến, tự bảo vệ invariant
public readonly record struct Money
{
    public decimal Amount { get; }
    public string Currency { get; }

    public Money(decimal amount, string currency)
    {
        if (amount < 0) throw new ArgumentException("Số tiền không âm");
        if (string.IsNullOrWhiteSpace(currency)) throw new ArgumentException("Thiếu currency");
        Amount = amount; Currency = currency;
    }

    public static Money operator +(Money a, Money b)
    {
        if (a.Currency != b.Currency)
            throw new InvalidOperationException("Khác loại tiền tệ");
        return new Money(a.Amount + b.Amount, a.Currency);
    }
}

Aggregate & Aggregate Root — ví dụ Order đầy đủ

Order là aggregate root; OrderLine là entity bên trong, chỉ truy cập qua Order. Mọi invariant (tổng tiền, trạng thái hợp lệ) được bảo vệ trong root.

public sealed class Order : AggregateRoot  // AggregateRoot giữ list domain event
{
    private readonly List<OrderLine> _lines = new();

    public Guid Id { get; private set; }
    public Guid CustomerId { get; private set; }
    public OrderStatus Status { get; private set; }
    public IReadOnlyList<OrderLine> Lines => _lines.AsReadOnly();
    public Money Total => _lines.Aggregate(
        new Money(0, "VND"), (sum, l) => sum + l.LineTotal);

    private Order() { }  // cho EF Core

    // Factory: cách DUY NHẤT tạo Order hợp lệ
    public static Order Place(Guid customerId, IEnumerable<OrderLine> lines)
    {
        var order = new Order
        {
            Id = Guid.CreateVersion7(),
            CustomerId = customerId,
            Status = OrderStatus.Pending
        };
        order._lines.AddRange(lines);
        if (order._lines.Count == 0)
            throw new DomainException("Đơn hàng phải có ít nhất 1 dòng");

        // raise domain event — chưa publish, chỉ ghi vào aggregate
        order.Raise(new OrderPlaced(order.Id, order.CustomerId, order.Total));
        return order;
    }

    public void Confirm()
    {
        if (Status != OrderStatus.Pending)
            throw new DomainException("Chỉ xác nhận đơn đang Pending");
        Status = OrderStatus.Confirmed;
        Raise(new OrderConfirmed(Id));
    }
}
💡 Quy tắc aggregate: (1) Mỗi transaction chỉ thay đổi một aggregate. (2) Tham chiếu aggregate khác bằng Id, không bằng object. (3) Aggregate root là ranh giới nhất quán mạnh — mọi thứ ngoài nó là eventual consistency.

Domain Event — phát & xử lý

// Domain event — record bất biến, "đã xảy ra"
public record OrderPlaced(Guid OrderId, Guid CustomerId, Money Total) : IDomainEvent;

// Sau khi SaveChanges thành công, dispatch event đã raise
public class OrderDbContext : DbContext
{
    private readonly IDomainEventDispatcher _dispatcher;

    public override async Task<int> SaveChangesAsync(CancellationToken ct = default)
    {
        var events = ChangeTracker.Entries<AggregateRoot>()
            .SelectMany(e => e.Entity.DomainEvents)
            .ToList();

        var result = await base.SaveChangesAsync(ct);  // commit trước
        await _dispatcher.DispatchAsync(events, ct);    // rồi mới phát
        return result;
    }
}
⚠️ Domain event ≠ Integration event. Domain event ở trong bounded context (in-process). Khi cần báo cho service khác, map sang integration event và đẩy qua Outbox → broker. Đừng để domain event nội bộ rò rỉ ra ngoài context.

Context Mapping — quan hệ giữa các context

Khi vẽ xong các bounded context, bạn phải định nghĩa chúng quan hệ với nhau thế nào. Đây là context map — bản đồ chính trị + kỹ thuật của hệ thống.

Quan hệÝ nghĩa
Partnership2 team phối hợp chặt, thành/bại cùng nhau, đồng bộ release
Customer / SupplierDownstream phụ thuộc upstream; upstream cân nhắc nhu cầu downstream
ConformistDownstream buộc theo model của upstream (vd dùng API bên thứ 3), không thương lượng
Anti-Corruption Layer (ACL)Downstream dựng lớp dịch để KHÔNG bị model upstream làm bẩn domain của mình
Open Host Service + Published LanguageUpstream phơi API/event chuẩn hoá, công khai cho nhiều consumer
Shared Kernel2 context chia sẻ 1 phần model nhỏ — dùng dè dặt, tạo coupling

Anti-Corruption Layer (ACL) — code thực chiến

Bài toán: Shipping service phải gọi 1 carrier API legacy với model xấu, đầy mã viết tắt khó hiểu. ACL dịch model bẩn của họ sang domain sạch của ta.

// Model bẩn từ carrier bên ngoài (không kiểm soát được)
public class CarrierTrackResp
{
    public string sts { get; set; }    // "D"=delivered, "T"=transit, "X"=fail
    public string loc_cd { get; set; }
    public long ts_epoch { get; set; }
}

// ACL: cô lập sự "bẩn" tại đây, domain bên trong luôn sạch
public sealed class CarrierAntiCorruptionLayer(ILegacyCarrierClient client)
{
    public async Task<ShipmentStatus> GetStatusAsync(TrackingNumber tn)
    {
        CarrierTrackResp raw = await client.TrackAsync(tn.Value);

        // dịch sang ngôn ngữ domain của ta — đây là toàn bộ điểm của ACL
        var status = raw.sts switch
        {
            "D" => DeliveryState.Delivered,
            "T" => DeliveryState.InTransit,
            "X" => DeliveryState.Failed,
            _   => DeliveryState.Unknown
        };
        return new ShipmentStatus(status,
            Location.FromCode(raw.loc_cd),
            DateTimeOffset.FromUnixTimeSeconds(raw.ts_epoch));
    }
}
📦 Lợi ích: Nếu carrier đổi format (vd sts → status_code), bạn chỉ sửa một nơi — ACL. Domain Shipping không hề biết carrier tồn tại.

Checklist — Áp dụng DDD đúng

✅ Strategic (vẽ ranh giới)

  • Đã xác định các bounded context bằng ngôn ngữ nghiệp vụ, không phải bảng DB
  • Có context map ghi rõ quan hệ (ACL, Conformist, OHS...)
  • Dùng EventStorming với domain expert để khám phá context
  • Mỗi service = 1 bounded context (hoặc 1 context = nhiều service nếu cần)

✅ Tactical (code)

  • Aggregate nhỏ, root bảo vệ invariant, tham chiếu chéo bằng Id
  • Value object bất biến cho khái niệm không có identity
  • 1 transaction = 1 aggregate
  • Domain event dispatch sau commit; map sang integration event khi ra ngoài
  • ACL bọc mọi tích hợp bên ngoài/legacy
