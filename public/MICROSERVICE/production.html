Microservices ở Production

Docker, Kubernetes, observability, security, performance — tất cả những gì cần để chạy 50+ service ổn định.

1. Containerize — Dockerfile chuẩn

Mỗi service một image. Multi-stage build → image nhỏ, build nhanh.

# --- Build stage ---
FROM mcr.microsoft.com/dotnet/sdk:9.0 AS build
WORKDIR /src
COPY *.csproj ./
RUN dotnet restore
COPY . .
RUN dotnet publish -c Release -o /app /p:PublishTrimmed=true

# --- Runtime stage (nhỏ hơn 5×) ---
FROM mcr.microsoft.com/dotnet/aspnet:9.0-alpine
WORKDIR /app
COPY --from=build /app .
USER $APP_UID            # non-root, security
EXPOSE 8080
ENTRYPOINT ["dotnet", "OrderService.dll"]
💡 Best practices: non-root user, .dockerignore, multi-stage, alpine/distroless, healthcheck, image scan (Trivy/Snyk).

2. Docker Compose — Local dev nhanh

# docker-compose.yml
services:
  rabbitmq:
    image: rabbitmq:3.13-management
    ports: ["5672:5672", "15672:15672"]

  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: dev
    volumes: [pgdata:/var/lib/postgresql/data]

  order-service:
    build: ./services/order
    depends_on: [postgres, rabbitmq]
    environment:
      ConnectionStrings__OrderDb: "Host=postgres;Database=order;Username=postgres;Password=dev"
    ports: ["5001:8080"]

  inventory-service:
    build: ./services/inventory
    depends_on: [rabbitmq]
    ports: ["5002:8080"]

volumes: { pgdata: {} }

→ docker compose up → cả hệ chạy local trong 30 giây.

3. Kubernetes — Production runtime

📦 Pod

Đơn vị chạy nhỏ nhất. 1 hoặc nhiều container chia sẻ network/storage.

🚀 Deployment

Quản lý replica của Pod. Rolling update, rollback.

🌐 Service

Tên DNS ổn định cho 1 nhóm Pod. Load balance nội bộ.

🚪 Ingress

Cổng vào từ ngoài cluster, route theo host/path.

⚙️ ConfigMap / Secret

Config & secret tách khỏi image, mount vào pod.

📊 HPA

Auto-scale theo CPU/RAM/custom metric.

Deployment manifest tối thiểu

apiVersion: apps/v1
kind: Deployment
metadata: { name: order-service }
spec:
  replicas: 3
  selector: { matchLabels: { app: order } }
  template:
    metadata: { labels: { app: order } }
    spec:
      containers:
      - name: app
        image: registry/order-service:v1.2.3
        ports: [{ containerPort: 8080 }]
        resources:
          requests: { cpu: 100m, memory: 128Mi }
          limits:   { cpu: 500m, memory: 512Mi }
        livenessProbe:
          httpGet: { path: /health/live, port: 8080 }
          initialDelaySeconds: 10
        readinessProbe:
          httpGet: { path: /health/ready, port: 8080 }
        env:
        - name: ConnectionStrings__OrderDb
          valueFrom: { secretKeyRef: { name: order-secrets, key: db } }
---
apiVersion: v1
kind: Service
metadata: { name: order-service }
spec:
  selector: { app: order }
  ports: [{ port: 80, targetPort: 8080 }]
📦 Đóng gói: Helm chart hoặc Kustomize. GitOps qua ArgoCD/Flux để mọi thay đổi auditable qua git.

4. Health Check — 3 loại

LoạiEndpointMục đích
Liveness/health/liveApp còn sống không? Fail → K8s kill & restart
Readiness/health/readySẵn sàng nhận traffic? Fail → K8s không route traffic vào
Startup/health/startApp đang khởi động (dùng cho app khởi động chậm)
 
// .NET
builder.Services.AddHealthChecks()
    .AddNpgSql(connStr, name: "db", tags: ["ready"])
    .AddRabbitMQ(rabbitUri, name: "mq", tags: ["ready"]);

app.MapHealthChecks("/health/live");
app.MapHealthChecks("/health/ready", new() { Predicate = c => c.Tags.Contains("ready") });

5. Observability — 3 trụ cột

📝 Logging

Mục tiêu: trả lời "chuyện gì xảy ra".

  • Cấu trúc JSON, không text thô
  • Bao gồm traceId, userId, service
  • Tập trung qua Loki / ELK
  • Tools: Serilog (.NET), zap (Go), pino (Node)

📊 Metrics

Mục tiêu: "hệ thống có bình thường không".

  • RED: Rate, Errors, Duration
  • USE: Utilization, Saturation, Errors (cho hạ tầng)
  • Prometheus scrape, Grafana visualize
  • Alert khi: P95 > 500ms, error rate > 1%

🔍 Tracing

Mục tiêu: "request đi qua đâu, chậm ở đâu".

  • Mỗi request có trace-id propagate qua mọi service
  • Span = mỗi đoạn xử lý
  • OpenTelemetry → Jaeger / Tempo
  • Bắt buộc khi > 5 service

OpenTelemetry .NET — setup 1 lần dùng cả 3

builder.Services.AddOpenTelemetry()
  .WithTracing(t => t
    .AddAspNetCoreInstrumentation()
    .AddHttpClientInstrumentation()
    .AddNpgsql()
    .AddOtlpExporter())
  .WithMetrics(m => m
    .AddAspNetCoreInstrumentation()
    .AddPrometheusExporter())
  .WithLogging(l => l.AddOtlpExporter());

6. Distributed Tracing — Cứu mạng khi debug

Request đi qua: Gateway → Order → Payment → Inventory → DB. Mỗi đoạn 1 span. Khi chậm, mở Jaeger thấy ngay span nào nuốt 80% thời gian.

trace-id: abc-123 (tổng 800ms)
├─ [Gateway]           5ms
├─ [OrderService.POST] 650ms   // ⚠️ chậm ở đây
│   ├─ [Postgres SELECT] 600ms  // 👈 thiếu index!
│   └─ [RabbitMQ publish] 5ms
├─ [InventoryService]  80ms
└─ [PaymentService]    60ms
💡 Insight: Không có tracing thì khi user complain "chậm", bạn phải đoán. Có tracing — chỉ ra được service & query thủ phạm trong 30 giây.

7. CI/CD pipeline cho Microservices

  1. PR mở → chạy lint, unit test, integration test (Testcontainers).
  2. Merge → build Docker image, tag service:<sha>, push registry, scan vulnerability.
  3. Deploy DEV tự động → smoke test.
  4. Deploy STAGING qua ArgoCD (GitOps) — đổi tag trong manifest repo → ArgoCD sync.
  5. Deploy PROD: canary 5% → 25% → 50% → 100%, rollback tự động nếu error rate tăng.
📦 Tools: GitHub Actions, GitLab CI, Jenkins, ArgoCD, Flux, Spinnaker, Argo Rollouts (canary/blue-green).

8. Security — bắt buộc ở production

🔐 Service-to-service

  • mTLS — mọi call nội bộ encrypt + xác thực 2 chiều (Istio/Linkerd làm sẵn)
  • JWT propagate qua header, mỗi service verify
  • Network Policy — chỉ service nào được nói chuyện với service nào

🔑 Secret & Auth

  • Vault / AWS Secrets Manager — không nhồi vào image
  • OAuth2 / OIDC — Keycloak, Auth0, Azure AD
  • Short-lived token (15 phút) + refresh token
  • API key có scope, rotation định kỳ

🛡️ Image & Cluster

  • Container scan: Trivy, Snyk
  • SBOM (Software Bill of Materials)
  • Pod Security Standards: non-root, read-only fs
  • RBAC trong K8s — least privilege

🚨 Edge

  • WAF ở Gateway (Cloudflare, AWS WAF)
  • Rate limit theo user/IP
  • DDoS protection
  • OWASP Top 10 review định kỳ

10. Disaster Recovery & Reliability

🎯 SLO & SLI

Đặt mục tiêu rõ: 99.9% uptime, P95 latency < 300ms. Đo qua metric, có error budget.

💾 Backup

DB backup hằng ngày, test restore hằng tháng. Không test = không có backup.

🌍 Multi-AZ / Multi-Region

K8s cluster trải qua nhiều AZ. Sạch sẽ cho HA. Multi-region khi đã giàu kinh nghiệm.

🧪 Chaos Engineering

Chủ động kill pod (Chaos Mesh, Litmus) → kiểm chứng resilience. Netflix Chaos Monkey là kinh điển.

📜 Runbook

Mỗi alert có document: "khi alert này nổ thì làm gì". Tránh on-call ngơ ngác lúc 3h sáng.

📋 Postmortem

Sau incident: blameless postmortem. Tập trung tìm process & system fix, không trách cá nhân.

Production Readiness Checklist

Trước khi đẩy 1 service lên production

  • ✅ Dockerfile multi-stage, image < 200MB
  • ✅ Health checks (live/ready)
  • ✅ Resource requests/limits
  • ✅ HPA cấu hình
  • ✅ Logs JSON structured, kèm traceId
  • ✅ Metrics endpoint /metrics
  • ✅ OpenTelemetry trace export
  • ✅ Secret từ Vault, không trong code
  • ✅ DB migration tự động (idempotent)
  • ✅ Graceful shutdown (SIGTERM)
  • ✅ Retry + Circuit Breaker cho call ngoài
  • ✅ Idempotency cho POST quan trọng
  • ✅ Outbox cho event publish
  • ✅ Network policy & mTLS
  • ✅ Có alert + runbook
  • ✅ Có dashboard Grafana
  • ✅ Có integration test trong CI
  • ✅ Tài liệu README, openapi.yaml
