1. Cài Đặt & Cấu Hình Ban Đầu

Cài đặt Sourcetree

  1. Tải Sourcetree từ sourcetreeapp.com
  2. Cài đặt và đăng ký tài khoản Atlassian (miễn phí)
  3. Chọn Git làm version control (bỏ chọn Mercurial nếu không cần)
  4. Cấu hình tên và email: Tools > Options > General

Kết nối với GitHub

  1. Vào Tools > Options > Authentication
  2. Nhấn Add, chọn Hosting: GitHub
  3. Auth Type: chọn OAuth hoặc Personal Access Token
  4. Với PAT: tạo token tại GitHub > Settings > Developer Settings > Personal Access Tokens
  5. Tick quyền: repo, workflow, read:org

2. Clone Repository

Clone từ GitHub

  1. Trên GitHub, nhấn nút Code > copy URL (HTTPS hoặc SSH)
  2. Trong Sourcetree: File > Clone / New hoặc nhấn + Clone
  3. Dán URL vào ô Source Path / URL
  4. Chọn thư mục lưu tại Destination Path
  5. Nhấn Clone và đợi hoàn tất

Mở repo có sẵn trên máy

  1. File > Open hoặc kéo thả thư mục vào Sourcetree
  2. Repo sẽ xuất hiện ở tab bên trái
Tip: Có thể clone nhiều repo cùng lúc bằng tab Remote - chọn tài khoản GitHub và thấy danh sách repo

3. Các Thao Tác Cơ Bản

3.1 Stage, Commit

Stage (chọn file để commit)

  • Vào tab File Status (góc trái dưới)
  • Unstaged files: danh sách file thay đổi
  • Tick chọn từng file hoặc nhấn Stage All
  • Unstage: tick bỏ chọn hoặc nhấn Unstage All
  • Xem thay đổi: click vào file để thấy diff bên phải

Commit

  • Sau khi stage, nhập commit message ở ô phía dưới
  • Nhấn Commit (hoặc Ctrl+Enter)
  • Commit chỉ lưu LOCAL, chưa lên GitHub
Quy tắc commit message:
feat: thêm tính năng mới
fix: sửa lỗi đăng nhập
docs: cập nhật README
refactor: tối ưu code

4. Quản Lý Branch (Nhánh)

Tạo branch mới

  1. Nhấn nút Branch trên toolbar
  2. Nhập tên branch: vd feature/login-page
  3. Tick Checkout New Branch để tự động chuyển sang
  4. Nhấn Create Branch

Chuyển branch (Checkout)

  • Panel trái: dưới Branches, double-click vào tên branch
  • Branch hiện tại sẽ có chữ đậm và icon tròn
  • Lưu ý: Phải commit hoặc stash thay đổi trước khi checkout

Xóa branch

  • Click phải vào branch > Delete branch
  • Tick Force delete nếu branch chưa merge
  • Xóa remote branch: click phải vào branch dưới Remotes/origin > Delete

Quy tắc đặt tên branch

  • feature/tên-tính-năng - tính năng mới
  • bugfix/mô-tả-lỗi - sửa lỗi
  • hotfix/vấn-đề-gấp - sửa khẩn cấp trên production
  • release/v1.0.0 - chuẩn bị release

5. Merge (Gộp Nhánh)

Merge branch

  1. Checkout sang branch nhận (vd: main)
  2. Click phải vào branch muốn merge > Merge [branch] into current branch
  3. Nếu không có conflict: merge tự động thành công
  4. Push lên GitHub sau khi merge

Xử lý Merge Conflict

  1. Khi conflict xảy ra, file sẽ hiện màu cam/vàng
  2. Click phải vào file > Resolve Conflicts
  3. Chọn: Mine (giữ của bạn), Theirs (lấy của người khác), hoặc Open External Merge Tool
  4. Sau khi resolve: Mark Resolved
  5. Stage và commit lại
Tip: Dùng VS Code làm merge tool: Tools > Options > Diff > External Diff/Merge > Custom trỏ đến VS Code

6. Pull Request (PR)

Tạo Pull Request

  1. Push branch của bạn lên GitHub trước
  2. Trên GitHub: nhấn Compare & pull request (banner tự động hiện)
  3. Hoặc vào tab Pull requests > New pull request
  4. Chọn base (branch nhận, vd main) và compare (branch của bạn)
  5. Viết tiêu đề và mô tả rõ ràng
  6. Assign reviewer, label, milestone nếu cần
  7. Nhấn Create pull request

Review & Merge PR

  • Files changed: xem toàn bộ thay đổi
  • Comment trực tiếp trên dòng code
  • Approve hoặc Request changes
  • Merge options: Merge commit, Squash and merge, Rebase and merge
  • Sau khi merge: tick Delete branch để dọn dẹp

7. Stash (Cất Giữ Tạm)

Lưu stash

  • Khi cần chuyển branch nhưng chưa muốn commit
  • Nhấn nút Stash trên toolbar
  • Nhập tên mô tả (vd: "WIP login form")
  • Thay đổi được cất đi, working tree sạch

Lấy lại stash

  • Panel trái: mở mục Stashes
  • Click phải > Apply Stash (giữ stash) hoặc Pop Stash (apply và xóa)
  • Delete Stash: xóa stash không cần nữa

8. Rebase

Rebase branch

  • Đang ở branch của bạn (vd: feature/login)
  • Click phải vào main > Rebase current changes onto main
  • Git sẽ "chơi lại" commit của bạn lên đầu main
  • Lịch sử sạch hơn so với merge
Lưu ý: KHÔNG rebase branch đã push và người khác đang dùng. Chỉ rebase branch CÁ NHÂN chưa share.

Interactive Rebase

  • Click phải vào commit > Rebase children of [commit] interactively
  • Squash: gộp nhiều commit thành 1
  • Edit: sửa commit message
  • Drop: bỏ commit
  • Reorder: kéo thả đổi thứ tự commit

9. Xem Lịch Sử & Diff

Xem lịch sử commit

  • Tab History (hoặc Log/History ở giữa màn hình)
  • Hiển thị graph với các nhánh màu sắc
  • Click vào commit để xem chi tiết: author, date, message, file changed
  • Click vào file để xem diff (dòng thêm/xóa)

So sánh (Diff)

  • So sánh 2 commit: giữ Ctrl, click 2 commit > xem diff
  • So sánh với branch: click phải branch > Diff against current
  • Blame: click phải file > Annotate (hiện ai viết dòng nào)

10. Thao Tác Nâng Cao

Cherry Pick

  • Lấy 1 commit cụ thể từ branch khác
  • Click phải vào commit > Cherry Pick
  • Commit đó sẽ được copy sang branch hiện tại

Reset & Revert

  • Revert: tạo commit mới đảo ngược thay đổi (an toàn)
  • Click phải commit > Reverse commit
  • Reset: quay về commit cũ (mất thay đổi phía sau)
  • Click phải commit > Reset current branch to this commit
  • Mode: Soft (giữ staged), Mixed (giữ file, unstage), Hard (xóa hết)
Cảnh báo: Hard reset sẽ MẤT hết thay đổi chưa commit. Dùng cẩn thận!

Tag (Đánh dấu phiên bản)

  • Click phải commit > Tag
  • Nhập tên tag: vd v1.0.0
  • Push tag: Push > tick Push all tags

Submodule

  • Repository > Add Submodule
  • Nhập URL repo con và đường dẫn thư mục
  • Submodule hiện trong panel trái dưới Submodules

11. .gitignore

Cấu hình .gitignore

  • Tạo file .gitignore ở root dự án
  • Trong Sourcetree: click phải file > Ignore > chọn pattern
  • Hoặc click phải > Stop Tracking (bỏ track file đã commit)
# Ví dụ .gitignore phổ biến node_modules/ dist/ .env *.log .DS_Store bin/ obj/

13. Git Workflow Thực Tế

Quy trình làm việc hàng ngày

  1. Pull code mới nhất từ main
  2. Tạo branch mới từ main: feature/tên-việc
  3. Code và commit thường xuyên (mỗi commit 1 đơn vị công việc)
  4. Push branch lên GitHub
  5. Tạo Pull Request trên GitHub
  6. Đợi review và sửa theo feedback
  7. Merge PR vào main
  8. Xóa branch đã merge
  9. Chuyển về main và Pull lại

14. Xử Lý Lỗi Thường Gặp

Authentication failed

  • Token hết hạn: tạo lại PAT trên GitHub
  • Cập nhật trong Tools > Options > Authentication
  • Windows: xóa credential cũ trong Credential Manager

Merge conflict

  • Không hoảng, conflict là bình thường
  • Mở file conflict, tìm đoạn <<<<<<<
  • Chọn giữ phần nào, xóa markers
  • Stage file > Commit

Detached HEAD

  • Bạn đang không ở trên branch nào
  • Checkout về branch: double-click vào branch trong panel trái
  • Nếu cần giữ thay đổi: tạo branch mới trước khi checkout

Push bị rejected

  • Remote có commit mới hơn local
  • Giải pháp: Pull trước rồi Push lại
  • KHÔNG dùng Force Push trừ khi biết rõ mình đang làm gì

Tổng Kết

Thành thạo Sourcetree + GitHub = làm việc nhóm hiệu quả, quản lý code chuyên nghiệp. Thực hành mỗi ngày với các thao tác cơ bản, sau đó nâng dần lên rebase, cherry-pick, và interactive rebase.
