Món 1

Git — quản lý code

🧠 Cốt lõi cần nhớ

  • Code đi qua 3 vùng: thư mục làm việc → staging (git add) → commit (ảnh chụp lịch sử).
  • Branch = nhánh làm việc song song; làm xong merge vào nhánh chính.
  • Remote (thường tên origin) = bản trên server (GitHub/GitLab). push đẩy lên, pull kéo về.
  • Conflict xảy ra khi hai người sửa cùng chỗ — phải sửa tay rồi commit lại.

Xử lý conflict (khi merge/pull bị đụng)

# Khi Git báo "CONFLICT", mở file bị đụng — bạn sẽ thấy:
<<<<<<< HEAD
code của bạn
=======
code của người khác
>>>>>>> nhanh-kia

# 1. Sửa lại cho đúng, XOÁ hết 3 dấu <<< === >>>
git add file-da-sua        # 2. đánh dấu đã giải quyết
git commit                 # 3. hoàn tất việc merge
✓ Đã copy
Đừng hoảng khi thấy conflict — nó chỉ là Git nói "hai người sửa cùng chỗ, bạn quyết định giữ gì". Tạo file .gitignore để Git bỏ qua những thứ không nên commit (thư mục node_modules/, file .env, log…).

✍️ Tự tay làm:

  1. Tạo thư mục mới → git init → tạo 1 file → git add . → git commit -m "khởi tạo".
  2. Tạo nhánh git switch -c thu-nghiem, sửa file, commit, rồi git switch main và git merge thu-nghiem.
  3. Chạy git log --oneline --graph xem lịch sử vừa tạo.

Database & SQL

🧠 Cốt lõi cần nhớ

  • Dữ liệu ở trong bảng (hàng & cột). Khóa chính (PK) định danh mỗi hàng; khóa ngoại (FK) nối sang bảng khác.
  • Index = mục lục giúp tìm cực nhanh. Tăng tốc đọc, nhưng làm ghi chậm hơn chút → chỉ đánh vào cột hay dùng để lọc/join.
  • Transaction = nhiều lệnh chạy như một khối "được ăn cả, ngã về không" (COMMIT hoặc ROLLBACK).
  • Cạm bẫy kinh điển: N+1 query — lặp query trong vòng lặp thay vì dùng một JOIN.

⌨️ Câu lệnh thiết yếu

Món 3

HTTP & API

🧠 Cốt lõi cần nhớ

  • Một lượt gọi = Request (method + URL + headers + body) → Response (status + headers + body).
  • Method: GET lấy · POST tạo · PUT/PATCH sửa · DELETE xoá.
  • REST: mỗi tài nguyên là một URL (vd /users/42), dùng method đúng ý nghĩa.
  • Stateless: mỗi request độc lập — server không "nhớ" request trước, nên cần token/session gửi kèm.
  • Header hay gặp: Content-Type: application/json, Authorization: Bearer <token>.

📊 Bảng status code phải thuộc

✍️ Tự tay làm:

  1. Chạy curl -i https://api.github.com/users/torvalds — đọc status code & body JSON trả về.
  2. Gọi thử một URL sai để thấy 404, và thử API cần token mà không gửi để thấy 401.
  3. Nếu có app của bạn đang chạy, dùng curl -X POST tạo thử một bản ghi.
Món 4

Networking cơ bản

🧠 Cốt lõi cần nhớ

  • IP = địa chỉ của máy. Port = cổng của một dịch vụ trên máy đó. Kết hợp lại: 1.2.3.4:8080.
  • localhost = 127.0.0.1 = chính máy bạn. Vậy localhost:8080 = "dịch vụ đang mở ở cổng 8080 trên máy này". ⭐
  • DNS = danh bạ đổi tên miền (google.com) → IP.
  • Firewall chặn/mở port — lý do app "chạy mà không truy cập được từ ngoài".
⚠️ Trong Docker/k8s: các container gọi nhau bằng tên service (vd redis:6379), không phải localhost.
