🔴 Jenkins — Hướng Dẫn Chi Tiết Từ Đầu Đến Cuối

Jenkins = CI/CD server open-source phổ biến nhất thế giới. Self-hosted, tùy biến 100%, 1800+ plugins. Dùng nhiều trong enterprise và dự án cần kiểm soát hoàn toàn pipeline.

📖 Jenkins Là Gì & Khi Nào Nên Dùng?

✅ Chọn Jenkins khi:

Self-hosted: Cần kiểm soát hoàn toàn server CI/CD, chạy on-premise
Enterprise: Dự án lớn, security policy nghiêm ngặt, air-gapped network
Complex pipelines: Pipeline phức tạp, nhiều stage, parallel builds
Multi-platform: Build cho Windows + Linux + macOS cùng lúc
Miễn phí: Không giới hạn build minutes (chỉ tốn server)

❌ Không cần Jenkins khi:

Dự án nhỏ: GitHub Actions miễn phí, dễ hơn 10x
Không muốn quản lý server: Jenkins cần bảo trì, update, backup
Team nhỏ: Setup + maintain Jenkins > giá trị nó mang lại
Đã dùng GitLab: GitLab CI tích hợp sẵn, không cần thêm tool

🛠️ Cài Đặt Jenkins — 3 Cách

🐳 Cách 1: Docker (khuyên dùng — dễ nhất)
# Chạy Jenkins bằng Docker
docker run -d \
  --name jenkins \
  -p 8080:8080 \
  -p 50000:50000 \
  -v jenkins_home:/var/jenkins_home \
  jenkins/jenkins:lts-jdk17

# Lấy admin password ban đầu
docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword

# Mở browser: http://localhost:8080
# Nhập password → Install suggested plugins → Tạo admin user
🐧 Cách 2: Ubuntu/Debian server
# Thêm Jenkins repo
curl -fsSL https://pkg.jenkins.io/debian-stable/jenkins.io-2023.key \
  | sudo tee /usr/share/keyrings/jenkins.asc > /dev/null

echo "deb [signed-by=/usr/share/keyrings/jenkins.asc] \
  https://pkg.jenkins.io/debian-stable binary/" \
  | sudo tee /etc/apt/sources.list.d/jenkins.list

# Cài đặt
sudo apt update
sudo apt install jenkins openjdk-17-jdk

# Start & enable
sudo systemctl start jenkins
sudo systemctl enable jenkins

# Lấy password: sudo cat /var/lib/jenkins/secrets/initialAdminPassword
🪟 Cách 3: Windows (cho dev local)
# Tải Jenkins WAR file hoặc MSI installer từ jenkins.io
# Cách nhanh: dùng Chocolatey
choco install jenkins

# Hoặc chạy trực tiếp WAR
java -jar jenkins.war --httpPort=8080

# Mở: http://localhost:8080

🏗️ Jenkins Architecture — Hiểu Cách Hoạt Động

🧠
Controller (Master)

Server chính chạy Jenkins UI. Quản lý jobs, plugins, users, scheduling. KHÔNG nên chạy build trên master — chỉ điều phối.

→
⚙️
Agents (Slaves/Nodes)

Máy thực sự chạy build. Có thể là: VM, Docker container, Kubernetes pod. Nhiều agent = build song song.

→
📋
Jobs / Pipelines

Định nghĩa "làm gì": build, test, deploy. Viết bằng Jenkinsfile (Pipeline as Code) hoặc cấu hình qua UI.

💡 Best Practice: Luôn dùng Pipeline as Code (Jenkinsfile) thay vì cấu hình qua UI. Jenkinsfile nằm trong repo → version control, review được, không mất khi Jenkins chết.

📝 Jenkinsfile — Ví Dụ Thực Tế

Jenkinsfile cho .NET 8 API — Build, Test, Docker, Deploy
pipeline {
    agent any

    environment {
        DOTNET_VERSION = '8.0'
        REGISTRY       = 'myregistry.azurecr.io'
        IMAGE_NAME     = 'myapp-api'
        IMAGE_TAG      = "${env.BUILD_NUMBER}"
    }

    stages {
        stage('Checkout') {
            steps {
                checkout scm
            }
        }

        stage('Restore & Build') {
            steps {
                sh 'dotnet restore'
                sh 'dotnet build --configuration Release --no-restore'
            }
        }

        stage('Test') {
            steps {
                sh 'dotnet test --configuration Release --no-build --logger trx'
            }
            post {
                always {
                    // Publish test results
                    mstest testResultsFile: '**/*.trx'
                }
            }
        }

        stage('Docker Build & Push') {
            when {
                branch 'main'  // Chỉ build Docker khi merge vào main
            }
            steps {
                script {
                    docker.build("${REGISTRY}/${IMAGE_NAME}:${IMAGE_TAG}")
                    docker.withRegistry("https://${REGISTRY}", 'acr-credentials') {
                        docker.image("${REGISTRY}/${IMAGE_NAME}:${IMAGE_TAG}").push()
                        docker.image("${REGISTRY}/${IMAGE_NAME}:${IMAGE_TAG}").push('latest')
                    }
                }
            }
        }

        stage('Deploy Staging') {
            when { branch 'main' }
            steps {
                sh """
                    ssh deploy@staging-server \\
                    'docker pull ${REGISTRY}/${IMAGE_NAME}:${IMAGE_TAG} && \\
                     docker compose up -d api'
                """
            }
        }

        stage('Deploy Production') {
            when { branch 'main' }
            input {
                message "Deploy lên Production?"
                ok "Deploy 🚀"
            }
            steps {
                sh """
                    ssh deploy@prod-server \\
                    'docker pull ${REGISTRY}/${IMAGE_NAME}:${IMAGE_TAG} && \\
                     docker compose up -d api'
                """
            }
        }
    }

    post {
        success {
            slackSend color: 'good',
                message: "✅ Build #${env.BUILD_NUMBER} SUCCESS — ${env.JOB_NAME}"
        }
        failure {
            slackSend color: 'danger',
                message: "❌ Build #${env.BUILD_NUMBER} FAILED — ${env.JOB_NAME}"
        }
        always {
            cleanWs()  // Dọn workspace sau mỗi build
        }
    }
}
Jenkinsfile cho Frontend (React/Next.js) + Deploy lên Nginx
pipeline {
    agent {
        docker {
            image 'node:20-alpine'  // Chạy trong Docker container Node.js
        }
    }

    environment {
        CI = 'true'
    }

    stages {
        stage('Install') {
            steps {
                sh 'npm ci'
            }
        }

        stage('Lint & Test') {
            parallel {             // Chạy song song → nhanh hơn
                stage('Lint') {
                    steps { sh 'npm run lint' }
                }
                stage('Test') {
                    steps { sh 'npm run test -- --ci --coverage' }
                }
            }
        }

        stage('Build') {
            steps {
                sh 'npm run build'
            }
        }

        stage('Deploy') {
            when { branch 'main' }
            steps {
                // Copy static files lên web server
                sh 'rsync -avz --delete dist/ deploy@web-server:/var/www/myapp/'
            }
        }
    }

    post {
        always {
            junit '**/test-results.xml'          // Publish test results
            publishHTML target: [                      // Coverage report
                reportDir: 'coverage/lcov-report',
                reportFiles: 'index.html',
                reportName: 'Coverage Report'
            ]
        }
    }
}

📚 Jenkinsfile Syntax — Cheat Sheet

pipeline { } Block gốc, chứa toàn bộ pipeline
agent any Chạy trên bất kỳ agent nào available
agent { docker { image 'node:20' } } Chạy trong Docker container cụ thể
agent { label 'linux' } Chạy trên agent có label "linux"
stages { stage('Name') { steps { } } } Định nghĩa các bước tuần tự
parallel { stage('A') { } stage('B') { } } Chạy nhiều stage song song
when { branch 'main' } Chỉ chạy stage này khi ở branch main
when { changeset '**/*.cs' } Chỉ chạy khi file .cs thay đổi
environment { KEY = 'value' } Biến môi trường cho pipeline
credentials('secret-id') Lấy secret từ Jenkins Credentials Store
input { message 'Approve?' } Chờ người dùng approve (manual gate)
post { success { } failure { } always { } } Actions sau khi pipeline kết thúc
triggers { pollSCM('H/5 * * * *') } Poll Git mỗi 5 phút (hoặc dùng webhook)
options { timeout(time: 30, unit: 'MINUTES') } Timeout cho pipeline

🔐 Quản Lý Secrets Trong Jenkins

Dùng Credentials trong Jenkinsfile
pipeline {
    agent any

    environment {
        // Lấy username/password credential
        DB_CREDS = credentials('database-credentials')
        // → tự tạo biến: DB_CREDS_USR, DB_CREDS_PSW

        // Lấy secret text
        API_KEY = credentials('api-key-prod')

        // Lấy secret file (certificate, .env)
        KUBECONFIG = credentials('k8s-config')
    }

    stages {
        stage('Deploy') {
            steps {
                // Secrets tự động mask trong log
                sh 'echo "Deploying with user: ${DB_CREDS_USR}"'
                // Password sẽ hiện ******* trong console
            }
        }
    }
}
⚠️ KHÔNG hardcode secrets trong Jenkinsfile! Jenkinsfile nằm trong repo = ai cũng đọc được. Luôn dùng Jenkins Credentials Store: Manage Jenkins → Credentials → Add Credentials. Jenkins auto-mask secrets trong console log.

🔔 Webhook — Tự Động Trigger Khi Push Code

1
Trong Jenkins: Job → Configure → Build Triggers → ✅ GitHub hook trigger for GITScm polling
2
Trong GitHub: Repo → Settings → Webhooks → Add webhook
Payload URL: https://your-jenkins.com/github-webhook/
Content type: application/json — Events: Just the push event
3
Kết quả: Push code → GitHub gọi webhook → Jenkins trigger build ngay lập tức (không cần poll)

🐳 Jenkins + Docker — Pipeline Thực Chiến

docker-compose.yml — Jenkins + Docker-in-Docker
version: "3.8"

services:
  jenkins:
    image: jenkins/jenkins:lts-jdk17
    ports:
      - "8080:8080"
      - "50000:50000"
    volumes:
      - jenkins_home:/var/jenkins_home
      # Mount Docker socket → Jenkins có thể build Docker images
      - /var/run/docker.sock:/var/run/docker.sock
    user: root  # Cần root để access Docker socket

volumes:
  jenkins_home:
💡 Docker-in-Docker (DinD): Mount Docker socket vào Jenkins container → Jenkins có thể build Docker images mà không cần cài Docker bên trong. Production nên dùng Kaniko hoặc Buildah thay vì mount socket (bảo mật hơn).

🌳 Multibranch Pipeline — Auto Detect Branches

Thay vì tạo 1 job cho mỗi branch → Multibranch Pipeline tự detect tất cả branches có Jenkinsfile → tạo job tự động.

Tạo New Item → Multibranch Pipeline
Chọn Branch Sources → GitHub → nhập repo URL
Jenkins scan tất cả branches
Branch nào có Jenkinsfile → tự tạo job
Push branch mới → Jenkins auto detect → chạy CI
Xóa branch → Jenkins auto xóa job
💡 Đây là cách dùng Jenkins đúng nhất cho team: Mỗi branch/PR tự có CI riêng. Không cần tạo job thủ công. Giống GitHub Actions nhưng self-hosted.

💀 Jenkins — Sai Lầm Phổ Biến & Mẹo

🔴 Không backup Jenkins

Jenkins chết = mất TẤT CẢ config, credentials, job history. Backup /var/jenkins_home hàng ngày. Hoặc dùng Configuration as Code (JCasC) plugin → config bằng YAML.

🔴 Build trên Master node

Master chỉ nên điều phối, không chạy build. Build nặng trên master = Jenkins UI lag, crash. Tạo agent riêng cho build.

🔴 Cài quá nhiều plugins

Plugin conflict, memory leak, security vulnerability. Chỉ cài plugin thật sự dùng. Review quarterly, xóa plugin không dùng.

🟡 Không dọn workspace / Docker images

Build liên tục → disk đầy → Jenkins crash. Thêm cleanWs() trong post block. Docker: docker system prune -af weekly.

🟡 Config qua UI thay vì Jenkinsfile

Config qua UI = không version control, không review, không reproduce. Mọi thứ nên ở Jenkinsfile trong repo.

💡 Shared Libraries — DRY cho pipeline

Nhiều repo dùng pipeline giống nhau? Tạo Shared Library → viết common steps 1 lần, reuse ở mọi Jenkinsfile. @Library('my-shared-lib') _

💡 Blue Ocean — UI hiện đại cho Jenkins

Classic Jenkins UI xấu và khó dùng. Blue Ocean plugin cho UI đẹp, visual pipeline editor, GitHub/Git integration tốt hơn.

💡 Jenkins Configuration as Code (JCasC)

Toàn bộ Jenkins config (plugins, security, credentials) viết bằng YAML. Jenkins chết → deploy lại từ YAML trong 5 phút. Infrastructure as Code cho Jenkins.
