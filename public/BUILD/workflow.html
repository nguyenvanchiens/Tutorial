10. Workflow Thực Tế — Từ Code Đến Production

Ghép tất cả lại — đây là cách deploy thật trong team chuyên nghiệp

📋 Workflow Hoàn Chỉnh — Step by Step

1

Developer code trên feature branch

git checkout -b feature/user-profile → code → commit theo conventional commits → push

2

Tạo Pull Request

Mô tả thay đổi, screenshots nếu có UI. CI tự chạy: build, test, lint.

3

Code Review

Ít nhất 1 người review. Check logic, security, performance. Request changes nếu cần.

4

Merge vào main

CI pass ✅ + Review approved ✅ → Squash & merge. Branch cũ tự xóa.

5

CD tự động deploy lên Staging

GitHub Actions build Docker image → push registry → deploy staging. Preview URL tự tạo.

6

QA test trên Staging

Test manual + automated. Smoke test, regression test. Nếu bug → quay lại bước 1.

7

Deploy Production

Approve manual gate (hoặc auto). Rolling deployment / Blue-green. Zero downtime.

8

Monitor & Verify

Check Sentry (errors?), metrics (response time?), logs. Nếu có vấn đề → rollback ngay.

🔄 Deploy Strategies — Cách Deploy Không Downtime

Rolling Deployment

Update từng server/container một. Nếu có 3 replicas → update 1 → healthy → update tiếp. Luôn có instance chạy version cũ serve traffic.

Dùng khi: Default cho hầu hết trường hợp. Kubernetes mặc định dùng cách này.

Blue-Green Deployment

2 environment giống hệt nhau: Blue (đang live) + Green (version mới). Test Green xong → switch traffic. Rollback = switch lại Blue.

Dùng khi: Cần rollback tức thì. Tốn gấp đôi resource nhưng an toàn nhất.

Canary Release

Deploy version mới cho 5% users trước. Monitor lỗi. OK → tăng lên 25% → 50% → 100%. Lỗi → rollback chỉ ảnh hưởng 5%.

Dùng khi: Feature quan trọng, cần validate với real traffic trước khi full rollout.

💀 Lời Khuyên Sống Còn — Deploy Edition

🔴 KHÔNG deploy chiều thứ 6.

Bug phát hiện cuối tuần = không ai fix. Deploy thứ 2-4 sáng, khi team đầy đủ.

🔴 Mọi deploy PHẢI có rollback plan.

Trước khi bấm deploy: "Nếu lỗi, rollback bằng cách nào?" Không trả lời được = chưa sẵn sàng deploy.

🔴 Không deploy nhiều thay đổi 1 lúc.

Deploy 10 features cùng lúc → lỗi → không biết feature nào gây ra. Deploy nhỏ, thường xuyên.

🟡 Database migration TRƯỚC app deploy.

App mới cần schema mới → deploy app trước khi migrate = crash. Luôn: migrate DB → deploy app → verify.

🟡 Feature flags > long-lived branches.

Feature chưa xong? Dùng flag để ẩn, vẫn merge vào main. Tránh merge conflict hell.

🟡 Smoke test SAU MỌI deploy.

Deploy xong → test ngay: login được không? API trả data không? Thanh toán hoạt động không? Không phải "deploy xong tắt máy đi ngủ".

💡 Document mọi thứ.

README phải có: cách chạy local, cách deploy, environment variables cần gì, architecture diagram. Dev mới join team phải setup được trong < 30 phút.

💡 Infrastructure as Code.

Server setup bằng code (Terraform, Pulumi), không phải click UI. Server chết → tạo lại trong 10 phút từ code. "Pets vs Cattle" mindset.
