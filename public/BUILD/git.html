2. Git & Git Workflow — Nền Tảng Của Deploy

Không có Git = không có CI/CD = không có deploy tự động. Git là bước #0.

📝 Git Cơ Bản — Lệnh Dùng Hàng Ngày

Tạo repo mới
git init
git remote add origin https://github.com/you/repo.git
git branch -M main
git push -u origin main
Workflow hàng ngày
git pull origin main          # Lấy code mới nhất
git checkout -b feature/login # Tạo branch mới
# ... code ...
git add .                      # Stage changes
git commit -m "feat: add login page"
git push origin feature/login  # Push lên remote
# → Tạo Pull Request trên GitHub/GitLab

🌳 Git Branching Strategy — Chọn Flow Phù Hợp

⭐ KHUYÊN DÙNG

GitHub Flow

Đơn giản, phù hợp hầu hết team.

main → tạo feature/xxx → code → PR → review → merge → auto deploy
✓ main luôn deployable
✓ Mọi thay đổi qua Pull Request
✓ PR phải có code review
✓ Merge vào main = tự động deploy
Phù hợp: Team nhỏ-vừa, deploy thường xuyên, SaaS

Git Flow

Nhiều branch hơn, cho release cycle dài.

main + develop + feature/* + release/* + hotfix/*
✓ develop = branch phát triển chính
✓ release/* = chuẩn bị phiên bản mới
✓ hotfix/* = sửa lỗi khẩn trên production
Phù hợp: Dự án lớn, release theo version (v1.0, v2.0)

Trunk-Based Development

Tất cả commit vào main, branch sống < 1 ngày.

main → short-lived branches (< 1 day) → merge liên tục
✓ Feature flags thay cho long-lived branch
✓ CI chạy trên mọi commit
✓ Deploy nhiều lần/ngày
Phù hợp: Team senior, CI/CD mạnh, deploy liên tục (Google, Facebook style)

📋 Conventional Commits — Viết Commit Message Chuẩn

Commit message chuẩn giúp đọc lịch sử, tự động tạo changelog, trigger CI/CD.

feat: Tính năng mới — feat: add user registration
fix: Sửa bug — fix: resolve login timeout issue
refactor: Tái cấu trúc — refactor: simplify auth middleware
docs: Tài liệu — docs: update API documentation
style: Format, không logic — style: fix indentation in login.cs
test: Thêm test — test: add unit tests for OrderService
chore: Config, build — chore: update Dockerfile
ci: CI/CD pipeline — ci: add staging deploy step
