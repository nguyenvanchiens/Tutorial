Config & Secrets Management

Connection string, API key, mật khẩu DB — những thứ TUYỆT ĐỐI không được hardcode hay commit lên Git.
Cách tách cấu hình khỏi code, quản lý theo từng môi trường và giữ secret an toàn từ local đến production.

🔑

1. Nguyên Tắc: Tách Config Khỏi Code

Factor III của "The Twelve-Factor App" — kim chỉ nam cho mọi app deploy hiện đại.

📖 Vì Sao Config Phải Tách Khỏi Code?

❌ Hardcode trong code

var db = "Server=prod-db;Password=Secret123"; nằm thẳng trong source → mỗi môi trường phải sửa code & build lại, và secret bị lộ ngay khi push lên Git.

✅ Đọc từ môi trường

var db = config["ConnectionStrings:Default"]; → cùng một bản build chạy được ở local, staging, prod. Chỉ giá trị cấu hình thay đổi, code không đổi.

💡 Quy tắc 12-factor: "Cùng một artifact (bản build) phải deploy được lên mọi môi trường mà không cần build lại." Mọi thứ khác nhau giữa các môi trường (DB, key, URL) đều nằm ở config bên ngoài, không trong code.

🏗️ Config Theo Từng Môi Trường

Môi trườngNguồn config thường dùng
Local (Dev)File .env (không commit) hoặc .NET user-secrets
CI/CDGitHub Actions secrets / biến của pipeline
Staging / ProductionBiến môi trường của host / secret manager (Key Vault, Secrets Manager...)

2. File .env & Không Bao Giờ Commit Secret

Cách quản lý config khi dev local — và lỗi rò rỉ secret phổ biến nhất.

📝 Mẫu .env và .env.example

.env — chứa giá trị thật (KHÔNG commit)
# Giá trị thật — chỉ tồn tại trên máy bạn
DATABASE_URL=postgres://user:S3cr3t@localhost:5432/app
JWT_SECRET=a9f8e7d6c5b4a3f2e1d0
STRIPE_API_KEY=sk_live_51Hxxxxxx
REDIS_URL=redis://localhost:6379
.env.example — bản mẫu (CÓ commit)
# Mẫu cho đồng đội — chỉ có KEY, không có giá trị
DATABASE_URL=
JWT_SECRET=
STRIPE_API_KEY=
REDIS_URL=
.gitignore — chặn .env khỏi Git
# LUÔN thêm dòng này NGAY KHI tạo project
.env
.env.*
!.env.example
appsettings.*.json
*.pfx
secrets.json

🚨 Không Bao Giờ Commit Secret

⚠️ Git nhớ MÃI MÃI. Lỡ commit secret rồi xoá ở commit sau là vô dụng — nó vẫn nằm trong lịch sử và ai clone repo đều thấy. Bot quét GitHub tìm key lộ chỉ trong vài phút.

Nếu lỡ commit secret:

Quy trình xử lý khi lộ secret
# 1. ROTATE NGAY — coi như key đã lộ, vô hiệu hoá & tạo key mới
#    (đây là bước QUAN TRỌNG NHẤT, làm trước mọi thứ)

# 2. Xoá khỏi toàn bộ lịch sử Git
git filter-repo --invert-paths --path .env
#    hoặc dùng BFG Repo-Cleaner cho repo lớn

# 3. Force push & báo cả team clone lại
git push --force --all
💡 Phòng hơn chống: Bật secret scanning (GitHub bật sẵn cho repo public), dùng git-secrets hoặc gitleaks như pre-commit hook để chặn secret ngay trước khi commit.

3. Secrets Trong Container & CI/CD

Truyền config vào Docker và pipeline mà không nhúng cứng vào image.

🐳 Biến Môi Trường Trong Docker

Truyền env vào container — đúng cách
# ✅ Truyền lúc chạy từ file .env (không nhúng vào image)
docker run --env-file .env -p 8080:8080 myapp

# ✅ Trong docker-compose.yml
services:
  api:
    image: myapp
    env_file: .env
    environment:
      - ASPNETCORE_ENVIRONMENT=Production
⚠️ KHÔNG dùng ENV SECRET=... hay COPY .env trong Dockerfile. Mọi thứ bake vào image sẽ nằm trong layer và lộ ra với bất kỳ ai pull image (docker history đọc được). Secret phải truyền lúc chạy, không phải lúc build.

⚙️ GitHub Actions Secrets

Lưu secret tại Settings → Secrets and variables → Actions, rồi tham chiếu qua ${{ secrets.NAME }}. Chúng được mã hoá và tự che (mask) trong log.

.github/workflows/deploy.yml
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to server
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
          API_KEY: ${{ secrets.API_KEY }}
        run: ./deploy.sh
💡 Environments + OIDC: Dùng GitHub Environments (production/staging) để gắn secret riêng theo môi trường và bắt buộc duyệt trước khi deploy. Tốt hơn nữa: dùng OIDC để pipeline lấy token tạm thời từ cloud thay vì lưu credential dài hạn.
🏦

4. Secret Manager & Rotation

Production thật không xài file .env mà dùng kho secret chuyên dụng, có audit và xoay vòng tự động.

🏦 Các Secret Manager Phổ Biến (2026)

🔵 Azure Key Vault

Hệ sinh thái Azure / .NET
Tích hợp Managed Identity — app lấy secret không cần credential
Lưu cả secret, key mã hoá & chứng chỉ

🟠 AWS Secrets Manager

Hệ sinh thái AWS
Tự động rotation cho DB credential
Truy cập qua IAM role

⬛ HashiCorp Vault

Đa cloud / on-premise, không khoá nhà cung cấp
Dynamic secrets — sinh credential ngắn hạn theo yêu cầu
Mạnh nhất nhưng vận hành phức tạp hơn

🐙 GitHub Actions Secrets

Dành riêng cho CI/CD pipeline
Đủ cho project nhỏ/vừa
Không phải kho secret runtime cho app
💡 Chọn theo bối cảnh: Đang ở Azure → Key Vault. Ở AWS → Secrets Manager. Đa cloud / muốn dynamic secret → Vault. Chỉ cần cho pipeline → GitHub Secrets.

🔄 Secret Rotation

Rotation = định kỳ thay secret mới và vô hiệu hoá cái cũ. Giảm thiệt hại nếu secret bị lộ mà bạn chưa biết.

Định kỳ — xoay password/key theo lịch (vd mỗi 90 ngày).
Khi nghi lộ — rotate ngay lập tức, không chờ.
Tự động — Secrets Manager/Vault có thể tự xoay DB credential.
Zero-downtime — dùng versioning để app không gián đoạn khi đổi.

5. Config Trong .NET — appsettings & user-secrets

Cách .NET xếp chồng cấu hình và giữ secret khỏi rò rỉ khi dev.

📚 Thứ Tự Ưu Tiên Cấu Hình (.NET)

.NET nạp config theo lớp, lớp sau ghi đè lớp trước:

Thứ tự (thấp → cao ưu tiên)
# 1. appsettings.json            (mặc định, CÓ commit — KHÔNG để secret)
# 2. appsettings.{Environment}.json   (vd appsettings.Production.json)
# 3. User Secrets                (chỉ Development, KHÔNG commit)
# 4. Environment Variables       (staging/prod)
# 5. Command-line arguments      (cao nhất)
⚠️ appsettings.json được commit lên Git. Chỉ để giá trị không nhạy cảm (logging level, feature flag) ở đây. Connection string thật, API key → dùng user-secrets (local) hoặc environment variable / Key Vault (prod).

🔐 User Secrets — Dev Local An Toàn

Công cụ dotnet user-secrets lưu secret ở thư mục riêng ngoài project (vd %APPDATA%\Microsoft\UserSecrets) nên không bao giờ lọt vào Git.

Thiết lập user-secrets
# Khởi tạo cho project
dotnet user-secrets init

# Lưu một secret
dotnet user-secrets set "ConnectionStrings:Default" "Server=...;Password=..."

# Xem & xoá
dotnet user-secrets list
dotnet user-secrets remove "ConnectionStrings:Default"
Đọc config trong code — nguồn nào cũng dùng chung API
var builder = WebApplication.CreateBuilder(args);

// Tự gộp appsettings + user-secrets + env vars + Key Vault
string? conn = builder.Configuration
    .GetConnectionString("Default");

string? apiKey = builder.Configuration["Stripe:ApiKey"];
💡 Production .NET: Set biến môi trường dùng dấu hai chấm __ (hai gạch dưới) thay cho : vì Linux không cho phép : trong tên biến — vd ConnectionStrings__Default. Hoặc tốt hơn: nạp thẳng từ Azure Key Vault qua AddAzureKeyVault().
