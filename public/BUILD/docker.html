4. Docker — Đóng Gói & Triển Khai Nhất Quán

"Ở máy tôi chạy được" → Docker giải quyết câu này. Đóng gói TẤT CẢ vào 1 container.

⚡ Học Docker KHÔNG Cần Cài Lên Máy — 4 Cách

Docker Desktop ngốn ~2.5GB RAM, chạy liên tục trong background làm máy ì. Nếu bạn chỉ muốn học hoặc máy yếu, dùng các cách dưới đây — không tốn byte nào bộ nhớ local.

🌐 1. Play with Docker KHUYÊN CHO NGƯỜI MỚI

URL: labs.play-with-docker.com
Cần: Tài khoản Docker Hub (miễn phí)
Session: 4 giờ / lần, có thể tạo lại
Tính năng: Tạo nhiều Linux node, đủ lệnh docker, docker-compose, Swarm cluster
Dùng khi: Luyện lệnh, thử Dockerfile, demo multi-container
Hạn chế: Session ngắn, mất data khi hết giờ. Không deploy production.

🎓 2. Killercoda — Scenario tương tác

URL: killercoda.com/docker
Cần: Không đăng ký cũng dùng được
Tính năng: Có sẵn bài tập theo chủ đề (Docker basics, compose, networking…)
Dùng khi: Học có dẫn dắt từng bước, muốn theo kịch bản
Hạn chế: Mỗi scenario environment riêng, không persist giữa các bài

☁️ 3. GitHub Codespaces KHUYÊN CHO DỰ ÁN THẬT

URL: Bất kỳ repo GitHub → Code → Codespaces → Create
Cần: Tài khoản GitHub
Free tier: 60h/tháng (Free), 180h/tháng (Pro $4)
Tính năng: Cloud VM 2-core + Docker + docker-compose cài sẵn, VS Code browser/desktop
Dùng khi: Làm project thật, cần persist code, push git, chạy app lâu
Ưu điểm: Hoạt động y như máy local mà không tốn tài nguyên máy bạn

💰 4. VPS Giá Rẻ — Học + Deploy luôn

Providers: Hetzner ($4/tháng), DigitalOcean ($4), Vultr ($2.5)
Cấu hình tối thiểu: 1 vCPU, 1-2GB RAM, Ubuntu 22.04
Cài đặt: SSH vào → curl -fsSL https://get.docker.com | sh
Dùng khi: Muốn deploy thật, học sysadmin, demo cho khách
Lưu ý: Mất tiền tháng, phải biết SSH cơ bản
💡 Lộ trình khuyên dùng: Play with Docker (học lệnh 1-2 tuần) → GitHub Codespaces (làm project thật) → VPS khi cần deploy production.

🪶 Phải Cài Local? — Dùng Podman Desktop Thay Docker Desktop

Nếu vẫn muốn chạy local (offline, dev liên tục), có 2 lựa chọn nhẹ hơn Docker Desktop 30-40% RAM:

🦭 Podman Desktop TOP CHOICE 2026

URL: podman-desktop.io
Giấy phép: Open-source (Apache 2.0), miễn phí kể cả cho doanh nghiệp lớn
CLI: podman tương thích 100% lệnh docker
Daemonless: Không có service chạy ngầm → tiết kiệm RAM rõ rệt
Rootless mode: An toàn hơn, không cần root privilege
RAM idle: ~1.2-1.5 GB (vs Docker Desktop 2.5GB+)
# Dùng podman y như docker — chỉ đổi tên lệnh
podman run -d -p 8080:80 nginx
podman ps
podman images

# Hoặc alias cho thói quen
alias docker=podman
alias docker-compose="podman compose"

🐄 Rancher Desktop

URL: rancherdesktop.io
Giấy phép: Open-source (Apache 2.0)
Engine: dockerd (containerd) — CLI docker hoạt động nguyên gốc
Kèm Kubernetes: Có k3s built-in → học K8s luôn
Dùng khi: Cần học cả Docker + Kubernetes, muốn CLI docker nguyên xi
Hạn chế: Nặng hơn Podman chút vì kèm K8s
⚠️ Docker Desktop có thu phí: Công ty ≥250 nhân viên hoặc doanh thu >$10M/năm phải mua license. Podman Desktop & Rancher Desktop đều miễn phí hoàn toàn, không giới hạn thương mại.

📖 Docker Là Gì? — Giải Thích Đơn Giản

❌ Không có Docker

"Máy tôi dùng .NET 8, server dùng .NET 6. Máy tôi Windows, server Linux. Database version khác. Biến môi trường khác. → Sập."

✅ Có Docker

"Đóng gói app + .NET 8 + tất cả dependencies vào 1 container. Container chạy giống nhau trên máy tôi, server dev, staging, production. → Luôn hoạt động."

Image = Bản thiết kế (blueprint). Chứa code + runtime + config. Không thay đổi.
Container = Instance đang chạy từ image. Giống "bật máy ảo" nhưng nhẹ hơn 100x.
Dockerfile = File hướng dẫn cách build image. Viết 1 lần, dùng mãi.
Registry = Nơi lưu trữ images (Docker Hub, GitHub Container Registry, Azure ACR).

📝 Dockerfile — Ví Dụ Thực Tế

Dockerfile cho .NET 8 API (Multi-stage build)
# Stage 1: Build
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src

# Copy csproj riêng → cache restore layer
COPY *.csproj .
RUN dotnet restore

# Copy toàn bộ source → build
COPY . .
RUN dotnet publish -c Release -o /app/publish

# Stage 2: Runtime (image nhỏ, chỉ chứa runtime)
FROM mcr.microsoft.com/dotnet/aspnet:8.0
WORKDIR /app
COPY --from=build /app/publish .

EXPOSE 8080
ENV ASPNETCORE_URLS=http://+:8080

ENTRYPOINT ["dotnet", "MyApp.dll"]
Dockerfile cho Next.js
# Stage 1: Install + Build
FROM node:20-alpine AS builder
WORKDIR /app

COPY package*.json .
RUN npm ci

COPY . .
RUN npm run build

# Stage 2: Runtime
FROM node:20-alpine
WORKDIR /app

COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
COPY --from=builder /app/public ./public

EXPOSE 3000
CMD ["node", "server.js"]
💡 Multi-stage build giúp image nhỏ gọn: SDK image (~800MB) chỉ dùng lúc build → runtime image (~100MB) dùng khi chạy. Production image nhỏ = deploy nhanh, bảo mật hơn.

🐙 Docker Compose — Chạy Nhiều Service Cùng Lúc

Web app thường gồm: API + Database + Redis + Nginx. Compose quản lý tất cả.

docker-compose.yml — Full stack development
version: "3.8"

services:
  api:
    build: ./backend
    ports:
      - "5000:8080"
    environment:
      - ConnectionStrings__Default=Server=db;Database=myapp;User=sa;Password=Pass@123
      - ASPNETCORE_ENVIRONMENT=Development
    depends_on:
      - db
      - redis

  web:
    build: ./frontend
    ports:
      - "3000:3000"
    environment:
      - NEXT_PUBLIC_API_URL=http://localhost:5000

  db:
    image: mcr.microsoft.com/mssql/server:2022-latest
    environment:
      - ACCEPT_EULA=Y
      - SA_PASSWORD=Pass@123
    ports:
      - "1433:1433"
    volumes:
      - db-data:/var/opt/mssql

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"

volumes:
  db-data:
Docker commands thường dùng
docker compose up -d           # Chạy tất cả services (background)
docker compose down             # Dừng tất cả
docker compose logs -f api      # Xem log service api
docker compose build            # Rebuild images
docker ps                       # List containers đang chạy
docker exec -it api bash        # Vào shell container
