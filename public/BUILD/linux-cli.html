Linux & CLI cơ bản

99% server production chạy Linux và bạn điều khiển chúng qua terminal — không có chuột.
Nắm vững những lệnh dưới đây là đủ để deploy app lên VPS, debug sự cố và sống sót khi SSH vào server lúc 2 giờ sáng.

🐧

1. Filesystem & Đường Dẫn

Linux không có "ổ C, ổ D". Mọi thứ treo trên một cây thư mục duy nhất bắt đầu từ / (root).

🌳 Cây Thư Mục — Những Chỗ Bạn Hay Gặp

Đường dẫnLà gì
/Root — gốc của toàn bộ hệ thống
/home/userThư mục cá nhân của user (viết tắt ~)
/etcFile cấu hình hệ thống (nginx, ssh, systemd...)
/var/logLog của hệ thống và app — nơi đầu tiên debug khi sập
/var/wwwThư mục chứa website (theo quy ước phổ biến)
/usr/bin, /usr/local/binNơi chứa các chương trình thực thi
/tmpFile tạm — bị xoá khi reboot
/optPhần mềm bên thứ ba cài thủ công
💡 Đường dẫn tuyệt đối vs tương đối: Bắt đầu bằng / là tuyệt đối (luôn cố định, vd /etc/nginx). Không có / đầu là tương đối (tính từ thư mục hiện tại). . = thư mục hiện tại, .. = thư mục cha, ~ = home của bạn.

🧭 Di Chuyển — Bạn Đang Ở Đâu, Đi Đâu

Navigation cơ bản
pwd                      # Print Working Directory — đang đứng ở đâu?
ls                       # Liệt kê file/thư mục
ls -lah                  # -l chi tiết, -a kể cả file ẩn, -h dung lượng dễ đọc
cd /var/www              # Chuyển vào thư mục tuyệt đối
cd app                   # Vào thư mục con (tương đối)
cd ..                    # Lùi ra thư mục cha
cd ~                     # Về home
cd -                     # Quay lại thư mục vừa đứng trước đó

📁 Thao Tác File & Thư Mục

Tạo, copy, di chuyển, xoá
mkdir releases           # Tạo thư mục
mkdir -p app/logs/2026   # -p tạo cả cây thư mục lồng nhau
touch app.log            # Tạo file rỗng / cập nhật timestamp
cp config.json config.bak   # Copy file
cp -r src/ backup/       # -r copy cả thư mục (recursive)
mv old.txt new.txt       # Đổi tên HOẶC di chuyển
rm temp.log              # Xoá file
rm -rf node_modules      # -r đệ quy, -f không hỏi — XÓA THẲNG TAY
⚠️ rm -rf không có thùng rác. Không có "Ctrl+Z". rm -rf / hoặc rm -rf $VAR/ khi $VAR rỗng = xoá sạch server. Luôn pwd và ls kiểm tra trước khi xoá. Trên prod, cân nhắc mv vào thư mục tạm thay vì rm ngay.

👀 Xem Nội Dung File

Đọc file & theo dõi log
cat config.json         # In toàn bộ file ra màn hình
less app.log             # Xem phân trang (q để thoát, / để tìm)
head -n 20 app.log       # 20 dòng đầu
tail -n 50 app.log       # 50 dòng cuối
tail -f app.log          # THEO DÕI log live — quan trọng nhất khi debug deploy
grep -i "error" app.log  # Lọc dòng chứa "error" (không phân biệt hoa thường)
grep -rn "TODO" src/     # Tìm đệ quy trong thư mục, kèm số dòng
💡 tail -f là người bạn thân nhất khi deploy. Mở một terminal chạy tail -f /var/log/nginx/error.log, terminal khác restart app — bạn thấy lỗi ngay khi nó xảy ra.

2. Quyền (Permissions) & User

Lý do số 1 khiến app "không chạy được trên server": sai permission. Hiểu rwx là hết bệnh.

🔢 Đọc Hiểu rwx và Số Octal

Chạy ls -l sẽ thấy dòng kiểu -rwxr-xr--. Mỗi nhóm 3 ký tự dành cho: Owner (chủ) · Group (nhóm) · Others (còn lại).

r = 4
read (đọc)
w = 2
write (ghi)
x = 1
execute (chạy)
chmod & chown
# Cộng các số lại: rwx=7, rw-=6, r-x=5, r--=4
chmod 755 deploy.sh      # owner rwx(7), group r-x(5), others r-x(5)
chmod 644 config.json   # owner rw-(6), group r--(4), others r--(4)
chmod +x deploy.sh       # Thêm quyền execute (cách viết ký hiệu)
chmod 600 ~/.ssh/id_ed25519  # SSH key BẮT BUỘC chỉ owner đọc/ghi

# chown = đổi chủ sở hữu (owner:group)
chown www-data:www-data /var/www/app
chown -R deploy:deploy /opt/myapp   # -R áp dụng đệ quy
⚠️ Đừng bao giờ chmod 777 để "cho nhanh". 777 = ai cũng đọc/ghi/chạy được — lỗ hổng bảo mật kinh điển. SSH private key sai quyền (không phải 600) sẽ bị từ chối kèm lỗi UNPROTECTED PRIVATE KEY FILE.

👤 User, Root & sudo

Trên server, root là vua — làm được mọi thứ kể cả tự huỷ. Best practice: tạo user thường rồi dùng sudo khi cần quyền cao, thay vì login root trực tiếp.

Quản lý user & sudo
whoami                   # Đang là user nào?
sudo apt update          # Chạy lệnh với quyền root
sudo adduser deploy      # Tạo user mới tên deploy
sudo usermod -aG sudo deploy   # Cho deploy quyền dùng sudo
su - deploy              # Chuyển sang user deploy
id deploy                # Xem user thuộc group nào

3. Cài Phần Mềm & Quản Lý Tiến Trình

Cài runtime, theo dõi tiến trình ngốn RAM, và "tắt" cái app đang treo cổng.

📥 Package Manager — apt vs yum/dnf

🟠 apt (Debian / Ubuntu)

sudo apt update — cập nhật danh sách package
sudo apt upgrade — nâng cấp các package đã cài
sudo apt install nginx — cài phần mềm
sudo apt remove nginx — gỡ phần mềm
apt search node — tìm package

🔴 yum / dnf (RHEL / CentOS / Fedora / Amazon Linux)

sudo dnf check-update — kiểm tra cập nhật
sudo dnf upgrade — nâng cấp
sudo dnf install nginx — cài
sudo dnf remove nginx — gỡ
dnf search node — tìm
💡 Ubuntu là distro phổ biến nhất cho VPS nên bạn sẽ gặp apt nhiều nhất. dnf là bản kế nhiệm hiện đại của yum (lệnh gần như y hệt).

⚙️ Tiến Trình (Processes)

Xem & kill process
ps aux                   # Liệt kê TẤT CẢ tiến trình
ps aux | grep dotnet     # Lọc tiến trình của app .NET
top                      # Bảng tiến trình live (CPU/RAM), q để thoát
htop                     # top phiên bản đẹp hơn (cần cài: apt install htop)
kill 12345              # Gửi tín hiệu dừng nhẹ nhàng (SIGTERM) cho PID 12345
kill -9 12345           # Ép tắt cứng (SIGKILL) — dùng khi treo cứng
lsof -i :8080           # Tiến trình nào đang chiếm cổng 8080?
⚠️ "Address already in use". Lỗi cực phổ biến khi deploy: cổng đã bị app cũ chiếm. Dùng lsof -i :8080 tìm PID rồi kill. Ưu tiên kill thường (cho app dọn dẹp) trước, chỉ kill -9 khi nó không chịu chết.

🔄 systemd & Quản Lý Service

Trên Linux hiện đại, app của bạn nên chạy như một service systemd để tự khởi động lại khi crash và tự bật khi reboot server.

systemctl — điều khiển service
sudo systemctl status nginx     # Xem service đang chạy/lỗi gì
sudo systemctl start myapp       # Khởi động
sudo systemctl stop myapp        # Dừng
sudo systemctl restart myapp     # Khởi động lại (sau khi deploy phiên bản mới)
sudo systemctl enable myapp      # Bật tự chạy khi reboot
journalctl -u myapp -f           # Xem log của service (live)
/etc/systemd/system/myapp.service — định nghĩa service cho .NET app
[Unit]
Description=My .NET API
After=network.target

[Service]
WorkingDirectory=/var/www/myapp
ExecStart=/usr/bin/dotnet /var/www/myapp/MyApp.dll
Restart=always
User=www-data
Environment=ASPNETCORE_ENVIRONMENT=Production

[Install]
WantedBy=multi-user.target
💡 Sau khi sửa file .service: chạy sudo systemctl daemon-reload rồi sudo systemctl restart myapp để áp dụng.

4. SSH — Kết Nối & Chuyển File

SSH là cách bạn điều khiển server từ xa một cách an toàn. Không có SSH = không deploy được lên VPS.

🗝️ Tạo Key & Đăng Nhập (không cần mật khẩu)

Quy trình SSH key chuẩn 2026
# 1. Tạo cặp key trên MÁY BẠN (ed25519 nhanh & an toàn hơn RSA)
ssh-keygen -t ed25519 -C "deploy@laptop"

# 2. Copy public key lên server (tự thêm vào ~/.ssh/authorized_keys)
ssh-copy-id deploy@203.0.113.10

# 3. Đăng nhập — giờ không cần gõ mật khẩu nữa
ssh deploy@203.0.113.10

# Đăng nhập qua port tuỳ chỉnh & chỉ định key cụ thể
ssh -p 2222 -i ~/.ssh/id_ed25519 deploy@myserver.com
⚠️ Private key (id_ed25519) KHÔNG bao giờ rời máy bạn. Chỉ copy file .pub (public) lên server. Đặt quyền chmod 600 cho private key, chmod 700 cho thư mục ~/.ssh.

📤 Chuyển File: scp vs rsync

Upload code/artifact lên server
# scp — copy đơn giản qua SSH
scp app.zip deploy@server:/var/www/          # Đẩy file lên
scp -r dist/ deploy@server:/var/www/app/     # Đẩy cả thư mục
scp deploy@server:/var/log/app.log ./        # Kéo file về

# rsync — thông minh hơn: chỉ truyền phần KHÁC BIỆT, hỗ trợ resume
rsync -avz --delete dist/ deploy@server:/var/www/app/
#  -a giữ nguyên quyền/timestamp  -v hiện chi tiết
#  -z nén khi truyền  --delete xoá file thừa ở đích cho khớp source
💡 Deploy thật nên dùng rsync. Lần đầu nó copy hết, các lần sau chỉ truyền file thay đổi → nhanh hơn nhiều và an toàn nếu mất mạng giữa chừng.

5. Biến Môi Trường, Pipe & Bash Script

Ghép các lệnh nhỏ thành một quy trình deploy tự động — đây là sức mạnh thật của CLI.

🌱 Biến Môi Trường (Environment Variables)

Đọc, đặt, xuất biến
echo $HOME               # In giá trị một biến
env                      # Liệt kê tất cả biến môi trường
export API_KEY="abc123"   # Đặt biến cho session hiện tại
printenv DATABASE_URL     # In một biến cụ thể

# Để biến tồn tại vĩnh viễn → thêm vào ~/.bashrc rồi: source ~/.bashrc
💡 App đọc cấu hình qua biến môi trường (vd ASPNETCORE_ENVIRONMENT, DATABASE_URL) — đây là nền tảng của 12-factor app. Chi tiết ở trang 🔑 Secrets.

🔗 Pipe | và Redirection > >>

Nối lệnh & điều hướng output
# Pipe: đưa output lệnh này làm input lệnh kia
ps aux | grep nginx | wc -l     # Đếm số tiến trình nginx
cat access.log | grep 500 | head   # Lọc lỗi 500, lấy vài dòng đầu

# Redirection: ghi output ra file
dotnet MyApp.dll > app.log 2>&1   # > ghi đè, 2>&1 gộp cả lỗi vào
echo "deployed $(date)" >> deploy.log   # >> ghi nối thêm vào cuối

🤖 Bash Script Deploy Cơ Bản

deploy.sh — script triển khai mẫu
#!/bin/bash
set -euo pipefail          # Dừng ngay khi có lỗi — RẤT QUAN TRỌNG

APP_DIR="/var/www/myapp"
BRANCH="main"

echo "==> Kéo code mới"
cd "$APP_DIR"
git pull origin "$BRANCH"

echo "==> Build"
dotnet publish -c Release -o ./publish

echo "==> Restart service"
sudo systemctl restart myapp

echo "✅ Deploy xong lúc $(date)"
⚠️ Luôn mở script bằng set -euo pipefail. -e dừng khi lệnh lỗi, -u báo lỗi khi dùng biến chưa khai báo, -o pipefail bắt lỗi giữa pipe. Không có dòng này, script sẽ "chạy tiếp dù đã hỏng" và deploy ra bản lỗi.
💡 Chạy script: chmod +x deploy.sh rồi ./deploy.sh. Dùng bash -x deploy.sh để debug từng dòng.
