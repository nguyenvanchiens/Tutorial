14.1 — Shift-Left — Bảo Mật Càng Sớm Càng Rẻ

Tìm lỗ hổng lúc viết code = sửa vài phút. Tìm lúc production = sự cố + tốn gấp 100 lần

🌊 Bảo mật dịch trái về phía developer

❌ Mô hình cũ — Security gác cổng

Code xong → đội security pentest ngay trước release → tìm ra 50 lỗ hổng → release trễ 2 tuần, hoặc release bừa rồi vá sau. Security là kẻ "nói không", dev ghét.

✅ DevSecOps — Shift Left

Security tự động hóa, chạy trong IDE + mỗi PR + mỗi build. Dev thấy lỗ hổng ngay khi commit, fix tại chỗ. Security là công cụ tích hợp, không phải cổng chặn cuối.

💡 Nguyên tắc: Mỗi giai đoạn càng về sau, chi phí sửa lỗ hổng càng tăng theo cấp số nhân. Tích hợp bảo mật vào pipeline để nó tự động & liên tục — không phải sự kiện một lần trước release. Đây là tinh thần cốt lõi của DevSecOps.

14.2 — Secret Scanning

Lỗ hổng phổ biến nhất: API key / password vô tình commit lên Git

🛑 Chặn Secret Trước Khi Quá Muộn

pre-commit hook — chặn ngay tại máy dev
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/gitleaks/gitleaks
    rev: v8.18.0
    hooks:
      - id: gitleaks   # quét secret trước khi commit
CI step — chặn ở pipeline
# GitHub Actions
- name: Secret scan
  uses: gitleaks/gitleaks-action@v2
  # + bật GitHub Secret Scanning &
  #   Push Protection trên repo
⚠️ Lỡ commit secret rồi thì sao? Xóa khỏi code KHÔNG đủ — nó vẫn nằm trong git history. Phải coi secret đó đã lộ vĩnh viễn: (1) ROTATE ngay (đổi key/password mới, vô hiệu cái cũ), rồi (2) cân nhắc xóa khỏi history (git filter-repo). Rotate quan trọng hơn xóa — kẻ tấn công có thể đã copy.

14.3 — SAST, DAST & Dependency Scanning

Quét chính code của bạn, quét app đang chạy, và quét thư viện bên thứ ba

🆚 SAST vs DAST

SAST — Static (Hộp trắng)

Quét source code TĨNH, không cần chạy app

Tìm: SQL injection, hardcoded secret, code pattern nguy hiểm
Chạy ở: PR / CI, sớm
Tool: CodeQL (GitHub), SonarQube, Semgrep
Nhanh, sớm — nhưng nhiều false positive

DAST — Dynamic (Hộp đen)

Tấn công app ĐANG CHẠY (staging) từ bên ngoài

Tìm: lỗ hổng runtime, auth, config sai, XSS thực
Chạy ở: sau deploy lên staging
Tool: OWASP ZAP, Burp Suite
Thực tế hơn — nhưng chậm & cần app chạy

📚 Dependency Scanning (SCA)

Phần lớn code app hiện đại là thư viện bên thứ ba. Một lỗ hổng trong NuGet/npm package = lỗ hổng của bạn (nhớ Log4Shell, xz backdoor).

DỄ NHẤT
🤖

Dependabot (GitHub)

Tự quét dependency, mở PR nâng version vá lỗ hổng. Bật 1 click. Có cả security alerts + version updates.

✓ Miễn phí, native GitHub, auto PR
Mọi repo trên GitHub
🦉

OWASP Dependency-Check

Quét dependency đối chiếu CSDL CVE (NVD). Chạy được offline / CI bất kỳ. Hỗ trợ .NET, Java, npm...

✓ Open-source, CI-agnostic
Pipeline tự host / không dùng GitHub
🐶

Snyk / Trivy fs

Snyk: SCA + fix suggestion mạnh. Trivy cũng quét được dependency lẫn IaC misconfig, không chỉ image.

✓ Đa năng, gợi ý fix tốt
Team muốn 1 tool quét nhiều thứ
.NET — kiểm tra package lỗ hổng
dotnet list package --vulnerable --include-transitive
# liệt kê cả dependency gián tiếp có CVE
npm — audit
npm audit
npm audit fix   # tự vá nếu không breaking

14.4 — Image Scanning & SBOM

Container image kế thừa mọi lỗ hổng của base image. Quét nó và biết chính xác bên trong có gì

🔎 Trivy — Quét Image trong CI

# Quét image local, fail build nếu có lỗ hổng nghiêm trọng
trivy image --severity HIGH,CRITICAL --exit-code 1 myapp:1.4.2

# GitHub Actions step
- name: Scan image
  uses: aquasecurity/trivy-action@master
  with:
    image-ref: myapp:${{ github.sha }}
    severity: "HIGH,CRITICAL"
    exit-code: "1"          # chặn deploy nếu dính lỗ hổng nặng
💡 Giảm bề mặt tấn công image: Dùng base image tối giản — distroless hoặc Alpine/chiseled (.NET) thay vì image full OS. Ít package = ít CVE = image nhỏ. Chạy container bằng user non-root. Pin digest (@sha256:...) thay vì tag để bất biến.

📜 SBOM — Software Bill of Materials

SBOM = "danh sách thành phần" của phần mềm: mọi package, version, license bên trong. Khi CVE mới công bố (kiểu Log4Shell), bạn tra SBOM trong vài giây để biết "mình có dính không" thay vì hoảng loạn rà tay.

# Sinh SBOM theo chuẩn (SPDX / CycloneDX)
syft myapp:1.4.2 -o spdx-json > sbom.json
# .NET: dotnet CLI cũng sinh được SBOM (CycloneDX)
dotnet CycloneDX MyApp.csproj -o ./sbom

# Sau đó quét SBOM với DB lỗ hổng
grype sbom:./sbom.json
⚠️ SBOM đang trở thành bắt buộc. Nhiều quy định/khách hàng (đặc biệt khu vực công, EU Cyber Resilience Act) yêu cầu SBOM đi kèm sản phẩm. Sinh SBOM tự động trong build và lưu kèm artifact — đừng để nước đến chân mới làm.

14.5 — Least-Privilege, OIDC & Ký Artifact

Bỏ key tĩnh dài hạn. Cho ít quyền nhất. Ký mọi thứ để chứng minh nguồn gốc

🔓 OIDC-to-Cloud — Hết Thời Key Tĩnh trong CI

❌ Long-lived secret

Lưu AWS_ACCESS_KEY / service principal secret trong GitHub Secrets. Key sống mãi → lộ là toang, phải rotate thủ công, dễ quên. Một secret rò = toàn quyền cloud.

✅ OIDC federation

CI (GitHub Actions) đổi token OIDC ngắn hạn lấy credential cloud tạm thời (vài phút). Không có secret tĩnh để lộ. Cloud tin "đúng repo/branch này" qua federation.

# GitHub Actions → Azure qua OIDC, KHÔNG cần client secret
permissions:
  id-token: write        # cho phép xin OIDC token
  contents: read
steps:
  - uses: azure/login@v2
    with:
      client-id: ${{ secrets.AZURE_CLIENT_ID }}      # id, không phải secret
      tenant-id: ${{ secrets.AZURE_TENANT_ID }}
      subscription-id: ${{ secrets.AZURE_SUB_ID }}
      # không có client-secret — dùng workload identity federation
💡 Least-privilege: Identity của pipeline/app chỉ được cấp đúng quyền cần thiết, đúng resource, đúng môi trường. Không gán "Contributor/Owner" cho tiện. Tách identity theo môi trường — credential deploy staging KHÔNG được chạm production.

✍️ Artifact Signing & Provenance

Ký image/artifact để khi deploy, cluster kiểm chứng "thứ này đúng do pipeline của ta build, chưa bị tráo". Chống tấn công supply-chain kiểu chèn image độc vào registry.

# Cosign (Sigstore) — ký image keyless bằng OIDC identity
cosign sign myregistry.io/myapp:1.4.2

# Verify trước/khi deploy (gắn vào admission controller K8s)
cosign verify myregistry.io/myapp:1.4.2 \
  --certificate-identity=... --certificate-oidc-issuer=...
💡 SLSA & provenance: Hướng tới attestation theo khung SLSA — chứng minh chuỗi "code nào → build ở đâu → ra artifact nào". Kết hợp với policy ở K8s (Kyverno/Gatekeeper) để chỉ cho phép chạy image đã ký + đã quét sạch. Đây là tuyến phòng thủ supply-chain mạnh nhất 2026.

✅ Checklist DevSecOps Pipeline

🔴
Secret scanning + push protection

Chặn secret ngay từ commit/PR. Rotate ngay nếu lỡ lộ.

🔴
OIDC thay key tĩnh

Không lưu credential cloud dài hạn trong CI secrets.

🟡
SAST + dependency scan ở mỗi PR

CodeQL/Semgrep + Dependabot. Fail build nếu CRITICAL.

🟡
Image scan + base image tối giản

Trivy + distroless/chiseled + non-root user.

🔵
SBOM mỗi build

Sinh & lưu SBOM (SPDX/CycloneDX) kèm artifact.

🔵
Ký artifact + verify khi deploy

Cosign sign/verify, policy chỉ chạy image đã ký.
